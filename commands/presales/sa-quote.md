# /sa-quote — 报价 & 宣讲物料（Module 6）

> **端到端 7 模块流水线的第 6 站**
>
> /sa-poc + /sa-impl + /sa-rfp →【本命令】→ /sa-archive

## 🚨 重要声明

**本命令只输出估算底稿，绝对不是最终报价**。最终报价必须由商务人工确认后对外报出。所有产出物顶部必须显式标注 **"⚠️ 报价底稿 - 非正式报价，最终以商务方案为准"**。

## 一句话

**输入总体方案 + 客户规模，输出可交给商务的《配置估算清单》和可交给市场的《宣讲材料底稿》**（PPT 大纲 + 每页文案 + 汇报话术）。

## 输入

```bash
# 最基础
/sa-quote ./output/sa-pipeline/xxx/03-overall-solution.md

# 加 POC 方案输入（更准确的估算）
/sa-quote ./03-overall-solution.md ./04-poc-plan.md --scale 500

# 输出到指定目录
/sa-quote ./03-overall-solution.md --out ./output/sa-pipeline/xxx/05-quote/
```

## 内部两个子 Agent

### Agent 6-1：配置估算

**输入**：总体方案 + POC 方案 + 客户规模指标（用户数、并发、数据量）

**输出**：
1. **产品模块选型清单**（我方哪些模块被启用）
2. **服务器 / 存储配置清单**（应用节点 / 数据节点 / 大屏节点）
3. **第三方组件清单**（数据库 / 中间件 / 监控 等）
4. **软件许可数量**（用户数 / CPU 核数 / 数据量）
5. **定制开发工作量初估**（按 M3 定制清单）
6. **服务人天初估**（部署 / 集成 / 培训 / 售后）

### Agent 6-2：对外宣讲材料底稿

**输出**：
1. **方案 PPT 大纲**（15-20 页典型结构）
2. **每页核心文案**（标题 + 3-5 个 bullet 点 + 补充说明）
3. **客户汇报话术要点**（每章讲述重点）

>

> 建议时长：45 分钟（30 汇报 + 15 Q&A）
> 页数：18-20 页

## PPT 结构

### 封面页
- 项目名：远大制造 - MES 替换方案
- 我方 LOGO + 客户 LOGO
- 时间 / 版本

### 议程页（1 页）
1. 项目背景与我方理解
2. 客户核心痛点
3. 我方总体方案
4. 关键差异化能力
5. 部署与集成
6. 实施计划
7. POC 建议
8. 后续步骤

### 第 1 章：项目背景与我方理解（2 页）
- **页面**：客户业务现状 → 挑战 → 目标
- **文案要点**：
  - 我们理解贵司在推进制造数字化，MES 替换是关键抓手
  - 挑战：老系统年限、集成复杂、国产化压力
  - 目标：3 个月交付、100% 国产化、生产效率提升 15%

### 第 2 章：客户核心痛点（2 页）
- **页面 1**：痛点全景图（Mermaid 或图表）
- **页面 2**：Top 3 痛点深度分析
- **文案要点**：
  - 痛点 1：车间排产靠 Excel，每天 8 点半才拿到排产结果
  - 痛点 2：质检数据 T+1，缺陷发现滞后 24 小时
  - 痛点 3：与 SAP 系统集成复杂，双录入错误率高

### 第 3 章：我方总体方案（4 页）
- **页面 1**：方案概览（一句话 + 三大能力）
- **页面 2**：业务架构图
- **页面 3**：技术架构图
- **页面 4**：与客户现有 IT 的关系
- **话术要点**：着重讲差异化能力，避免陷入功能罗列

### 第 4 章：关键差异化能力（3 页）
- **页面 1**：智能排产算法（含算法效果数据）
- **页面 2**：100% 国产化（对齐信创要求）
- **页面 3**：3 月快速交付（对比行业标准 6-12 月）

### 第 5 章：部署与集成（2 页）
- **页面 1**：部署架构（客户 IDC + 双活）
- **页面 2**：与 SAP / LDAP / 设备的集成关系

### 第 6 章：实施计划（2 页）
- **页面 1**：6 阶段 Gantt 图
- **页面 2**：里程碑 + 客户参与度

### 第 7 章：POC 建议（1 页）
- **文案**：POC 目标 + 4 周周期 + 关键验证点

### 第 8 章：后续步骤（1 页）
- **文案**：下一步动作 + 客户方需要的支持 + 联系人

我们预估可以做到 15% 以上的效率提升。这个具体数字我们建议在 POC 阶段验证。"

"我们的方案是 100% 国产化 —— 从麒麟 OS 到 OceanBase 到东方通中间件，

**快速交付**（3 分钟）：
"我们承诺 3 个月完成交付上线。行业平均需要 6-12 个月。我们能做到的原因是：

3）4 周后 POC 验收签字，进入商务合同。
我们会派出 { 项目经理 + 架构师 + 部署工程师 } 团队全程支持。"

## Q&A 常见问题应答

### Q: 你们比用友 / 西门子好在哪？
A: 三个维度：1）智能排产算法效果实测数据支撑；2）国产化率 100% vs 用友部分 / 西门子弱；
3）交付周期 3 月 vs 竞品 6-12 月。您具体想对比哪个维度我们可以深入。

### Q: 3 个月上线现实吗？
A: 现实。三个前提：贵司 IT 团队能按计划投入；POC 环境按时就位；不临时改需求。
我们有承诺书面的里程碑，每周同步进度，如果延期我们承担违约责任。

### Q: 与我们现有 SAP 的集成会不会有风险？
A: 会有集成复杂度，但可控。我们已有 XX 家使用 SAP 客户的成功案例。
POC 阶段我们就会重点验证 SAP 集成，如果 POC 过不去，项目不推进。

### Q: 后续升级怎么办？定制会不会影响？
A: 定制通过扩展点实现，不改核心代码。后续版本升级不受影响。
我们承诺 5 年内的免费小版本升级 + 有偿大版本升级。

## 反模式（汇报中避免）

- ❌ 陷入功能罗列（客户听不懂）
- ❌ 承诺不能兑现的时间 / 效果
- ❌ 攻击竞品（专业性差）
- ❌ 用"最"、"唯一"（客户会较真）
- ❌ 汇报超时（客户注意力有限）

## 与其他命令的边界

| 场景 | 用 |
|---|---|
| **方案 + POC → 估算 + 宣讲底稿** | 本命令 |
| 归档全部产物 | 下一步 `/sa-archive` |
| 需要一键跑完整 7 模块 | `/sa-pipeline` |
| 商务定价 | 商务团队（本命令不涉及） |
| PPT 美化 | 交给设计师（本命令只出底稿） |

## 反模式

- ❌ 输出没有 "⚠️ 报价底稿" 声明 —— 违规，会被当正式报价
- ❌ 定制工作量给具体人天而不是范围 —— 违规
- ❌ 服务人天没含售后 —— 遗漏关键项
- ❌ PPT 大纲没有汇报话术 —— 售前不敢用
- ❌ 汇报话术用"最"、"唯一"等 —— 违规
