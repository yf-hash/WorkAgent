# /sa-rfp — RFP 招标应答（Module 5.3）

> **端到端 7 模块流水线的第 5.3 站（专项之三）**

## 一句话

**输入 RFP 招标文件 + 我方总体方案，逐条应答，输出可提交的《招标应答表》 + 《技术偏离表》**。这是投标场景的核心产出物。

## 输入

```bash
# 最常见：RFP + 总体方案
/sa-rfp ./rfp/2026-政务云-RFP.pdf ./output/sa-pipeline/xxx/03-overall-solution.md

# 输出到指定目录
/sa-rfp ./rfp.pdf ./03-overall-solution.md --out ./output/sa-pipeline/xxx/04-rfp/
```

## 内部四步

### 步骤 1：RFP 解析

调用 `skills/sa/sa-rfp-response` 解析：
- 招标编号 / 招标方 / 截止时间
- 目录结构（技术需求 / 商务需求 / 服务需求 / 附件）
- 关键条款（评分项 / 分值 / 资质要求 / 交付要求）
- 逐条编号 + 原文 + 类别

### 步骤 2：打分项提取（🔑 关键）

- 自动识别"评分标准"章节
- 提取所有打分点 + 分值 + 判定方式
- 标注哪些打分点我方有明显优势 → 应答时重点展开
- 标注哪些打分点我方有明显劣势 → 应答时用规避话术

### 步骤 3：逐条应答

每条 RFP 条目：
- **完全满足 ✅**：写清楚我方哪个模块 / 版本 / 能力对应
- **部分满足 🟡**：写清楚哪些满足 + 哪些不满足 + 补齐路径
- **不满足 🔴**：诚实标注 + 替代方案

### 步骤 4：技术偏离表

对不完全满足的项目，生成正式的技术偏离表，供商务提交。

### 04-deviation-table.md（技术偏离表）

```markdown
# 技术偏离表：{{招标编号}}

> 说明：以下条款我方存在偏离，请招标方审阅。

| 条目号 | RFP 原文 | 偏离方向 | 我方能力 | 影响 | 补救方案 |
|---|---|---|---|---|---|
| T1.5.3 | 5 秒内响应所有查询 | 负偏离（部分） | 普通查询 ≤ 5s，复杂报表 ≤ 10s | 影响小，复杂报表频率低 | 预聚合 + 缓存优化到 5s，+ 2 周 |
| T1.5.5 | 支持 Oracle 数据库 | 负偏离（不满足） | 标品支持 OceanBase | 需定制适配 | 中间件层适配，+ 15 人天 |
| T3.2.1 | 提供 7×24 小时热线 | 正偏离（超越） | 7×24 + 1 小时响应承诺 | 我方能力更强 | — |

## 偏离说明
1. **负偏离**：我方能力低于 RFP 要求 —— 需补救方案 or 替代
2. **正偏离**：我方能力高于 RFP 要求 —— 加分项
3. **持平**：完全满足 —— 不入偏离表
```

## 与其他命令的边界

| 场景 | 用 |
|---|---|
| **RFP 招标 → 应答表 + 偏离表** | 本命令 |
| POC 测试方案 | `/sa-poc` |
| 实施方案 | `/sa-impl` |
| 需要一键跑完整 7 模块 | `/sa-pipeline` |
| 只解析 RFP（不出应答） | `/sa-intake --source rfp` |

## 反模式

- ❌ 应答"完全满足"但没引用方案哪个模块 —— 违规
- ❌ 不满足项没有替代方案 —— 违规
- ❌ 偏离表遗漏"影响" —— 商务会被客户问倒
- ❌ 打分项分析不做 —— 中标概率大打折扣
- ❌ 应答用夸张话术 —— 客户不傻，反而扣分
