# /sa-clarify — 客户调研澄清（Module 2）

> **端到端 7 模块流水线的第 2 站** — 处理销售转述的模糊客户需求
>
> /sa-intake →【本命令】→ /sa-solution-map → /sa-architect → /sa-poc/impl/rfp → /sa-quote → /sa-archive

## 一句话

**把销售转述的模糊碎片信息或 RFP 原文，加工成一份可以给客户拿去核对的《客户调研与痛点分析报告》**，含现状 / 痛点 / 显性/隐性诉求 / 合规约束 / 假设项 / 待确认项 / 风险初判。

## 输入

```bash
# 最常见：接 M1 输出
/sa-clarify ./output/sa-pipeline/mfg-mes-{date}/00-intake.json --mode mixed

# 直接给描述（跳过 M1）
/sa-clarify "某银行客户，要做移动办公" --mode human --industry finance

# 全部假设补全（用于快速原型验证）
/sa-clarify ./00-intake.json --mode auto
```

## 三种运行模式

| 模式 | 触发 | 行为 | 适合场景 |
|---|---|---|---|
| `human` | `--mode human` | 只出问题清单交给售前，售前访谈客户回来后再继续 | 高度模糊 / 合规敏感 / 大项目 |
| `mixed`（默认） | `--mode mixed` | 一般项自动假设 + 合规/预算/规模等关键项列到"待确认" | 中小项目 / 有一定信息 |
| `auto` | `--mode auto` | 全部基于行业历史案例假设，明确标【假设项，需要客户确认】 | 快速内部原型 / 立项前评估 |

**特别注意**：合规相关字段（等保 / 国产化 / 数据不出境）**不允许 auto 假设**，必须走 human 或 mixed 中的"待确认"栏。

## 内部三个子 Agent（顺序执行）

### Agent 2-1：信息缺口 & 歧义识别

**扫描 7 类信息**，识别缺失或歧义：

| # | 类别 | 关键问题 |
|---|---|---|
| 1 | 现有 IT 架构 | 什么系统 / 什么数据库 / 什么云 / 多少年历史 |
| 2 | 业务流程 | 主流程有几步 / 谁在哪一步 / 有没有审批 |
| 3 | 现存痛点 | 慢 / 错 / 漏 / 重 / 断，具体在哪一步 |
| 4 | 约束条件 | 时间 / 预算 / 人力 / 硬件 |
| 5 | 合规要求 | 等保几级 / 是否国产化 / 数据不出境 / 行业规范 |
| 6 | 性能指标 | 并发 / 数据量 / 响应时间 / 可用性 |
| 7 | 项目边界 | 哪些不做 / 哪些是二期 |
| + | 禁止项 | 客户明确说的"不接受什么" |

**输出**：`【缺失清单】` + `【歧义清单】`

### Agent 2-2：调研问题生成

**分三类问题**（每类 5-8 个）：

- **业务问题**：现在怎么做的？谁做？做几次？出错怎么办？
- **技术问题**：现有系统能否对接？数据怎么迁移？峰值多少？
- **合规问题**：需要过等保吗？数据能不能出园区？是否要求国产化？

**mode = human**：直接输出提问清单，等售前带回客户答案。
**mode = mixed**：非合规类基于同行业假设，合规类留在"待确认项"。
**mode = auto**：所有问题都基于同行业案例假设并标【假设项】。

### Agent 2-3：痛点 & 诉求收敛

**关键区分**：

- **表面诉求 vs 真实痛点**：
  - 表面："客户要个 BI 看板"
  - 真实：客户月末对账要 3 天，希望降到 1 天

- **业务诉求 / 技术诉求 / 合规诉求** 分类

- **伪需求识别**：
  - "增加导出按钮" → 真实是"月末对账"
  - "增加一个报表" → 真实是"某个决策场景"

- **需求内部冲突检测**：
  - 既要低成本 又要 超大并发
  - 既要私有化 又要 SaaS 化敏捷迭代
  - 既要国产化 又要 SAP / Oracle 深度集成

  ```
  【M2 调研澄清完成】《客户调研与痛点分析报告》已生成：
    - 客户：{name}
    - 业务痛点：{n} 条
    - 假设项：{m} 条
    - 待确认项：{k} 条（其中合规 {c} 条）
    - 检测到冲突：{cf} 条

  请选择：
  (1) 通过 → 进入 M3 方案拆解
  (2) 部分修改后继续 → 我改文件后按回车
  (3) 驳回重跑 → 补充信息重新澄清
  (4) 中止
  ```

- **合规硬约束 gate**：识别到"等保 / 国产化 / 数据不出境"等硬约束时，强制询问：
  ```
  【硬约束确认】以下客户合规约束将影响整个流水线：
    - 等保三级（关基）
    - 国产化率 ≥ 70%
    - 数据不出境

  是否确认这些约束已从客户方明确获知（非假设）？
  ```

## 与其他命令的边界

| 场景 | 用 |
|---|---|
| **M1 输入 → 结构化痛点报告** | 本命令 |
| 只想快速看假设 | 本命令 `--mode auto` |
| 需要一键跑完整 7 模块 | `/sa-pipeline` |
| 方案拆解 | 下一步 `/sa-solution-map` |
| 内部产品 PRD 澄清 | `/pm-clarify`（走 PM 流水线） |

## 反模式

- ❌ 合规字段用 auto 假设 —— 违规
- ❌ 未列"待确认项" —— 违规
- ❌ 冲突检测栏空缺 —— 违规
- ❌ 把客户口头承诺写成事实 —— 必须标注"客户口头"或"待确认"
- ❌ 报告没写"业务痛点"章节 —— 违规，这是本模块的核心产出
