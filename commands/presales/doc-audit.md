# /doc-audit — 产品文档自查审核

加载技能：`skills/presales/doc-auditor/SKILL.md`

## 触发条件
需要对产品文档进行质量审核、检查文档完整性、校验命名规范、审查内容合规时。适用于文档发布前的自查、版本更新后的核验、新产品资料首次评审。

## 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `<文档路径或产品名>` | 待审核的文档路径或产品名称（必填） | — |
| `--mode` | 审核模式（见下表） | `single` |
| `--strict` | 严格模式：将★★警告项也列为阻断项 | `false` |

### 审核模式

| `--mode` | 输出内容 | 适用场景 |
|----------|---------|---------|
| `single` | 单文档14项自查结果 + 问题清单 + 修改建议 | 发布前最后检查 |
| `fullset` | 全套24类文档完整性检查 + 缺口报告 | 新产品资料首次入库 |
| `format` | 专项：格式规范（命名/封面/目录/版权/字体） | 批量格式整改 |
| `naming` | 专项：文件命名规范校验 + 重命名建议 | 历史文档清理 |

## 使用示例

```
/doc-audit 产品白皮书.docx
/doc-audit "c:/产品资料/数据安全网关/" --mode fullset
/doc-audit 销售指南.docx --mode format --strict
/doc-audit "c:/产品资料/" --mode naming
```

## 执行流程

```
Step 1: 文档识别
  → 识别文档类型（按24类标准分类）
  → 提取文档元信息（文件名/版本/日期）

Step 2: 逐项自查（14项清单）
  → 格式类7项（F1-F7）
  → 内容类4项（C1-C4）
  → 上传类3项（U1-U3）
  → 输出：✅通过 / ⚠️建议 / ❌阻断

Step 3: 问题汇总
  → ❌阻断项（★★★）：必须修改才能发布
  → ⚠️建议项（★★/★）：建议修改，不阻断

Step 4: 修改建议
  → 针对每个问题给出具体修改指令
  → 提供正确示例
```
