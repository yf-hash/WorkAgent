# /sa-poc — POC 测试方案（Module 5.1）

> **端到端 7 模块流水线的第 5.1 站（专项之一）**
>
> /sa-architect →【本命令】/ /sa-impl / /sa-rfp → /sa-quote → /sa-archive

## 一句话

**基于总体方案生成一份可交付客户的 POC 测试方案** —— 明确"测什么、不测什么、环境要什么、测试用例、验收标准、时间、风险"。

## 输入

```bash
# 最常见：接 M4 输出
/sa-poc ./output/sa-pipeline/xxx/03-overall-solution.md

# 显式指定 POC 周期
/sa-poc ./03-overall-solution.md --duration 4  # 4 周

# 输出到指定位置
/sa-poc ./03-overall-solution.md --out ./output/sa-pipeline/xxx/04-poc-plan.md
```

## 内部处理

### 步骤 1：POC 范围界定（关键）

**从总体方案提取**：
- 客户 P0 痛点（一定要测）
- 差异化能力（我方优势项，必测）
- 高风险集成点（必测）
- 定制开发点（必测但可分阶段）

**明确不测的**：
- 已通过其他客户案例证明的成熟能力
- 后续版本才做的功能
- 与本次痛点无关的能力

### 步骤 2：环境要求清单

拆解到"客户方 / 我方"两侧：
- 客户方：服务器 / 网络 / 数据 / 账号 / 三方接口开放
- 我方：软件包 / 部署人员 / 培训材料

### 步骤 3：测试用例设计

每个测试用例：**目标 → 步骤 → 期望结果 → 通过标准（数字）**

### 步骤 4：验收判定

明确：
- 通过标准（客户签字）
- 部分通过（进入商务谈判）
- 不通过（回炉重来 / 项目暂停）

## Harness 卡点

**范围界定后**：AskUserQuestion：
```
【POC 范围】
必测：{n} 项（痛点 P1/P2、差异化能力、高风险集成）
可选：{m} 项（视客户重点关注）
不测：{k} 项（成熟能力 + 无关能力）

请确认范围，(y / n / edit)
```

## 4. POC 测试用例

### T1 - 智能排产算法验证
- **目标**：验证排产算法在客户真实数据下的效率与质量
- **前提**：环境 E1/E2/E4/E5 就绪
- **步骤**：
  1. 导入 1000 个订单
  2. 触发智能排产
  3. 检查排产结果（时间/资源/依赖）
  4. 对比客户 Excel 排产结果
- **期望结果**：
  - 排产完成时间 ≤ 10 分钟
  - 关键约束（交期、产能）满足率 ≥ 95%
  - 与 Excel 相比资源利用率提升 ≥ 15%
- **通过标准**：所有期望结果达成，客户业务方签字
- **不通过处理**：定位算法参数问题，回炉调整

## 5. 验收判定标准

### 5.1 整体判定
| 结果 | 标准 | 后续动作 |
|---|---|---|
| ✅ 全通过 | 必测项全部通过 + 可选项 ≥ 50% 通过 | 进入商务合同 |
| 🟡 部分通过 | 必测项 ≥ 80% + 无 P0 失败 | 进入整改期，1 个月内补测 |
| 🔴 不通过 | 有 P0 失败 or 必测项 < 80% | POC 终止，客户可选其他方案 |

### 5.2 签字环节
- 客户方：CIO + 业务负责人 + IT 负责人
- 我方：售前 + 项目经理

## 6. POC 周期

```
W1: 环境搭建 + 数据准备
    - 客户提供服务器、账号、测试数据
    - 我方部署软件、连通性测试

W2: 集成对接 + 初步测试
    - SAP 集成对接
    - 设备接入
    - T1/T2 初测

W3: 深度测试 + 客户参与
    - 客户业务方参与用例执行
    - T3/T4/T5 全部执行
    - 缺陷修复

W4: 验收 + 汇报
    - 客户签字验收
    - POC 汇报会
    - 缺陷 / 改进 backlog
```

## 与其他命令的边界

| 场景 | 用 |
|---|---|
| **总体方案 → POC 测试方案** | 本命令 |
| 实施方案（上线阶段） | `/sa-impl` |
| RFP 应答 | `/sa-rfp` |
| 需要一键跑完整 7 模块 | `/sa-pipeline` |

## 反模式

- ❌ 只列必测项，不写"不测项" —— 违规，客户会加需求
- ❌ 环境要求没写"责任人 + 截止时间" —— 到时候没就位没人担责
- ❌ 测试用例期望结果不带数字 —— 违规
- ❌ 验收标准模糊 —— 违规，最终扯皮
- ❌ 风险栏 < 5 条 —— POC 一定会出问题，风险要提前列
