# /self-evolve

内容自进化命令。五阶段流程，每个阶段有明确的输入、输出和用户确认点：

```
阶段一：风格学习        → 生成风格卡片 ⏸ 用户确认
阶段二：技术调查        → 生成调查摘要 ⏸ 用户确认
阶段三：Writer-Reviewer 迭代  → 达标稿件
阶段四：内容丰富        → 段落化改写（按需触发）⏸ 用户确认
阶段五：AI 去痕         → 最终文章输出
```

**重要执行原则**：每轮迭代结束后，只保留当前最新稿件和评分摘要（一行），丢弃历史轮次的完整内容。使用 `--dangerously-skip-permissions` 或 `allow-dangerously-skip-permissions` 模式时，各阶段自动连续执行直至任务完成，无需用户逐阶段确认。

**上下文节制原则（防止 Autocompact thrashing）**：
- 每个阶段产物必须立即用 Write 工具写入临时文件（路径：`./self-evolve-tmp/`），不得仅保留在上下文中
- WebFetch 抓取文章时，每篇抓取后立即提取所需信息并丢弃原文，不在上下文中保留完整网页内容
- 阶段三每轮迭代结束后，将最新稿件写入 `./self-evolve-tmp/draft-latest.md`，将评分摘要追加到 `./self-evolve-tmp/scores.md`，然后从上下文中只保留文件路径引用
- 进入下一阶段前，通过 Read 工具按需读取上一阶段的文件，而不是依赖上下文记忆

---

## 用法

```
# 完整流程（风格学习 + 技术调查 + 创作）
/self-evolve --learn <url1,url2,...> --title <文章标题> [--framework <框架>]

# 使用已有风格卡片创作（跳过阶段一）
/self-evolve --style-card <路径> --title <文章标题> [--framework <框架>]

# 跳过技术调查（已有充足素材时）
/self-evolve --style-card <路径> --title <文章标题> --skip-research

# 仅风格学习（生成风格卡片，稍后复用）
/self-evolve --learn <url1,url2,...>

# 优化已有文章（以风格卡片为基准）
/self-evolve --style-card <路径> <文档路径>
```

## 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--learn <urls>` | 1-5 篇优质文章链接，触发阶段一风格学习 | — |
| `--title <标题>` | 要创作的文章标题 | — |
| `--framework <框架>` | 文章框架，如 `"问题引入→分析→方案→行动"` | AI 自动推导 |
| `--style-card <路径>` | 已保存的风格卡片路径（跳过阶段一） | — |
| `--save-card <路径>` | 将生成的风格卡片保存到指定路径 | — |
| `--target-score <分>` | 迭代目标评分，范围 60-100 | **85** |
| `--max-rounds <轮>` | 最大迭代轮次，范围 1-10 | **3** |
| `--mode <模式>` | 见下方模式说明 | `quality` |
| `--skip-research` | 跳过阶段二技术调查 | false |
| `--show-process` | 显示完整迭代过程 | false |
| `--report` | 生成进化报告 | false |

### 创作模式（`--mode`）

| 模式 | 侧重 | Reviewer 重点 |
|------|------|--------------|
| `quality` | 内容深度、案例数据、逻辑结构 | 内容质量子维度优先 |
| `humanize` | 去 AI 味、活人感、灵魂注入 | 风格合规优先；扫描 24 种 AI 写作模式；应用六大人性原则 |
| `balance` | 两维度均衡推进 | 最低子维度优先 |

`humanize` 模式的目标不是"无菌干净"，而是"有声音、有立场、有灵魂"。基于 op7418/Humanizer-zh 六大原则：表明立场 / 变换节奏 / 承认复杂性 / 适当用"我" / 允许一些混乱 / 感受具体化。

## 执行流程

### 阶段一：风格学习（`--learn` 触发，有 `--style-card` 时跳过）

**输入**：1-5 篇优质文章 URL
**输出**：风格卡片 ⏸ 等待用户确认

**步骤 1 — 逐篇抓取与解析**

使用 WebFetch 逐篇抓取文章，每篇抓取后立即提取以下信息并写入 `./self-evolve-tmp/article-N-analysis.md`，然后丢弃原文全文，不在上下文中保留：标题、段落结构、小标题分布、开头/结尾模式、字数、平均段落长度。每篇处理完毕后再抓取下一篇。

**步骤 2 — 7 维度结构分析**

| 分析维度 | 分析内容 |
|----------|----------|
| 开篇模式 | 如何抓住读者（问题/故事/数据/观点） |
| 论证结构 | 总分总 / 问题-解决 / 时间线 / 对比 |
| 段落节奏 | 长短句比例、段落字数分布 |
| 过渡方式 | 章节间如何衔接 |
| 结尾策略 | 总结/行动号召/开放式提问 |
| 语言风格 | 口语化程度、人称使用、情感浓度 |
| 案例密度 | 每千字案例数量、案例类型 |

**步骤 2.5 — 读取分析文件**

从 `./self-evolve-tmp/article-N-analysis.md` 逐篇读取提取结果，汇总后进行 7 维度分析。读取完成后不再保留各篇分析的完整内容，只保留汇总结论。

**步骤 3 — 提炼共性规律，生成风格卡片**

**禁止事项**默认包含 Humanizer-zh 的 AI 高频词列表（此外/至关重要/深入探讨/格局/增强/培养/宝贵的/充满活力的/首先其次最后/值得注意的是 等）。

```markdown
## 风格卡片（提炼自 N 篇优质文章）

**开篇原则**：[共性开篇策略]
**结构原则**：[共性论证结构]
**节奏原则**：[段落节奏规律]
**语言原则**：[语言风格特征]
**案例原则**：[案例使用规律]
**结尾原则**：[结尾策略]
**禁止事项**：[AI 高频词 + 从参考文章识别出的反模式]
```

**步骤 4 — 写入文件**

将风格卡片写入 `./self-evolve-tmp/style-card.md`（若指定 `--save-card` 则同时写入目标路径）。展示风格卡片内容。非 `allow-dangerously-skip-permissions` 模式下等待用户确认/修改；跳过权限模式下自动进入下一阶段。确认后上下文中只保留文件路径 `./self-evolve-tmp/style-card.md`，不保留卡片全文。

用户可：直接确认 / 修改某项原则后确认（修改后重新写入文件）。

---

### 阶段二：技术调查（风格卡片确认后，`--skip-research` 时跳过）

**输入**：`--title` + `--framework`（推断写作意图）
**输出**：调查摘要（控制在 500 字以内）

目的是让 Writer 在充足的事实/数据支撑下创作，而不是凭空发挥。

**调查策略：横纵双轴并行搜索**

| 调查轴 | 目标 | 典型来源 |
|--------|------|---------|
| **纵向**（时间深度） | 技术/概念的起源、演进节点、关键决策 | 官方博客、arXiv 论文、创始人推文、GitHub Release Notes |
| **横向**（同期广度） | 同类技术/方案的对比、差异点、用户口碑 | 竞品官网、Reddit/知乎讨论、评测文章、GitHub Issues |

**执行步骤**

1. 从 `--title` 和 `--framework` 推断核心技术议题
2. 并行双轴搜索：纵向追踪技术起源与演进（学术类必查 arXiv），横向识别同类方案与用户反馈。每次 WebFetch 抓取页面后立即提取关键信息写入 `./self-evolve-tmp/research-notes.md`，丢弃页面原文
3. 信息充分性自检：纵向能还原清晰演进脉络？横向主要竞品都覆盖到？关键事实有来源支撑？
4. 从 `./self-evolve-tmp/research-notes.md` 读取笔记，提炼为 ≤500 字调查摘要，写入 `./self-evolve-tmp/research-summary.md`
5. 展示调查摘要。非 `allow-dangerously-skip-permissions` 模式下等待用户确认；跳过权限模式下自动进入下一阶段。确认后上下文只保留文件路径，不保留摘要全文

```markdown
## 技术调查摘要（≤500 字）

**主题**：[文章核心技术议题]

**纵向发现**（技术演进）
- 起源：[技术诞生背景、提出者、时间节点]
- 关键演进：[主要版本/论文/里程碑，按时间排列]
- 当前状态：[最新进展、尚未解决的核心问题]

**横向发现**（同类对比）
- 主要方案：[列举 2-5 个同类技术/产品]
- 核心差异：[各方案的本质区别]
- 用户口碑：[社区中被提及最多的优缺点]

**关键素材**（可直接用于写作）
- [数据/案例/引用 1]
- [数据/案例/引用 2]

**来源清单**：[URL 列表]
```

用户可：直接确认进入创作 / 要求补充某个方向 / 跳过直接创作。

---

### 阶段三：Writer-Reviewer 迭代（技术调查确认后）

**输入**：风格卡片 + 调查摘要 + `--mode`
**输出**：达到目标分数或触发终止条件的稿件

**确定输入类型**

- 有 `--framework` → 按标题 + 框架从零创作
- 仅有 `--title` → AI 根据风格卡片结构原则推导框架（输出供用户确认）
- 有文档路径 → 优化模式，先做基线评分（Round 0）

**迭代循环**

每轮开始前，用 Read 工具读取 `./self-evolve-tmp/style-card.md` 和 `./self-evolve-tmp/research-summary.md`（若存在）作为创作依据。

Writer 按风格卡片生成/改写稿件（调查素材优先作为案例/数据支撑）→ 将稿件写入 `./self-evolve-tmp/draft-latest.md` → Reviewer 双维度评分 + 精准诊断 → 将一行评分摘要追加到 `./self-evolve-tmp/scores.md` → 上下文中丢弃稿件全文和诊断详情，只保留评分摘要一行 → Writer 读取 `./self-evolve-tmp/draft-latest.md` 针对诊断改稿 → 循环直至终止。

每轮结束后上下文只保留：当前评分摘要一行 + 文件路径引用。历史轮次的完整稿件和诊断报告不在上下文中保留。

**终止条件（满足任一即停）**

- 评分达到 `--target-score`（默认 85/100）
- 已迭代 `--max-rounds` 轮（默认 3）
- 连续 2 次提升 < 3 分（边际收益递减）

---

### 阶段四：内容丰富（迭代完成后自动检测，按需触发）

**输入**：阶段三输出的稿件
**输出**：段落化改写后的稿件

检测文章是否存在 **AI 格式化过度** 问题，满足以下任一条件时触发改写：

- 全文无序列表项总数超过全文段落数的 40%
- 连续出现 3 个或以上纯要点式短行（每行 ≤ 25 字，无完整语句）
- 某个章节内 80% 以上内容为列表，缺少过渡段落

**不触发时**：直接跳过，进入阶段五。

**触发时执行步骤**

1. 读取 `./self-evolve-tmp/draft-latest.md`，输出检测报告：标注所有疑似堆砌区块（章节名 + 列表项数 + 占比）
2. 段落化改写，按要点数量选择转换规则：
   - ≤3 个要点 → 融入前后段落，以连贯句式叙述
   - 3-5 个要点 → 拆分为 2-3 个叙述段落，每段以核心论点展开，辅以解释、例证或数据
   - ≥5 个要点 → 重构为"引导句 + 展开段 + 小结句"三段式，必要时保留 1 个精简列表，其余转为正文
   - 纯枚举型内容（参数、步骤清单）和用户明确要求的对比表格保留列表形式
3. 节奏校验：确认段落长短有变化，避免连续 4 个以上字数相近的段落
4. 将改写后稿件写入 `./self-evolve-tmp/draft-enriched.md`
5. 将改写后稿件写入 `./self-evolve-tmp/draft-enriched.md`。展示改写前后对比（仅展示变动段落，不展示全文）。非 `allow-dangerously-skip-permissions` 模式下等待用户确认；跳过权限模式下自动进入阶段五

---

### 阶段五：AI 去痕（输出最终文章前，必执行）

**输入**：`./self-evolve-tmp/draft-enriched.md`（若阶段四未触发则读取 `./self-evolve-tmp/draft-latest.md`）
**输出**：最终文章写入 `./self-evolve-tmp/final.md`

用 Read 工具读取输入文件，对全文执行一轮系统性 AI 去痕：

**第一步 — 扫描去痕**

- 逐句扫描 24 种 AI 写作模式，消除内容类、语言类、风格类、交流类、填充类 AI 特征
- 对照中文高频 AI 词汇列表，消除"此外/至关重要/深入探讨/格局/增强/培养/宝贵的/充满活力的/首先其次最后/值得注意的是/标志着/见证了/体现了"等
- 执行 7 项句式微策略：句式与关联词调整、主语明确化、长句优化拆分、同义词自然化替换、标点符号微调、精简冗余、上下文连贯性检查

**第二步 — 灵魂注入（六大人性原则）**

H1 表明立场 / H2 变换节奏 / H3 承认复杂性 / H4 适当用"我" / H5 允许一些混乱 / H6 感受具体化

去痕完成后将最终文章写入 `./self-evolve-tmp/final.md`，然后输出进化概览，并告知用户最终文章已保存路径。

## 质量标准

| 维度 | 满分 | 子维度 |
|------|------|--------|
| 内容质量 | 50 | 深度与完整性 /15 + 案例与数据 /15 + 逻辑连贯性 /10 + 结构完整性 /10 |
| 风格合规 | 50 | 自然度 /15（含 24 种 AI 模式扫描） + 真实感 /15（含六大人性原则） + 节奏变化 /10 + 风格一致性 /10 |

## 诊断报告格式（精简版）

每轮迭代输出一行评分摘要 + 最高优先级问题：

```
第 N 轮 | 总分：XX/100（内容 XX/50 + 风格 XX/50）
P1：[最高优先级问题，1-2 条，含具体位置和改写方向]
P2：[次优先级问题，1-2 条]
建议：[继续迭代 / 已达标 / 边际收益递减建议停止]
```

## proven_solutions 策略库

Writer 改稿时优先从以下已验证策略中选取：

**内容质量策略**
- CQ-01 案例具象化（论点缺乏支撑 → 案例分 +3-5）
- CQ-02 数据精确化（描述模糊 → 深度分 +2-4）
- CQ-03 认知进化轨迹（缺乏历史背景 → 深度分 +3-5）
- CQ-04 反事实推理（论证不够有力 → 深度分 +4-6）
- CQ-05 例外情况讨论（结论过于绝对 → 完整性 +2-3）
- CQ-06 段落化展开（要点式表达 → 结构分 +3-5）

**风格合规策略**
- SC-01 删除 AI 高频词（此外/至关重要/格局等 → 自然度 +3-5）
- SC-02 打破公式结构（三项排比/否定排比过多 → 自然度 +2-4）
- SC-03 节奏变化注入（句子长度单一 → 节奏分 +3-4）
- SC-04 个人观点植入（只报告事实，无反应无立场 → 真实感 +3-5）
- SC-05 主动语态转换（被动语态/无主语片段过多 → 自然度 +2-3）
- SC-06 真实转折设计（逻辑过于完美，无摩擦感 → 真实感 +2-4）
- SC-07 删除意义膨胀（标志着/见证了/体现了 → 自然度 +2-3）
- SC-08 具体化归因（"专家认为"等无来源表述 → 真实感 +3-4）
- SC-09 删除宣传语言（广告式形容词 → 自然度 +2-3）
- SC-10 去除聊天套语（"希望对您有帮助"等 → 自然度 +2-3）
- SC-11 精简填充短语（"值得注意的是/为了实现这一目标"等 → 精炼度 +2-4）
- SC-12 去除破折号滥用（每句多个破折号 → 自然度 +1-2）
- SC-13 具体化结尾（"未来光明/激动人心"等泛化收尾 → 真实感 +2-3）

**风格卡片策略**
- SL-01 开篇模式复刻（复用优质文章的开篇钩子结构）
- SL-02 论证结构迁移（迁移优质文章的论证框架）
- SL-03 节奏模式对齐（对齐参考文章的段落节奏规律）
- SL-04 语言风格校准（校准口语化程度和情感浓度）

## 核心原则

- **风格卡片优先**：所有创作必须以风格卡片为基准，不是凭空发挥
- **用户确认闸门**：阶段一风格卡片、阶段二调查摘要、阶段四内容丰富（触发时），各暂停等待用户确认
- **调查驱动内容**：先摸清技术来龙去脉和横向竞品，再动笔——素材决定内容深度下限
- **诊断驱动改稿**：Writer 每轮改稿必须针对 Reviewer 的具体诊断，不盲目重写
- **上下文节制**：每轮迭代只保留最新稿件和一行评分摘要，不累积历史轮次全文
- **边际收益递减时主动停止**：避免过度优化
- **活人感优先**：去 AI 味的目标是"有声音、有立场、有灵魂"，不只是"无菌干净"
