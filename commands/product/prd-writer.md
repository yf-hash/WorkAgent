# /prd-writer — 对话式 PRD 引导写作

加载技能：`skills/prd-writer/SKILL.md`

## 与 /product-spec 的区别

| | `/prd-writer` | `/product-spec` |
|--|--|--|
| 交互方式 | 多轮对话，渐进追问 | 一次输入，一次输出 |
| 适合场景 | 想法模糊/非 PM/需要引导 | 想法清晰/有经验/需要模板 |
| 核心价值 | 帮你想清楚再写 | 快速生成结构化文档 |
| 文档评估 | ✅ 内置三层评分 | ❌ |
| 增量更新 | ✅ 不重写原文，打标记 | ❌ |
| 两阶段闸门 | ✅ 概念稿确认后才写实现稿 | ❌ |

---

## 三种模式

```
/prd-writer                  → 自动判断模式（AI 会先问你情况）
/prd-writer --mode a         → Mode A：从零生成（有想法，没文档）
/prd-writer --mode b         → Mode B：评估现有文档
/prd-writer --mode b doc.md  → Mode B：评估指定文件
/prd-writer --mode c         → Mode C：增量更新（有文档，要加功能）
/prd-writer --mode c doc.md  → Mode C：对指定文件做增量更新
```

---

## 执行逻辑

### 自动判断模式（不带 --mode 时）

AI 先问：
> "你目前处于哪种情况？
> A. 有产品/功能想法，还没有文档
> B. 已有一份 PRD，想评估或优化
> C. 已有一份 PRD，想增加新功能/模块"

---

### Mode A：从零引导生成

**核心流程：**

```
Step 0  资质核查         ← 先说核心想法，判断是否ready
Step 1  三镜诊断         ← 用户/商业/技术 三个视角对话追问
Step 2  输出概念稿       ← 方向对齐，等待确认（闸门 1）
Step 3  输出实现稿       ← 可开发的完整规格（闸门 2 只在概念稿确认后触发）
```

**Step 0 — 资质核查**

AI 会问：
> "能先跟我说说这个产品/功能的核心想法是什么吗？一两句话就好——想解决谁的什么问题？"

| 用户回应 | 下一步 |
|---------|-------|
| 能清晰描述谁/用什么/解决什么 | 进入三镜诊断 |
| 模糊但有方向 | 追问 1-2 个定向问题后继续 |
| 完全没有方向 | 建议先思考，暂停流程 |

**Step 1 — 三镜诊断（每次只问 1-2 个问题）**

用户视角追问方向：
- 用户现在怎么解决这个问题？
- 你的方案比现有方式好在哪里？
- 你跟真实用户聊过吗？

商业视角追问方向：
- 这个产品怎么赚钱？
- 有竞品吗？差异是什么？
- 目标用户规模大概多少？

技术视角追问方向：
- 有核心技术能力吗？
- 最难实现的功能是哪个？
- 如果只做一个核心功能先上线，是哪个？

**Step 2 — 概念稿（V1）**

```markdown
输出内容（控制在 1 页内）：
- 一句话定位
- 产品形态 + 选择理由
- 目标用户（1-2 个画像）+ 核心痛点
- 产品价值（用户价值 + 商业逻辑）
- 核心功能方向（只写方向，不展细节）
- 本次不做（排除项 + 原因）
- 待解决的关键问题
```

输出后 AI 会问：
> "以上是基于你的描述梳理出的产品方向，请确认：方向是否准确？有哪些需要调整？确认后我们进入详细规格。"

**Step 3 — 实现稿（V2）**（只在概念稿确认后执行）

```markdown
完整 PRD 结构：
1. 产品概述（继承概念稿）
2. 目标用户与使用场景（展开画像 + 2-3 个场景）
3. 核心用户流程（Mermaid 流程图，含异常分支）
4. 功能列表（树状 + 🔴/🟡/⚪ 优先级）
   4.1 关键页面线框图（ASCII）
5. 功能详情（每个🔴核心功能单独一节）
   - 描述 + 触发条件
   - 交互细节（操作反馈/破坏性确认/空态/失败引导）
   - 状态清单（6 种状态）
   - 边界条件（空输入/溢出/网络/权限/并发/格式）
   - 数据规格表（字段/类型/长度/必填/默认/验证）
6. 文案规范
   6.1 整体语气
   6.2 技术说明文案（面向开发/AI）
   6.3 用户界面文案（按钮/空态/提示/确认）
7. 非功能需求（性能/权限/兼容性/安全/存储）
8. 待解决问题
```

---

### Mode B：评估现有文档

AI 会读取文档（或让用户粘贴），执行三层评分：

```
第一层：方向层（目标用户/一句话定位/产品形态/商业价值/范围边界）
第二层：结构层（用户流程/优先级功能列表/线框图/功能详情章节）
第三层：细节层（状态完整性/边界条件/交互反馈/数据规格/文案分离）
```

每项标注 ✅ / ❌ / ⚠️，最终输出：
- 总分（/10）+ 分层评分
- 主要问题汇总（按优先级）
- 三个处理选项供用户选择：A 补充薄弱章节 / B 全面重写 / C 只给建议

---

### Mode C：增量合并更新

```
Step 1  读取现有文档
Step 2  确认本次要新增/变更的内容
Step 3  分析影响范围（功能列表/用户流程/功能详情）
Step 4  执行合并，所有变更打 【本次更新】 标记
Step 5  合并后检查（流程图/新功能状态/文案同步）
```

所有变更标记：
```
【本次更新】新增：...
【本次更新】修改：[原内容] → [新内容]
【本次更新】删除：...
```

## 使用示例

```bash
# 从零开始（AI 自动引导）
/prd-writer

# 明确指定从零生成模式
/prd-writer --mode a

# 评估已有文档
/prd-writer --mode b
/prd-writer --mode b requirements.md

# 在现有文档基础上增加功能
/prd-writer --mode c
/prd-writer --mode c product-prd.md
```

---

## 推荐工作流

```
想法阶段（模糊）：
  /prd-writer --mode a          引导式生成概念稿 + 实现稿

已有草稿（需评估）：
  /prd-writer --mode b doc.md   三层评分 → 针对性补充

迭代阶段（加功能）：
  /prd-writer --mode c doc.md   增量更新，不破坏原文

深度规格化（清晰需求）：
  /product-spec --mode spec     Spec-First 四件套（适合已想清楚的场景）
```
