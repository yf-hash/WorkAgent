# /gtm-strategy — B2B 产品 Go-to-Market 上市战略

加载技能：`skills/strategy/gtm-strategy/SKILL.md`

> **核心理念**：B2B 产品 GTM 的本质，不是「做一次发布」，而是把产品从「能用」推向「有人买、能交付、可复制增长」的全过程。
> 整体可以分为 **市场验证 → 产品包装 → 样板客户 → 正式发布 → 规模化销售 → 持续增长** 六个阶段。

## 触发条件
- 需要为 B2B 产品制定从 0 到 1 的上市 SOP
- 已上市但增长不达预期，需要按阶段做诊断（哪个阶段卡住）
- 即将启动正式发布，需要 12 周甘特图与发布检查清单
- 需要把成功项目沉淀为可复制的标准方案与行业打法
- 需要 ICP / 场景 / 价值主张 / POC 验收标准 / 报价体系 / 线索分级等专项产出

## 执行流程（六阶段 SOP）

### 阶段 0：GTM 准备期（T-8 ~ T-6 周）
> 这个阶段不要急着做宣传，先回答清楚：**产品到底卖给谁、客户为什么现在要买、买了之后解决什么问题。**

**关键任务**
| 工作项 | 具体动作 | 输出物 |
|--------|---------|--------|
| 明确目标客户 ICP | 定义客户行业、规模、角色、预算、采购路径 | ICP 画像 |
| 明确核心场景 | 找出 3–5 个最容易成交的高价值场景 | 场景清单 |
| 明确客户痛点 | 梳理客户当前成本、风险、效率、合规压力 | 痛点地图 |
| 竞品分析 | 分析同类产品功能、价格、客户、差异点 | 竞品对比表 |
| 价值主张 | 提炼一句话定位和 3 个核心卖点 | 产品定位文案 |

**阶段必须回答的 6 个关键问题**
1. 谁最痛？
2. 谁有预算？
3. 谁有采购权？
4. 谁最容易成为样板客户？
5. 我们比竞品强在哪里？
6. 客户为什么现在必须行动？

**阶段交付物**：ICP 客户画像 / 行业场景地图 / 客户痛点清单 / 竞品对比表 / 产品一句话定位 / 核心价值主张

---

### 阶段 1：产品包装期（T-6 ~ T-4 周）
> 把「技术能力」包装成「客户可购买的解决方案」。很多 B2B 产品失败，不是产品能力不强，而是客户听不懂、销售讲不清、材料不成体系。

**关键任务**
| 工作项 | 具体动作 | 输出物 |
|--------|---------|--------|
| 产品定位包装 | 明确产品是什么、不是什么、解决什么问题 | 产品介绍页 |
| 方案包装 | 按行业 / 场景形成解决方案 | 行业解决方案 PPT |
| 销售材料 | 准备销售可直接使用的材料 | BP、售前 PPT、FAQ |
| 技术材料 | 准备技术评审和客户 CTO 可看的材料 | 白皮书、架构图、部署方案 |
| Demo 准备 | 做一个能快速打动客户的演示流程 | Demo 脚本 |
| 报价设计 | 设计 SaaS / 私有化 / 订阅 / 项目制报价 | 报价单 |

**产品包装的核心结构**（建议所有 B2B 产品材料按此顺序组织）
1. 行业趋势 → 2. 客户痛点 → 3. 解决方案 → 4. 产品架构 → 5. 核心功能 → 6. 典型场景 → 7. 客户价值 → 8. 部署方式 → 9. 成功案例 → 10. 商务模式

**阶段交付物**：产品官网页面 / 产品介绍 PPT / 解决方案 PPT / 技术白皮书 / 产品架构图 / Demo 视频与脚本 / 客户 FAQ / 报价体系 / 合同模板

---

### 阶段 2：内测与样板客户期（T-4 ~ T-1 周）
> 这个阶段的目标不是大规模销售，而是 **快速验证产品价值，找到可讲、可复用、可信的客户案例。**

**关键任务**
| 工作项 | 具体动作 | 输出物 |
|--------|---------|--------|
| 招募种子客户 | 从已有关系、行业客户、合作伙伴中筛选 | 种子客户名单 |
| 设计 POC | 明确 POC 范围、周期、成功标准 | POC 方案 |
| 快速交付 | 用小范围场景验证核心价值 | POC 结果 |
| 收集反馈 | 记录客户问题、需求、反对意见 | 反馈清单 |
| 打磨案例 | 提炼客户价值、数据、前后对比 | 案例素材 |
| 调整产品 | 根据反馈优化功能、话术、定价 | 迭代清单 |

**POC 成功标准（每个 POC 开始前必须定义清楚，否则 POC 容易变成无限试用）**
- 验证什么场景？
- 用什么数据？
- 多久完成？
- 谁来验收？
- 什么结果算成功？
- 成功后下一步是什么？

**阶段交付物**：种子客户清单 / POC 标准方案 / POC 验收标准 / 客户反馈记录 / 样板案例初稿 / 产品优化清单 / 销售反对意见库

---

### 阶段 3：正式发布期（T 周）
> 正式发布的目标是制造市场认知，让客户知道你是谁、解决什么问题、为什么值得了解。
> **B2B 发布不一定追求全民刷屏，更重要的是触达正确的人。**

**关键任务**
| 工作项 | 具体动作 | 输出物 |
|--------|---------|--------|
| 发布内容 | 发布产品文章、官网、海报、视频 | 发布物料包 |
| 市场传播 | 微信公众号、媒体、社群、朋友圈、行业群 | 传播计划 |
| 销售跟进 | 同步销售名单，统一话术 | 销售作战表 |
| 渠道联动 | 让合作伙伴同步转发和推荐 | 渠道传播清单 |
| 线索承接 | 建表记录咨询客户、预约 Demo、下载资料 | 线索表 |
| 高管背书 | 创始人、专家、客户证言增强信任 | 背书素材 |

**正式发布至少准备的物料**：一篇产品发布长文 / 一张产品海报 / 一个产品官网页面 / 一个 3–5 分钟 Demo 视频 / 一套销售 PPT / 一份技术白皮书 / 一份客户 FAQ / 一个预约 Demo 表单

**阶段交付物**：产品发布文章 / 产品海报 / 官网落地页 / Demo 视频 / 媒体稿 / 销售话术 / 客户线索表 / 传播数据报告

---

### 阶段 4：销售转化期（T+1 ~ T+8 周）
> 发布之后最关键的不是继续发文章，而是 **快速把线索转化成商机、POC、报价和合同。**

**关键任务**
| 工作项 | 具体动作 | 输出物 |
|--------|---------|--------|
| 线索分级 | 按客户价值、预算、需求急迫度分级 | A/B/C 客户池 |
| 销售触达 | 电话、微信、会议、拜访 | 跟进记录 |
| 需求诊断 | 识别客户真实场景、痛点、预算、采购流程 | 需求调研表 |
| 售前方案 | 输出针对客户场景的方案 | 定制方案 |
| POC 推进 | 控制周期和验收标准 | POC 报告 |
| 商务报价 | 根据客户规模和部署方式报价 | 报价单 |
| 合同推进 | 法务、采购、付款、交付排期 | 合同与回款计划 |

**线索分级建议**
| 等级 | 特征 | 动作 |
|------|------|------|
| A 类 | 有明确需求、预算、负责人、时间表 | 销售和售前重点跟进 |
| B 类 | 有兴趣但需求不清或预算未定 | 持续教育和场景挖掘 |
| C 类 | 只是了解产品 | 进入市场培育池 |

**阶段交付物**：商机漏斗 / 客户需求调研表 / POC 方案 / 定制化售前方案 / 报价单 / 合同模板 / 客户跟进节奏表

---

### 阶段 5：规模化增长期（T+8 周以后）
> 当产品已经有样板客户和初步成交后，重点从「单点突破」转向「可复制增长」。

**关键任务**
| 工作项 | 具体动作 | 输出物 |
|--------|---------|--------|
| 标准化方案 | 把成功项目沉淀成标准方案 | 标准方案包 |
| 行业复制 | 选择 2–3 个重点行业复制 | 行业打法 |
| 渠道建设 | 找集成商、代理商、生态伙伴 | 渠道政策 |
| 客户成功 | 提升续费、扩容、复购 | 客户成功流程 |
| 产品迭代 | 根据客户反馈优化功能 | Roadmap |
| 数据复盘 | 分析线索、转化、客单价、回款 | GTM 复盘报告 |

**增长阶段核心指标**
| 指标类型 | 重点指标 |
|---------|---------|
| 市场指标 | 官网访问、资料下载、预约 Demo、活动报名 |
| 销售指标 | 线索数、商机数、POC 数、报价数、成交数 |
| 商务指标 | 客单价、合同额、回款额、销售周期 |
| 产品指标 | 激活率、使用频次、功能使用率 |
| 客户成功 | 续费率、扩容率、转介绍率 |

## B2B GTM 12 周甘特图（标准 SOP）

| 周期 | 阶段 | 核心动作 | 负责人 |
|------|------|---------|--------|
| 第 1 周 | 市场定义 | 明确 ICP、行业场景、客户痛点 | CEO / 产品 / 市场 |
| 第 2 周 | 竞品分析 | 完成竞品、差异化、价格分析 | 产品 / 市场 |
| 第 3 周 | 价值主张 | 明确定位、卖点、核心话术 | 产品 / 市场 / 销售 |
| 第 4 周 | 产品包装 | 完成官网、PPT、白皮书、Demo 脚本 | 市场 / 产品 |
| 第 5 周 | 销售准备 | 完成报价、FAQ、合同、销售话术 | 销售 / 售前 / 法务 |
| 第 6 周 | 种子客户 | 筛选并邀约首批内测 / POC 客户 | 销售 / BD |
| 第 7 周 | POC 验证 | 完成客户试用、部署、价值验证 | 售前 / 交付 |
| 第 8 周 | 案例沉淀 | 整理 POC 结果、客户反馈、案例素材 | 市场 / 售前 |
| 第 9 周 | 正式发布 | 发布文章、官网、海报、Demo 视频 | 市场 |
| 第 10 周 | 线索承接 | 线索分级、销售跟进、预约演示 | 销售 |
| 第 11 周 | 商机推进 | 输出客户方案、POC、报价 | 销售 / 售前 |
| 第 12 周 | 复盘优化 | 复盘转化数据，优化话术和方案 | CEO / 市场 / 销售 |

## B2B GTM 标准流程图

```
市场洞察
   ↓
ICP 定义
   ↓
场景与痛点梳理
   ↓
竞品与差异化分析
   ↓
产品定位与价值主张
   ↓
产品包装与销售材料
   ↓
种子客户 / POC
   ↓
样板案例沉淀
   ↓
正式发布
   ↓
销售线索承接
   ↓
商机推进 / 报价 / 合同
   ↓
客户成功 / 复购 / 行业复制
```

## 每个阶段最容易踩的坑

| 阶段 | 常见问题 | 正确做法 |
|------|---------|---------|
| 市场定义 | 客户太泛，谁都想卖 | 先锁定最痛、最容易成交的客户 |
| 产品包装 | 只讲技术，不讲客户价值 | 用客户痛点组织产品能力 |
| POC | 没有验收标准，越试越久 | POC 前明确范围、周期和成功标准 |
| 发布 | 只做声量，不接线索 | 发布前准备线索承接机制 |
| 销售 | 只讲产品，不问需求 | 先做诊断，再给方案 |
| 增长 | 每个项目都定制 | 把成功案例沉淀为标准打法 |

## 与其他命令的协同关系

```
/gtm-strategy（B2B GTM 主入口）
  ├── /market-research        → 阶段 0：竞品研究、TAM/SAM/SOM、行业场景
  ├── /prd --mode standard           → PRD GTM 章节、ICP / 场景需求
  ├── /pricing-strategy       → 阶段 1：SaaS / 私有化 / 订阅 / 项目制报价
  ├── /battle-card            → 阶段 1-4：销售对比 / 反对意见库
  ├── /sales-guide-writer     → 阶段 1-4：销售话术 / FAQ / 售前 PPT
  ├── /poc-plan               → 阶段 2-4：POC 方案与验收标准
  ├── /product-case-writer    → 阶段 2-5：样板客户案例
  ├── /launch-checklist       → 阶段 3：发布前检查清单
  ├── /rfp-response           → 阶段 4：央国企招投标响应
  ├── /win-loss-analysis      → 阶段 4-5：赢/失单复盘
  ├── /product-roadmap        → 阶段 5：产品迭代路线图
  └── @gtm-strategist         → 全链路 GTM Agent 编排（推荐复杂场景）
```

---

## 使用示例

```bash
# B2B 新产品的完整六阶段 SOP（默认）
/gtm-strategy 智能合同审查 SaaS

# 输出 12 周甘特图（市场/产品/销售/售前协作排期）
/gtm-strategy AI 客服平台 --mode sop --output gantt

# 已上市但转化卡在 POC 阶段，做诊断
/gtm-strategy 工业质检 AI 产品 --mode diagnose --stage pilot --motion solution

# 即将正式发布，生成发布检查清单
/gtm-strategy 企业知识库 SaaS --mode launch --stage launch --output checklist

# 央国企赛道，融合招投标与信创要求
/gtm-strategy 数据安全平台 --mode fullplan --market cn-soe --motion solution

# 规模化阶段：标准化方案 + 行业复制 + 渠道建设
/gtm-strategy 低代码平台 --mode optimize --stage scale --motion platform

# 战略层澄清：ICP / 价值主张 / 竞品差异化
/gtm-strategy 我们做了一款多 Agent 编排平台 --mode strategy --output brief
```
