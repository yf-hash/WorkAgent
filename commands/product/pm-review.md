# /pm-review — 产品方案质量评审

请对以下产品方案/PRD/需求列表进行**产品经理视角**评审：

$ARGUMENTS

> 与 `/review-plan`（开发计划评审）互补：
> 本命令做**人工产品视角**的定性评审，关注客户价值、商业逻辑、产品取舍。

## 评审维度（10 维）

1. **客户价值**是否清晰（谁在什么场景获得什么收益）
2. **业务场景**是否完整（含异常 / 边界 / 失败路径）
3. **需求可标准化**性（一次性定制 vs 可沉淀产品能力）
4. **功能边界**是否清楚（什么不做也写出来）
5. **流程闭环**性（含异常回退、对账、补救）
6. **权限/字段/状态/异常**完整性（B 端默认必查）
7. **验收标准**可执行性（能不能给客户演示并签字）
8. **风险**：商业 / 交付 / 技术 / 安全 / 合规 / 团队
9. 是否需要**拆版本**（MVP / V1 / V2 / V3）
10. 是否**适合进入研发**（DoR 满足度）

## 输出格式

```markdown
# 产品评审意见：{{方案名}}

## 1. 总体结论
（通过 / 需修改 / 退回）

## 2. 问题清单

| # | 维度 | 问题 | 严重度 | 修改建议 |
|---|------|------|--------|----------|

## 3. 关键风险
（商业 / 交付 / 技术 / 安全 / 合规）

## 4. 推荐版本拆分
（如果当前方案太大）

## 5. 修改建议（可直接套用的话术 / 段落）

## 6. 优化后版本（如果改动小，直接输出修改后版本）
```

## 红线（任一不达标 → 不通过）

- 没有客户付费理由
- 没有可标准化判断
- 没有验收标准
- 没有异常 / 失败路径
- 角色权限不清楚（B 端）
- 审计/数据隔离缺失（B 端）
