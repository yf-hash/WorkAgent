# /build-vs-buy — Build vs Buy 决策评估

请基于以下输入，使用 Build vs Buy 框架评估：

$ARGUMENTS

## 评估步骤

### 第 1 步：分类

判断这是哪类决策：
- 核心差异化能力（默认偏 Build）
- 基础设施 / 通用能力（默认偏 Buy）
- 合规 / 安全 / 法务（默认偏 Buy）
- 客户专属定制（默认 Customize）
- 战略选项 / 未来杠杆（Build 或 Hybrid）

### 第 2 步：维度打分（1-5）

| 维度 | Build | Buy |
|------|-------|-----|
| 战略价值 | | |
| 时间窗口 | | |
| 总拥有成本（TCO，3 年） | | |
| 控制力 / 灵活性 | | |
| 风险敞口 | | |
| 机会成本 | | |
| 合规 / 安全 | | |

### 第 3 步：TCO 3 年模型

```
Build TCO = 研发人工 + 基础设施 + 机会成本 + 风险溢价
Buy TCO   = 订阅成本 + 集成成本 + 培训成本 + 切换成本 + Vendor 风险溢价
```

### 第 4 步：Vendor 评估（若决定 Buy）

候选 Vendor 按 12 维度评估：产品能力 / 本地化 / 客户基础 / 财务健康 / 路线图对齐 / 集成能力 / 合规 / SLA / 数据归属 / 退出策略 / 价格透明度 / 支持。

### 第 5 步：考虑 Hybrid 模式

- **Buy + Customize**：买平台 + 自研差异化层
- **Buy 临时 + Build 长期**：MVP 用 SaaS，孵化自研
- **Build 核心 + Buy 周边**：核心自研，周边 SaaS

## 红线（不要做）

- ❌ 拍脑袋 "我们能做" 就 Build：低估持续维护成本
- ❌ "开源免费" 就 Buy：忽略集成 / 运维 / 安全审计
- ❌ 只看初期成本：3 年 TCO 才是真账
- ❌ 不考虑机会成本：研发做这件事少做了什么
- ❌ 忽略退出策略：买了下不了贼船
