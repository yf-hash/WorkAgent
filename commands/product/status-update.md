# /status-update — 干系人状态更新

请基于以下输入生成 Status Update：

$ARGUMENTS

## 模式

| 模式 | 用途 | 频次 | 长度 |
|------|------|------|------|
| `weekly`（默认）| 周状态邮件 | 每周五 | ≤ 1 屏 |
| `monthly` | 月度更新 | 每月 1 日 | ≤ 2 屏 |
| `escalation` | 升级备忘录 | 出问题时 | ≤ 1 页 |
| `all-hands` | 全员产品周报 | 每周 | ≤ 1 屏 |

## 通用原则

1. **结论先行**，证据在后 — 30 秒读懂结论
2. **状态码统一**：🟢 On Track / 🟡 At Risk / 🔴 Off Track / ⚪️ Blocked
3. **量化超过形容**："上线了" → "上线了，D+3 注册 +12%"
4. **明确 Ask** — 每篇都要有"需要您做什么"
5. **不超过一屏**

## 输出格式

### Weekly（默认）

```markdown
主题：[产品/项目] 周更 W{周数}：{核心结论一句话}

## TL;DR
{2-3 句话讲完本周最重要}

## 关键指标

| 指标 | 本周 | 上周 | 目标 | 状态 |
|------|------|------|------|------|

## 本周关键进展（≤ 5 条）
- ✅ {完成项 + 量化结果}

## 本周问题与决策
- ⚠️ {风险 + 当前对策 + 是否需要升级}

## 下周计划（≤ 3 件）

## 需要您帮助（Ask）
- {具体 1-2 条 Ask，含截止}
```

### Monthly

```markdown
主题：{产品} {YYYY-MM} 月度更新

## 一、本月 Top 3 成就（含量化）
## 二、关键指标看板（图）
## 三、客户洞察（新 / 流失 / Top 反馈）
## 四、产品发布（本月 / 下月）
## 五、风险与挑战（🔴 / 🟡）
## 六、团队动态
## 七、下月 OKR 进展
## 八、需要管理层支持
```

### Escalation（升级备忘）

```markdown
主题：【升级】{问题简述} — 需要 {决策 / 资源 / 知会}

收件人：{决策人}
抄送：{相关方}

## 一、发生了什么（事实，5 句话内）
## 二、影响（量化 — 客户 / 营收 / 时间）
## 三、根因（初步判断，诚实不甩锅）
## 四、已做的动作
## 五、即将做的（含负责人 + 截止）
## 六、需要决策的事（清晰二选一 + 推荐）
## 七、后续沟通节奏
```

### All-Hands（全员周报）

```markdown
# 产品周报 W{周数}

## 🚀 上线了什么（含短截图）
## 📊 关键指标（三个数字：北极星 / 收入 / 客户数）
## 💬 用户怎么说（含好评 + 批评）
## 🏗️ 正在做什么（进度条 + ETA）
## 🤝 跨团队合作亮点
## 🔜 下周看什么
## ❓ 问产品团队（留邮箱/Slack）
```

## 路由建议

| 场景 | 推荐 |
|------|------|
| 平时周报 | `--mode weekly` |
| 月度老板 / Board 汇报 | `--mode monthly`（或 `/product-report --mode monthly`）|
| 出 P0 / 客户严重投诉 / KR 不达预期 | `--mode escalation` |
| 给全员同步 | `--mode all-hands` |

## 红线

- ❌ 状态吹嘘 / 隐藏风险（长期失去信任）
- ❌ 过度细节（1 页够别写 5 页）
- ❌ 没有 Ask（等于没沟通）
- ❌ 照搬 Jira 状态（那不是给老板看的）
- ❌ 节奏不稳定（临时跳过比内容差更糟）
