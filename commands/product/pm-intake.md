# /pm-intake — 产品需求信息收集

请作为产品经理工作台，围绕以下输入进行需求信息收集和澄清：

$ARGUMENTS

## 你的任务

1. 判断这是市场、需求、PRD、Roadmap、销售材料、发布管理还是其他产品任务。
2. 提取已知信息（用户、场景、问题、约束、来源）。
3. 标注缺失信息（必须澄清才能推进的项）。
4. 给出下一步建议（推荐使用哪个 Skill / Command / Agent）。
5. **如果信息足够，直接输出初步需求分析，不要只提问题**。

## 输出格式

```markdown
# 产品需求 Intake

## 1. 任务类型判断
（市场研究 / 需求澄清 / PRD / Roadmap / 销售 / 发布 / 复盘 / 其他）

## 2. 已知信息
- 客户/角色：
- 场景：
- 问题：
- 来源：
- 约束/截止时间：

## 3. 关键缺口
| 缺口 | 影响 | 谁能回答 |
|---|---|---|

## 4. 初步判断
（是真需求 / 伪需求 / 单一客户 / 共性需求 / 标准化机会 / 一次性项目）

## 5. 建议下一步
| 步骤 | 工具 | 预期交付 |
|---|---|---|

## 6. 可直接推进的输出
（如果信息足够，给出第一版需求分析）
```

## 推荐路由

- 信息已经清晰 → `/prd --mode standard`（C 端）/ `/pm-prd-enterprise`（B 端）
- 想法模糊 → `@prd-coach` 进行多轮对话，或 `/prd --mode diagnose` 三镜诊断
- 跨团队复杂任务 → `@product-director` 评审
- 端到端从想法到方案 → `@product-manager` Agent 编排全流程
