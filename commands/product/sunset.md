加载技能：`skills/strategy/sunset-plan/SKILL.md`

请基于以下要下线的产品 / 功能，制定完整下线计划：

$ARGUMENTS

## 工作流程

### 第 1 步：下线评估

输出："是否应该下线"的判断：

- 流失信号扫描（月活 / 收入 / 维护成本 / 战略偏移 / 合规风险，至少 2 项触发才考虑）
- 利益相关方影响盘点（客户付费 / 客户免费 / 内部团队 / 合作伙伴 / 监管）
- 替代方案分析（自家 / 第三方 / 客户自建）
- 合约 / 法务 / 合规审查
- 财务影响

→ 决策矩阵：Stay / Migrate（迁移到新产品）/ Sunset

### 第 2 步：90/60/30/0 天节奏

| T | 关键动作 |
|---|----------|
| T-90 | 内部沟通先于外部 → 邮件 + 站内 + 客户经理 1:1 → 停止新销售 |
| T-60 | 迁移工具上线 + 文档发布 + Office Hour |
| T-30 | 二次提醒 + 未迁移客户名单 + CSM 主动外呼 + 媒体声明 |
| T-0 | API 返回 410 Gone + UI 公告 + 数据冻结期开始 |
| T+30 | 账号暂停（仍可导出）|
| T+90 | 数据导出截止 |
| T+180 | 数据正式删除 + 删除证明发给客户 |

### 第 3 步：客户沟通模板

至少输出 3 份：
1. T-90 通知邮件（含为什么下线 + 替代方案 + 迁移协助）
2. T-30 二次提醒
3. T-0 正式停服公告

### 第 4 步：内部团队转移

- 工程师明确去向（哪个新项目）
- 文档归档到只读知识库
- 客户数据归档到冷存储（按合规要求保留 N 年）
- T+30 做 Post-Mortem

## 红线（不要做）

- ❌ 静悄悄下线（客户某天发现服务不可用）
- ❌ 甩锅式公告（"因业务调整"）
- ❌ 不提供迁移路径
- ❌ 客户成功 / 销售最后一秒才知道
- ❌ 数据过早删除（合规义务！）
- ❌ 节奏太急（最低 90 天，重大产品 180 天）
