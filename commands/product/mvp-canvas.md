# /mvp-canvas — MVP 设计画布

加载技能：`skills/mvp-canvas/SKILL.md`

## 触发条件
需要定义 MVP 范围、识别最致命假设、选择 MVP 形态、设定验证标准，或避免落入"大爆炸 MVP"陷阱时。

## 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `<产品/功能描述>` | 产品/功能的一句话描述（必填） | — |
| `--mode` | 输出模式 | `canvas` |
| `--budget` | 投入预算等级 | `low` |
| `--timebox` | 验证时长盒 | `2w` |

### 输出模式
| `--mode` | 输出 | 适用场景 |
|----------|------|---------|
| `canvas` | 一页纸 MVP 画布（10 格） | 立项对齐（**默认**） |
| `assumption` | 仅假设清单 + 致命度排序 | 战略验证排序 |
| `type` | MVP 类型推荐 + 选型决策树 | 落地形式选择 |
| `validation` | 验证成功/失败标准 + 退出条件 | 上线前明确退出 |
| `fullset` | 画布 + 假设 + 类型 + 验证全套 | 完整 MVP 立项 |

### 预算等级（--budget）
| 值 | 含义 | 推荐 MVP 类型 |
|----|------|-------------|
| `low` | < 1 周时间 / < 1 万投入 | 落地页 / 解释视频 / 拼凑 |
| `mid` | 2-4 周 / 5-20 万 | 数字原型 / 单功能 / 门童 |
| `high` | 1-3 月 / 20 万+ | 绿野仙踪 / 混凝土 MVP |

### 时长盒（--timebox）
| 值 | 含义 |
|----|------|
| `1w` | 1 周冲刺验证 |
| `2w` | 2 周（**默认**） |
| `4w` | 4 周（标准） |
| `8w` | 8 周（最长不建议超过） |

## 执行流程

```
Step 1: 想法描述澄清
  → 一句话价值主张是什么？
  → 目标用户是谁？
  → 当前最不确定的事情是什么？

Step 2: 假设盘点
  → 列出价值/增长/商业/可行 4 类假设
  → 每个假设打 3 分：商业影响 / 不确定度 / 验证成本
  → 计算致命度，识别 RAT（最致命假设）

Step 3: MVP 类型推荐
  → 基于预算 + 时长 + 假设类型，推荐 1-3 种 MVP 形态
  → 给出选型理由和潜在陷阱

Step 4: MVP 范围圈定
  → 包含的能力（5 项以内，对应 RAT 验证）
  → 明确排除的能力（防止 Scope Creep）
  → 早期用户来源 + 触达方式

Step 5: 验证退出标准
  → 成功条件：[指标 ≥ 数值]
  → 失败条件：[指标 < 数值]
  → 时间盒到期决策树

Step 6: 风险预案 + 伪 MVP 反模式自检
  → 是否避免了大爆炸/完美主义/PoC 当 MVP 等陷阱
  → 如何在 [timebox] 内交付
```

## 输出示例（canvas 模式）

```
┌─────────────────────────────────────────────────────────────┐
│ MVP CANVAS: [产品名]                                          │
├─────────────────────────────────────────────────────────────┤
│ 1. 最致命假设                                                │
│    "如果【XXX】不成立，整个想法都站不住脚"                     │
├──────────────────────────┬───────────────────────────────────┤
│ 2. 成功定义               │ 3. 失败定义                       │
│    [主要指标 ≥ 数值]       │    [主要指标 < 数值]              │
├──────────────────────────┴───────────────────────────────────┤
│ 4. MVP 类型 + 一句话描述                                       │
│    [推荐类型]: [描述]                                         │
├─────────────────────────────────────────────────────────────┤
│ 5. 包含的能力           │ 6. 明确不做                          │
│    ✅ ...               │    ❌ ...                           │
├─────────────────────────┼───────────────────────────────────┤
│ 7. 用户来源             │ 8. 验证时长                         │
│    [渠道]               │    [timebox]                       │
├─────────────────────────────────────────────────────────────┤
│ 9. 风险与应对                                                │
│    - [风险] → [应对]                                         │
└─────────────────────────────────────────────────────────────┘

🚦 验证后决策：
  ✅ 达成成功条件 → Persevere（继续 MLP/正式产品）
  ❌ 触发失败条件 → Pivot 或 Stop
  ⚠️ 时间到期未明确 → 延长 1 个 timebox 或召开复盘
```

## 与其他命令的协同

```
/mvp-canvas（本命令）
  ├── /product-strategy → 假设来自 Lean Canvas
  ├── /user-research    → 验证假设的访谈方案
  ├── /user-story-mapping → Walking Skeleton = MVP 范围
  ├── /ab-test          → MVP 上线后 A/B 验证
  ├── /pmf-survey       → 验证后判断 PMF
  └── /growth-experiment → MVP 之后的增长循环

推荐工作流：
  早期想法：
    /product-strategy --mode lean
    → /mvp-canvas --mode fullset --budget low --timebox 2w
    → 上线 MVP → 收集数据
    → /pmf-survey（达到验证标准后）
```

## 使用示例

```bash
# 一页纸 MVP 画布（默认）
/mvp-canvas AI 写作助手浏览器插件

# 仅识别最致命假设
/mvp-canvas 跨境电商选品 SaaS --mode assumption

# MVP 类型选型
/mvp-canvas 智能客服平台 --mode type --budget mid --timebox 4w

# 验证标准定义
/mvp-canvas 团队协作工具 --mode validation

# 完整立项画布（低预算 1 周）
/mvp-canvas 工程师面试题刷题工具 --mode fullset --budget low --timebox 1w

# 中等投入 4 周验证
/mvp-canvas B2B 数据分析平台 --mode fullset --budget mid --timebox 4w
```
