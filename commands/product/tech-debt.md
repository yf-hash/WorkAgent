$ARGUMENTS

## 工作流程

### 第 1 步：技术债分类（7 类）

1. 架构债（系统设计不当）
2. 代码债（实现质量低）
3. 测试债（覆盖不足）
4. 文档债（缺失 / 过期）
5. 基础设施债（部署 / 监控落后）
6. 安全债（已知漏洞未修）
7. 数据债（模型 / 质量问题）

### 第 2 步：影响打分（每条债务）

| 维度 | 业务量化（必填）|
|------|----------------|
| 速度影响 | "新增相关功能 6 周 → 还本后 3 周" |
| 风险影响 | "近 3 月已发 2 次 P1，影响 X 客户" |
| 成本影响 | "每月多支付 N 万云费用" |

> 没量化的债 → 永远排不上优先级。

### 第 3 步：WSJF 优先级

```
WSJF = (业务价值 + 时间紧迫度 + 风险 + 机会成本) / Job Size
```

WSJF 高的先还。

### 第 4 步：容量分配（20% 规则）

| 比例 | 用途 |
|------|------|
| 60-70% | 新功能 |
| 10-20% | **技术债 + 基础设施投资** |
| 10-15% | Bug 修复 |
| 5-10% | Spike / 探索 |

### 第 5 步：SLO 守门

| SLO | 阈值 | 违反时 |
|-----|------|--------|
| 可用性 | < 99.5% | 暂停新功能 |
| P95 延迟 | > 500ms | 性能投资 |
| 测试覆盖 | < 60% | 补测试再上 |
| 部署频率 | < 1次/周 | 投资 CI/CD |
| MTTR | > 1 小时 | 投资监控 |

## 红线（不要做）

- ❌ 工程自己决定，PM 不参与（业务方向脱节）
- ❌ PM 一刀切不让做（复利积累 → 1 年后全员瘫痪）
- ❌ 没量化（永远排不上）
- ❌ 没 SLO 守门（等到 P0 才补，代价 10×）
- ❌ "今年做完技术债再做新功能"（永远做不完）
- ❌ PM 不懂工程全权交 EM（失去业务视角）
