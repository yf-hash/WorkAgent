# /pm-tech-spec — 产品技术指标 & 规格书 Agent（Module 6）

> **端到端 6 模块流水线的第 5 站** — 本工具集的核心差异化能力
>
> /pm-clarify → /pm-solution → /pm-prototype → /prd →【本命令】→ /pm-archive

## 一句话

**很多 PM 只会写业务 PRD，不会梳理技术指标 —— 本命令自动从 PRD + 澄清报告出发，输出一份可交付给研发/合规/客户的《产品技术规格书》**，含六大类指标（性能/安全/兼容/可靠/合规/依赖）+ 三项自动校验。

## 关键区别：产品技术指标 vs 系统技术方案

| | 产品技术指标（本命令产出） | 系统技术方案（研发产出） |
|---|---|---|
| 视角 | 产品对外要满足的规格 | 内部如何实现 |
| 举例 | "验证码 6 位数字、5-10 分钟有效" | "Redis 存 code，TTL 300-600s，key = phone:xxx" |
| 受众 | 客户、销售、售前、合规、研发 | 研发内部 |
| 用途 | PoC 验证、招投标、合规审计 | 系统设计文档、CR 依据 |

## 输入

```bash
# 最简
/pm-tech-spec ./output/pm-pipeline/xxx/04-PRD.md

# 引用上游流水线全套产物（推荐）
/pm-tech-spec ./04-PRD.md --input ./01-clarify-report.md,./02-business-solution.md,./03-prototype/03-prototype.json

# 指定产品类型（影响合规默认项）
/pm-tech-spec ./04-PRD.md --product-type saas-b
```

## 内部三个子 Agent

### Agent 6-1：产品技术指标梳理

**输入**：PRD + 澄清报告 + 业务方案

**输出**：**结构化指标清单**（表格形式），分六大类：

#### 1. 性能指标
- 接口响应时间（P50 / P95 / P99）
- 并发上限（同时在线用户数、峰值 QPS）
- 支持的数据量级（单表行数、单请求大小、批量上限）
- 首屏加载 / LCP / FID
- 报表 / 导出的生成时间

#### 2. 安全指标
- 认证方式（密码复杂度、MFA、SSO 协议）
- 授权粒度（RBAC / ABAC 层级）
- 会话超时（Idle / Absolute）
- 密码 / 密钥策略（加密算法、轮换周期）
- 防刷 / 防爬（频次限制、IP 拉黑）
- 敏感数据处理（脱敏、加密存储、不落日志）
- 审计日志（保留期、字段、可查询窗口）
- 验证码策略（长度 / 有效期 / 单账户频次 / 全站频次）

#### 3. 兼容性指标
- 浏览器（Chrome / Firefox / Safari / Edge 版本下限）
- 移动端（iOS / Android 系统版本、屏幕尺寸）
- 桌面客户端版本（Win / Mac / Linux）
- 数据格式兼容（Excel 版本、CSV 编码、JSON schema 兼容）
- API 版本策略（向后兼容多久）

#### 4. 可靠性指标
- 可用性（99.5% / 99.9% / 99.99%）
- 故障恢复（RTO / RPO）
- 失败重试策略（次数、指数回退）
- 幂等性保证（写操作、消息消费）
- 数据备份（周期、跨区、加密）
- 灾备演练频率

#### 5. 合规指标
- 数据留存期（业务数据 / 日志 / 备份）
- 隐私要求（PII 定义、脱敏、删除权）
- 跨境传输规则
- 行业合规（等保 / SOC2 / ISO27001 / GDPR / HIPAA / 个保法）
- 数据主权 / 本地化
- 未成年人保护 / 内容审核

#### 6. 外部依赖指标
- 第三方接口 SLA / QPS 上限
- 错误容忍策略（重试 / 降级 / 兜底）
- 单价 & 用量预算
- 供应商锁定风险
- 数据字段稳定性

### Agent 6-2：技术规格书生成

将上面结构化指标清单生成完整《产品技术规格书》文档，标准章节：

1. **概述**（产品定位、版本、目标读者）
2. **适用范围**（业务模块、部署环境、用户角色）
3. **业务上下文**（一句话业务目标 + 主流程简图）
4. **产品技术指标总表**（跨六类的汇总，含指标名、目标值、验证方法）
5. **各模块详细规格**（按业务模块拆分）
6. **边界与降级策略**（每类失败的兜底）
7. **上线验收标准**（每个指标的可测试断言）
8. **外部依赖说明**（清单 + SLA + 替换方案）
9. **风险与约束**（技术天花板、合规风险）
10. **变更管理**（谁能改指标、走什么流程）

### Agent 6-3：规格书自动校验

调用 `skills/pm/pm-tech-spec-validate` 跑三项校验：

#### 校验 1：指标可量化
扫描所有指标，识别模糊表述（同 PRD 校验的歧义规则库，但更严）：
- "接口要快" → 必须改为具体数字
- "支持并发" → 必须给上限
- "数据保留合适时长" → 必须给天数
- "兼容主流浏览器" → 必须列版本

#### 校验 2：PRD - 规格书一致性
逐条对比：
- PRD 提到的所有异常场景在规格书都有降级策略
- PRD 提到的所有集成在依赖清单里
- PRD 的性能预期与规格书数字对得上
- PRD 的合规要求全部落地到指标

#### 校验 3：验收标准完整性
每个指标必须有：
- [ ] 具体目标值（数字或枚举）
- [ ] 验证方法（压测 / 扫码 / 审计 / 三方证明）
- [ ] 触发验证时机（上线前 / 每周 / 季度）
- [ ] 未达标的处理（阻断上线 / 降级 / 告警）

## Harness 卡点

- **指标出稿后**：AskUserQuestion 展示总指标数和高严重度指标，确认后再生成规格书
- **校验后**：如果有 🔴 项，强制暂停要求 PM 决策：
  - PM 补充数字后重跑
  - 记入 assumptions 直接归档
  - 回到 M5 修改 PRD

## 与其他命令的边界

| 场景 | 用 |
|---|---|
| **PRD + 澄清 → 产品技术规格书** | 本命令 |
| 招投标响应中的技术条款 | 本命令产出直接引用 |
| 合规审计准备 | 本命令产出 → 合规团队 |
| PoC 验收标准 | 本命令产出 § 7 上线验收标准 |
| 非功能需求初稿（放在 PRD 里） | `/prd --mode full`（简版） |
| 需要一键跑完整 6 模块流水线 | `/pm-pipeline` |

## 反模式

- ❌ 指标全是"合理" / "适度" / "尽量"——违规，必须给数字
- ❌ 没有验收方法——违规，规格书就是验收依据
- ❌ 依赖没写 SLA / 单价——违规，商业决策依据缺失
- ❌ 缺少合规指标（B 端）——违规，售前会被卡
- ❌ 直接跳过本命令用 PRD 卖标书——违规，会被专业客户识破
