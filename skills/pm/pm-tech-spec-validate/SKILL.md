# pm-tech-spec-validate — 技术规格书校验工具箱

> 本 skill 被 `/pm-tech-spec` 命令的 Agent 6-3 调用。

## 一、指标可量化校验规则

### 强制"给数字"的字段
每个指标的**目标值**列不能是以下类型：

**❌ 违规词表**：
```
快 / 慢 / 好 / 差 / 高 / 低（无对比基准）
适当 / 合理 / 合适 / 适度 / 平衡
大量 / 少量 / 多个 / 若干
主流 / 常见 / 大部分 / 常用
尽可能 / 尽量 / 争取
稳定 / 流畅 / 顺滑 / 智能
```

**✅ 合规格式**：
```
数值 + 单位（500ms / 10w rows / 99.9%）
枚举列表（Chrome 最近 2 版本 / SAML 2.0 + OIDC）
范围（5-10min / 8-32 字符）
布尔（是 / 否，含前置条件）
```

### 扫描输出格式
```
【可量化 P1】"接口响应要快"（§ 4. 性能指标 - P1）
  问题："快" 是模糊程度词
  建议改写：接口响应 P95 ≤ 500ms（1000 并发下压测）
```

### 常见错误映射
| 错误表述 | 建议改写 |
|---|---|
| "支持大规模" | 支持 X 万用户同时在线 |
| "响应快" | P95 ≤ Xms |
| "数据不丢失" | RPO ≤ Xmin |
| "系统稳定" | 可用性 ≥ 99.X% |
| "兼容主流浏览器" | Chrome/Firefox/Safari/Edge 最近 2 版本 |
| "日志保留合适时长" | 90 天（业务）/ 180 天（安全） |
| "密码强度高" | 8-32 字符，含大写+数字+特殊 |
| "支持常见格式" | 明确列出格式清单 |
| "灵活配置" | 明确可配置字段 + 配置权限 |
| "智能识别" | 明确用什么模型 / 规则，准确率 X% |

## 二、PRD - 规格书一致性映射规则

### 逐条映射检查

#### 从 PRD 的每个功能 → 规格书必须响应的指标
| PRD 中出现 | 规格书必须有 |
|---|---|
| "支持批量导入" | § 性能：批量上限；§ 可靠性：断点续传/重试；§ 兼容：Excel/CSV 版本 |
| "发送邮件通知" | § 依赖：邮件供应商 SLA；§ 可靠性：到达率 & 兜底 |
| "AI 生成 XX" | § 依赖：AI 供应商 & 单价；§ 性能：延迟；§ 安全：内容审核 |
| "用户可以登录" | § 安全：密码策略 & 会话策略；§ 兼容：SSO 协议 |
| "生成月度报表" | § 性能：生成时长；§ 可靠性：定时任务重试 |
| "支持多租户" | § 安全：数据隔离；§ 可靠性：租户级备份 |
| "接入企微/飞书" | § 依赖：IM 平台 SLA；§ 安全：OAuth 授权 |

#### PRD 提到的每个异常场景 → 规格书必须有降级
| PRD 异常 | 规格书 § 边界与降级 |
|---|---|
| "邮件发送失败" | 短信兜底 / 站内信兜底 / 用户提示 |
| "AI 响应超时" | 缓存复用 / 模板化响应 / 降级到小模型 |
| "数据校验失败" | 拒绝写入 + 详细错误报告 |
| "并发冲突" | 乐观锁 + 冲突提示 UI |
| "三方 API 429" | 退避重试 + 队列削峰 |

#### PRD 的性能预期 → 规格书具体数字
如果 PRD 说 "3 秒内返回结果" → 规格书必须写 P95 ≤ 3s（不能更宽松）。

### 冲突输出格式
```
【一致性 T1】
  PRD § 3.2 批量导入："10 万行 5 分钟内完成"
  规格书 § P2："10 万行 30 分钟"
  影响：客户预期 vs 实际能力落差 6 倍
  建议：以 PRD 为准（改规格书数字），或回 PRD 修正预期
```

## 三、验收标准完整性 checklist

### 每个指标的验收标准四要素
| 要素 | 必答问题 |
|---|---|
| 目标值 | 数字是多少？（不能是描述） |
| 验证方法 | 怎么测？（压测 / 单元测试 / 合规审计 / 三方证明） |
| 验证时机 | 什么时候测？（上线前 / 每次 CI / 季度） |
| 未通过处理 | 不达标怎么办？（阻断上线 / 记 backlog / 告警） |

### 六大类别的默认验收方法

| 类别 | 常用验证方法 | 常用时机 |
|---|---|---|
| 性能 | 压测（JMeter/k6）、性能测试 | 上线前 |
| 安全 | 单元测试、渗透测试、代码审计 | CI / 季度 |
| 兼容性 | 兼容测试矩阵（BrowserStack） | 上线前 |
| 可靠性 | 灾备演练、混沌工程 | 季度 |
| 合规 | 合规审计、三方证明 | 年度 |
| 依赖 | 供应商 SLA 合同、监控 | 持续 |

### 缺失输出格式
```
【验收 P1】"接口响应 P95 ≤ 500ms"（§ 4. 性能）
  缺失：
    - 未指定测试并发数（500 / 1000 / 5000？）
    - 未指定验证工具（JMeter？k6？）
    - 未指定未通过处理（阻断上线？）
  建议补充：
    验证方法：JMeter 1000 并发压测 15 分钟
    验证时机：每次上线前必跑
    未通过处理：阻断上线，回滚到上一版本
```

## 四、B 端 / C 端合规必查项

### B 端 SaaS 私有化 / 政企场景
- [ ] 等保 2.0 三级（政企必须）
- [ ] 数据本地化（大陆客户）
- [ ] 审计日志保留 ≥ 180 天
- [ ] 支持国密算法（可选，视客户）
- [ ] 支持信创（可选，视客户）

### C 端全国范围
- [ ] 个保法：告知、单独同意、删除权
- [ ] 内容审核（用户生成内容）
- [ ] 未成年保护（有 < 18 岁用户）
- [ ] 数据备案（工信部）

### 跨境
- [ ] 数据出境评估（PIPL 55 条）
- [ ] GDPR（欧盟客户）
- [ ] CCPA（加州客户）

## 六、通过标准

| 类别 | 通过标准 |
|---|---|
| 指标可量化 | 零违规词 |
| PRD 一致性 | 零冲突（有 --input 时） |
| 验收标准 | 每个 🔴 高严重度指标四要素齐全 |

三项全通过 → **总体：通过**
任一有 🔴 → **总体：需重写**
其他 → **总体：有修改建议**
