# Demo Design — Demo 设计与沙盘演练知识库

> Demo 是售前最高密度的展示窗口（30 分钟决定客户对产品的核心印象）。
> 区别于 `marketing-copy --type demo`（写脚本）：本 Skill 关注**怎么设计、怎么演练、怎么应对意外**。
> 区别于 `sales-guide-writer`（销售话术总集）：本 Skill 专注 Demo 这一具体场景。

---

## 一、Demo 三段式黄金结构

### 1.1 标准 30 分钟 Demo

```
0-5 分钟｜场景对齐（不打开产品）
  - 复述客户痛点（来自 discovery-call 输出）
  - 引入一个客户能共鸣的真实场景
  - 用客户自己的话讲（从纪要中引用）
  - 目的：让客户从一开始就觉得"我们懂他"

5-22 分钟｜价值演示（围绕 3 个客户痛点，不是 Feature 列表）
  - 痛点 1：[客户原话] → 操作演示 → 量化结果
  - 痛点 2：同上结构
  - 痛点 3：同上结构
  - 每个痛点 5-7 分钟，不超过 3 个

22-27 分钟｜客户化深谈（关键差异化）
  - 演示 1 个客户特殊场景（提前准备）
  - 客户化数据 / 客户行业术语
  - 接受现场提问

27-30 分钟｜Next Step（不留作业）
  - 总结 3 大价值
  - 邀请下一步行动（PoC / 二访 / 商务会议）
  - 留物料（Demo 录屏 / 资料包 / 同行案例）
```

### 1.2 反模式（要避免）

```
❌ Feature Tour（"这是登录页 / 这是仪表盘 / 这是设置"）
   → 客户立刻走神
❌ 60 分钟一气呵成不互动
   → 客户记忆点为零
❌ 用产品默认 demo 数据
   → 客户感觉"通用产品"
❌ 没有结尾 / 结尾是"任何问题都可以问"
   → 客户没有具体下一步
```

## 二、Demo 类型与场景

| Demo 类型 | 场景 | 准备时长 | 核心要点 |
|----------|------|---------|---------|
| **标准 Demo** | 销售初步接触 | 通用 | 8-10 分钟版本（Discovery 后用）|
| **客户化 Demo** | 关键客户深谈 | 1-3 天 | 客户行业 + 客户场景 + 客户数据 |
| **同行案例 Demo** | 客户犹豫 / 找参考 | 0.5 天 | 同规模 / 同行业客户的真实使用录屏 |
| **Demo Day** | 多客户路演（如行业大会）| 1-2 天 | 5-10 分钟极简版 + 强情感 |
| **PoC Demo** | PoC 中期 review | PoC 周期 | 用客户真实数据 + 量化 Phase 1 结果 |

## 三、客户化故事线设计

### 3.1 故事线四件套
```
1. 客户业务场景（让客户进入剧情）
   - 30 秒复述：客户每天 / 每周做什么
   - 用客户视角、客户术语
   - 引用客户原话："上次您提到……"

2. 痛点剧情（戳到客户）
   - 一个具体场景：当 [触发条件] 时，您的团队 [当前怎么做]
   - 量化代价：花费 [N] 小时 / 损失 [M] 万 / 错过 [机会]
   - 业务后果：导致 [更大的业务问题]

3. 解决路径（演示阶段）
   - 我方产品如何介入这个场景
   - 不讲功能名，讲"做了什么动作 → 解决了什么"
   - 关键点：每个动作 ≤ 90 秒展示

4. 量化成果（数据落地）
   - 与剧情开头的"代价"对比
   - 给出具体数字（来自同行案例）
   - 引出下一步对话："您觉得这个改善对您团队意味着什么？"
```

### 3.2 故事线生成模板

```
客户：[客户公司]
行业：[行业]
角色（演示对象）：[角色 + 关心什么]

场景剧情（30 秒开场）：
  "[客户角色] 王总，过去半年您团队的 [日常工作] 大概是这样：
   [描述具体场景]。每周大概要花 [N] 小时在 [低价值任务] 上，
   而真正能 [高价值动作] 的时间不到 [M] 小时。"

痛点剧情（90 秒切入）：
  "上次您提到……（引用客户原话）。这个场景我们见过很多类似的，
   比如 [同行客户] 之前每天 [具体痛点]，导致 [业务后果]。"

解决路径（核心演示，10-15 分钟）：
  动作 1：[在产品中做什么] → [发生什么] → [对应的业务效果]
  动作 2：同上
  动作 3：同上

量化成果（90 秒收尾）：
  "[同行客户] 用这套流程后：
   - [指标 1] 从 X 改善到 Y（提升 Z%）
   - [指标 2] 同上
   - [指标 3] 同上
   团队从 [低价值任务] 解放出来，开始做 [高价值动作]。"
```

## 四、Demo 数据集准备

### 4.1 三套数据集（必备）

```
1. 行业脱敏数据（标准 Demo 用）
   - 来源：从公开数据 + 我方过往项目脱敏
   - 数量：足够覆盖核心演示场景
   - 风险点：如果客户问"这是真实数据吗"，诚实回答"行业典型样本"

2. 客户化数据（重要客户专用）
   - 来源：客户提供 / 客户公开数据
   - 准备时间：1-3 天
   - 价值：客户感受到"为我准备"

3. 异常场景数据（防御性准备）
   - 边界值 / 极大量 / 极小量 / 错误格式
   - 演示时不主动触发，但客户问到时可演
```

### 4.2 数据集准备清单

```
□ 演示场景所需数据全覆盖
□ 数据脱敏（无客户隐私 / 商业机密）
□ 数据量级合理（不要 100 万条让客户等加载）
□ 中文数据已本地化（避免英文姓名 / 美元单位）
□ 异常场景有兜底（崩溃保护 / 网络断开恢复 / 慢查询）
□ 数据日期"未过期"（不要演示昨天的数据让客户觉得产品不更新）
```

### 4.3 客户化技巧

```
低成本客户化（1-2 小时）：
  - 修改菜单 / Logo / 公司名（界面层）
  - 把示例数据中的"张三"改成客户行业术语
  - 把示例图表标题改成客户业务关键词

中成本客户化（半天）：
  - 准备客户行业的典型业务流程
  - 演示数据用客户行业术语命名
  - 增加 3-5 个客户行业关键场景

高成本客户化（1-3 天）：
  - 用客户提供的样本数据
  - 与客户现有系统做演示集成
  - 模拟客户实际工作流
```

## 五、Demo 异常应对剧本

### 5.1 常见异常 5 类

| 异常 | 概率 | 应对剧本 |
|------|------|---------|
| **崩溃 / 报错** | 中 | "这个我们后台有专门的运维监控，正常使用不会出现。我先切换到 [备用环境] 继续。" |
| **加载缓慢** | 高 | 不要等！立即切换："正在演示的是真实生产规模数据。我们看下结果……（直接打开下一步预加载页面）" |
| **网络断开** | 中 | 切换离线 Demo 录屏："网络好像有点问题，我们看一段提前录的同样场景，效果完全一致。" |
| **客户提问超出 Demo 范围** | 高 | "好问题。这个场景我让 [产品 PM 名字] 在 PoC 阶段为您专门设计。今天我们先看核心场景。" |
| **演示效果不达预期** | 中 | 立即解释："今天演示的是产品默认配置。在 PoC 阶段，我们会针对您的业务调优，效果会更好。我可以让您看一份调优后的同行案例数据。" |

### 5.2 演练 SOP

```
关键 Demo 必须演练 ≥3 遍：
  第 1 遍：自己跑通（脚本 + 操作）
  第 2 遍：内部同事旁观，记录卡点
  第 3 遍：模拟客户提问（找最难搞的人扮演客户）

关键检查点：
  □ 全程不超过承诺时长（30 分钟就 30 分钟）
  □ 每段衔接自然（不要"那我们看下一个"）
  □ 数字记得（不要现场翻 PPT 找数据）
  □ 异常应对剧本能背出来
```

## 六、Demo 反对意见库（5 类常见）

### 6.1 五类反对意见 + 标准应答

```
反对 1：「这看起来很复杂 / 学习成本很高」
应答：
  "[客户角色] 看到的是完整功能。实际您团队 80% 时间用的是
   主页这 3 个动作。新员工平均 1 周上手，比 [对手] 快一半。
   我们 [同行案例] 在 30 天内全员熟练。"

反对 2：「我们已经用 [对手] / 自建了，迁移成本很高」
应答：
  "理解。迁移成本主要是 [3 类]。我们的迁移方案：[方法]。
   类似客户 [同行] 从 [对手] 迁过来用了 [N] 周，零数据丢失。
   我可以让您和他们的负责人聊聊。"

反对 3：「价格比预算高」
应答：
  "我先问下您的预期范围……（让客户先报）
   我们 ROI 测算 [Payback X 个月] 是基于您实际场景。
   如果价格是关键卡点，我们有 [三档方案]，
   还有 [Phase 1 试点] 可以先小规模验证。"

反对 4：「我们决策慢，要走流程」
应答：
  "理解。让我帮您把这件事推进得更顺：
   我会给您准备一份 [Business Case 一页纸] 给您领导汇报，
   再给一份 [技术方案] 给 IT 团队评估。
   您看下个月的 [关键节点] 我们怎么配合最合适？"

反对 5：「这个功能我看 [对手] 也有」
应答：
  "[对手] 是这个领域的成熟玩家，您看到的功能确实他们也有。
   差异在于 [具体维度 + 量化]。
   如果您 [关心的维度]，我们和 [对手] 谁更合适，
   PoC 里能直接对比验证。"
```

## 七、技术 Demo vs 商务 Demo

| 维度 | 商务 Demo | 技术 Demo |
|------|----------|----------|
| 受众 | EB / 业务负责人 | TB / 工程师 |
| 时长 | 20-30 分钟 | 60-90 分钟 |
| 内容 | 业务场景 + 价值 + ROI | 架构 + API + 集成 + 部署 |
| 演示重点 | "解决了什么业务问题" | "怎么实现 / 性能 / 扩展性" |
| 数据使用 | 业务结果数据 | 性能数据 / 日志 / Trace |
| 互动方式 | 业务讨论 | 技术深度问答 |
| 关键 Hook | 客户行业故事 | 架构图 + 第一行代码 |

## 八、Demo 后续跟进物料

Demo 结束 24 小时内必须发的：

```
1. Demo 录屏（≤30 分钟，剪辑过的精华版）
2. Demo 中提到的客户案例 PPT
3. 客户问到但 Demo 中没演的问题答复
4. Business Case 一页纸（如客户问到 ROI）
5. 下一步约定（PoC / 二访 / 商务会议时间）
```

## 九、Demo 评分自检（演练后必跑）

```
节奏（30 分）：
  □ 0-5 分钟有客户场景共鸣点（10 分）
  □ 5-22 分钟分 3 段，每段不超 7 分钟（10 分）
  □ 22-30 分钟有 Next Step（10 分）

情感曲线（30 分）：
  □ 痛点剧情让客户点头 / 共鸣（10 分）
  □ 演示中至少 2 次"哦原来还能这样"的惊喜（10 分）
  □ 收尾给客户行动的勇气而非作业（10 分）

信息密度（30 分）：
  □ 每段都有客户行业关键词（10 分）
  □ 至少 5 个量化数字（10 分）
  □ 至少 1 个同行案例（10 分）

防御性（10 分）：
  □ 异常应对剧本演练通过（5 分）
  □ 客户高难度反对意见有应答（5 分）

合格线：80 分
优秀线：90 分
```

## 十、与其他 Skill 的边界

| 选择 | 用前者 | 用后者 |
|------|-------|-------|
| `demo-design` vs `marketing-copy --type demo` | Demo 设计与演练方法论 | Demo 脚本撰写 |
| `demo-design` vs `sales-guide-writer` | Demo 这一具体场景 | 销售一页禅（产品总体）|
| `demo-design` vs `discovery-call` | 第 3+ 次会议（产品演示）| 第 1-2 次会议（需求挖掘）|
| `demo-design` vs `poc-plan` | 30-90 分钟现场演示 | 4-12 周完整 PoC |
