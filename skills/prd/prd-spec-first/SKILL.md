# Prd Spec-First — 规格优先工作流

> 单一职责：生成 Spec-First 四件套（proposal / specs / design / tasks）。
> 不做：传统 PRD（→ `prd-standard`）、一页纸（→ `prd-lite`）、含线框图（→ `prd-proto`）

> 核心理念：**AI / 研发写代码之前，先让人与 AI 对齐规格**（灵感来源 OpenSpec）

## 四件套工作流

```
一句话想法
    ↓
proposal.md ── 为什么做？改什么？不做什么？        [立项对齐]
    ↓
specs/      ── 具体要发生什么？（用户视角）          [研发交付]
    ↓
design.md   ── 长什么样？怎么交互？（UI 视角）       [设计对接]
    ↓
tasks.md    ── 谁来做？做什么？先做什么？（研发视角） [Sprint 规划]
```

## Proposal 模板（立项对齐）

```markdown
# [功能名] — 提案

**日期**：YYYY-MM-DD
**提案人**：[姓名]
**状态**：草稿 / 讨论中 / 已批准 / 已拒绝

---

## 背景与问题

[1-3 句话描述现状和问题，必须附关键数据]

**关键数据**：
- [数据点 1，如：当前新用户 7 日留存率仅 18%]（来源：[数据来源]）

**用户反馈**：
> "[典型用户反馈原话]" — [渠道：用户访谈/工单/NPS 评论]

---

## 我们要做什么

[一句话描述解决方案]

**核心改变**：
1. [改变 1]
2. [改变 2]
3. [改变 3]

---

## 成功标准

| 指标 | 当前值 | 目标值 | 时间范围 | 类型 |
|------|--------|--------|---------|------|
| [主指标] | — | — | 发布后 30 天 | 提升 |
| [护栏指标] | — | ≥ 当前值 | 持续监控 | 不退化 |

---

## 不在范围（明确不做）

- **[排除项 1]**：原因：[简短说明]
- **[排除项 2]**：原因：[简短说明]

---

## 开放问题

- [ ] [待决策问题 1]（截止：[日期]，决策人：[姓名]）
- [ ] [待决策问题 2]
```

## Specs 模板（研发交付）

```markdown
# [功能名] — 功能规格

**关联提案**：proposal.md
**版本**：v1.0 | **状态**：草稿 / 评审中 / 已确认

---

## 用户角色定义

| 角色 | 描述 | 典型场景 |
|------|------|---------|
| [角色 1] | [描述] | [核心使用场景] |

---

## 用户故事

### US-01：[故事名称]

**As a** [用户角色],
**I want to** [行为/目标],
**So that** [价值/原因].

**优先级**：P0 / P1 / P2
**估时**：[工程师工作量，如 3 天]

#### 验收标准

| # | Given（前置条件） | When（触发操作） | Then（期望结果） |
|---|-----------------|----------------|----------------|
| AC-01 | [正常条件] | [用户操作] | [系统响应] |
| AC-02（异常）| [异常条件] | [用户操作] | [错误处理方式] |
| AC-03（边界）| [边界条件] | [用户操作] | [边界处理方式] |

#### 边界条件

- **最大限制**：[如输入框最多 200 字符]
- **并发处理**：[如同时多人编辑时的锁定机制]
- **空状态**：[列表为空时的展示策略]
- **权限限制**：[不同角色的访问/操作权限差异]
- **网络异常**：[断网/超时的降级处理]

---

## 数据模型

| 字段名 | 类型 | 必填 | 验证规则 | 说明 |
|--------|------|------|---------|------|
| [字段] | String / Int / Boolean | 是/否 | [规则，如最长 50 字] | [说明] |

---

## 非功能需求

- **性能**：[如接口 P95 响应时间 < 500ms]
- **安全**：[如敏感字段脱敏展示]
- **兼容性**：[如 Chrome 90+, Safari 14+, 移动端 iOS 15+]
- **可访问性**：[WCAG 2.1 AA 级]
```

## Tasks 模板（Sprint 规划）

```markdown
# [功能名] — 实施任务清单

**Sprint**：[编号]
**目标发布日**：YYYY-MM-DD
**关联文档**：[proposal.md] | [specs/] | [design.md]

---

## P0 核心任务（阻塞发布）

### 🔧 后端
- [ ] **[任务名]**（预估：[N 天]，负责人：[工程师]）
  - [ ] 设计数据库表结构
  - [ ] 实现 CRUD 接口
  - [ ] 编写单元测试（覆盖率 ≥ 80%）
  - 依赖：[依赖项]

### 🎨 前端
- [ ] **[任务名]**（预估：[N 天]，负责人：[工程师]）
  - [ ] 实现页面组件（默认态/空态/加载态/错误态）
  - [ ] 对接后端接口
  - [ ] 响应式适配（移动端/桌面端）
  - [ ] 埋点接入

### 🧪 测试
- [ ] **编写测试用例**（预估：[N 天]，负责人：[QA]）
  - [ ] 覆盖所有验收标准（AC-01 至 AC-XX）
  - [ ] 边界条件测试
  - [ ] 性能测试

---

## P1 优化任务（重要但非阻塞）

- [ ] [任务]（预估：[N 天]，说明：[为什么是 P1]）

---

## P2 后续迭代（本期不做）

- [ ] [功能点]（延后原因：[说明]，预计时间：[时间]）

---

## 埋点需求

| 事件名 | 触发时机 | 参数 |
|--------|---------|------|
| [event_name] | [用户操作/页面加载] | { [key]: [value], ... } |

---

## 发布检查清单

- [ ] 所有 P0 任务已完成
- [ ] 所有验收标准已通过测试
- [ ] 埋点数据已验证（测试环境抓包确认）
- [ ] 性能指标达标（P95 接口 < 500ms，页面 LCP < 2.5s）
- [ ] 灰度方案已确认（建议先 10% → 50% → 100%）
- [ ] 回滚方案已确认（Feature Flag / 版本回退流程）
- [ ] 监控告警已配置（错误率 / 成功率 / 响应时间）
- [ ] 上线文案已准备（Changelog / 用户通知）
```

## 阶段质量门控

```
Proposal → Specs 入场条件：
✅ 问题描述有数据/用户反馈支撑
✅ 成功标准可量化（有具体数值）
✅ 排除项已明确（写出"不做什么"）
✅ 关键假设和开放问题已识别

Specs → Design 入场条件：
✅ 所有主路径（P0 用户故事）有完整验收标准
✅ 异常场景和边界条件已覆盖
✅ 数据模型和字段约束已定义
✅ 权限边界已明确

Design → Tasks 入场条件：
✅ 所有关键页面状态已绘制（默认/空/加载/错误）
✅ 核心交互流程有 Mermaid 流程图
✅ 文案已定稿（无 [待定]/[TBD] 占位）
✅ 组件规格和交互细节已说明

Tasks → 研发启动 入场条件：
✅ 所有 P0 任务有明确负责人
✅ 任务依赖关系已梳理（无循环依赖）
✅ 估时合理（未超出 Sprint 容量）
✅ 发布检查清单已确认完整
```

> Design 阶段的线框图与状态机生成详见 `prd-proto`。
