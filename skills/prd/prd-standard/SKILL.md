# Prd Standard — 标准 PRD（Full PRD）

> 单一职责：生成标准 8 章 PRD 文档。
> 不做：一页纸（→ `prd-lite`）、Spec-First 四件套（→ `prd-spec-first`）、线框图（→ `prd-proto`）、B 端严格 12 章（→ `/prd --mode enterprise`）

## 黄金原则

```
1. 问题优先：先说清楚要解决什么问题，再说解法
2. 用户视角：每个功能点都能对应到用户需求
3. 可测试：验收标准用 Given/When/Then 写，开发和测试能直接用
4. 刚好够用：精炼而不精简，避免歧义但不过度设计
5. 活文档：PRD 随迭代更新，记录决策变更历史
6. 行业无偏见：消费品/游戏/电商/工业品/服务业与 SaaS 同等适用
```

## 完整模板（8 章）

```markdown
# [产品/功能名] PRD

**版本**：v1.0 | **状态**：[草稿/评审/已批准/已交付]
**PM**：[姓名] | **工程师**：[姓名] | **设计师**：[姓名]
**创建日期**：YYYY-MM-DD | **目标发布日**：YYYY-MM-DD

---

## 1. 概述

### 1.1 问题陈述
[描述用户痛点或业务机会，附数据]

### 1.2 解决方案摘要
[2-3 句话说明方案核心思路]

### 1.3 成功标准
| 指标 | 当前值 | 目标值 | 时间范围 |
|------|--------|--------|---------|
| [指标 1] | X | Y | 30 天 |

---

## 2. 用户与场景

### 2.1 目标用户
**主要用户**：[画像描述]
**次要用户**：[画像描述]

### 2.2 使用场景
**场景 A（核心）**：[用户] 在 [时间/地点] 需要 [做某事]，因为 [原因]。

### 2.3 用户旅程（关键路径）
[步骤 1] → [步骤 2] → [步骤 3] → [Aha Moment]

---

## 3. 功能规格

### 3.1 功能 1：[名称]

**用户故事**：
As a [用户角色], I want to [行为], so that [目的].

**验收标准**：
- Given [前置条件], When [用户操作], Then [系统响应]
- Given [异常条件], When [用户操作], Then [错误处理]

**边界条件**：
- [限制/约束 1]
- [限制/约束 2]

---

## 4. 非功能需求
- **性能**：[响应时间要求]
- **安全**：[数据处理要求]
- **兼容性**：[浏览器/设备/OS]
- **可访问性**：[WCAG 级别]

---

## 5. 指标体系
- **北极星指标**：[指标名]
- **核心指标**：[指标 1]、[指标 2]
- **护栏指标**：[不能恶化的指标]
- **埋点需求**：[关键事件列表]

---

## 6. 发布计划
| 阶段 | 范围 | 时间 | 负责人 |
|------|------|------|--------|

| Beta | 灰度（10%） | W3 | Eng |

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|

---

## 8. 变更记录
| 日期 | 版本 | 变更内容 | 原因 |
|------|------|---------|------|
```

## 验收标准写法（Given/When/Then）

```
❌ 系统应该支持多种登录方式
✅ Given 用户在登录页，When 点击"微信登录"，Then 弹出微信授权页面，授权成功后自动登录

❌ 提升用户满意度
✅ NPS 从 32 提升到 45，发布后 60 天内
```

## 与其他 PRD 模式的边界

| 场景 | 推荐 |
|------|------|
| 1 页内对齐方向 | `prd-lite` |
| Spec-First 工程化（proposal/specs/design/tasks） | `prd-spec-first` |
| 含线框图 + 状态图 | `prd-proto` |
| B 端 SaaS / 私有化 / 多租户 | `/prd --mode enterprise` + `templates/prd-template.md` |
| 含 LLM/Agent/RAG | `@ai-product-architect` |
| 完成后做质量自检 | `prd-quality-check` |
