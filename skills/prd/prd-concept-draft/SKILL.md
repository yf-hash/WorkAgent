# Prd Concept Draft — PRD 概念稿

> 单一职责：把三镜诊断后的产品想法，输出为 1 页内的概念文档。
> 不做：三镜诊断（→ `prd-diagnose`）、详细字段/状态机/接口（→ `prd-implementation-draft`）

> 来源：[chituai/prd-writer](https://github.com/chituai/prd-writer)（MIT License）

## 前置条件

- 三镜诊断已完成（用户/商业/技术至少各有一条清晰回答）
- 用户已对当前理解的复述表示认可

## 模板

```markdown
# [产品名] — 概念文档 v1

**日期**：YYYY-MM-DD
**作者**：[姓名]
**状态**：草稿（待方向确认）

---

## 一句话定位

[目标用户] 使用 [产品形态]，解决 [核心问题]，
相比 [现有方案]，我们 [差异化优势]。

---

## 产品形态

[选择的形态] + 选择理由 + 分阶段策略（如有）

---

## 目标用户

- **核心用户**：[1-2 个画像] + 核心痛点
- **为什么他们会用这个产品而不是别的？**

---

## 产品价值

- **用户价值**：[直接解决的问题]
- **商业逻辑**：[变现方式 / 业务目标]

---

## 核心功能方向（不展细节）

1. [功能方向 A] — [一句话价值]
2. [功能方向 B] — [一句话价值]
3. [功能方向 C] — [一句话价值]

---

## 本次不做

- [排除项 1]：原因
- [排除项 2]：原因

---

## 待解决的关键问题

- [ ] [尚未有答案的问题 1]
- [ ] [尚未有答案的问题 2]
```

## 写作要点

1. **方向对齐为主，不展细节**：篇幅控制在 1 页以内
2. **每节最多 3-5 个要点**：超出就推迟到实现稿
3. **信息不足处写 `[待补充]`**：禁止编造
4. **不做的同样重要**：明确写出排除项 + 原因，避免后期 scope creep

## 交付后流程

```
交付后必须：

1. 请用户确认方向：
   > "以上是基于你的描述梳理出的产品方向，请确认：方向是否准确？有哪些需要调整？"

2. 用户三种选择：
   A. 确认 → 进入实现稿（调用 `prd-implementation-draft`）
   B. 调整 → 修改后再次确认
   C. 暂停 → 当前阶段足够，不进入实现稿

3. 严禁未确认就进入实现稿。
```
