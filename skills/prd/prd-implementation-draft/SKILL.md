# Prd Implementation Draft — PRD 实现稿（23 节）

> 单一职责：把已确认的概念稿展开为详细的 23 节实现稿。
> 不做：诊断（→ `prd-diagnose`）、概念稿（→ `prd-concept-draft`）、评估已有文档（→ `prd-deep-evaluate`）

> 标准模板：`templates/prd-template.md`
> 严禁未经概念稿确认就直接写实现稿。

## 23 节文档结构

```markdown
# [产品名] PRD v1.0

## 1. 文档信息
（产品名称/需求名称/版本号/作者/创建时间/更新时间/评审人员/当前状态/相关人员/版本变更记录）

## 2. 需求背景
2.1 当前问题
2.2 业务影响
2.3 用户痛点

|---|---|---|---|---|---|
| 普通用户 | | | | | |
| 管理员 | | | | | |
| 审计/只读角色 | | | | | |

## 5. 需求范围
5.1 本期实现（MVP，🔴/🟡/⚪ 优先级）
5.2 本期不实现（含原因）
5.3 后续版本规划

## 6. 功能位置与入口
（一级菜单 / 二级菜单 / 页面名称 / 入口按钮 / 默认展示条件 / 可见角色）

### 8.3 异常流程表（含是否允许重试）

## 9. 功能详细说明

每个 🔴 核心功能单独一节（9.1 / 9.2 / 9.3 ...），每节包含：

- 功能说明 + 触发条件 + 入口位置 + 用户操作 + 系统规则 + 权限要求

- 9.x.3 边界条件（空输入/溢出/网络/权限/并发/格式）
- 9.x.4 验收标准（可勾选 checklist）

## 10. 页面与交互说明

- 页面入口 / 页面用途 / 默认状态 / 可见角色

- ASCII 线框图（核心页面布局，可调用 `prd-proto`）
- 用户操作 / 系统反馈 / 异常提示

## 11. 字段说明
```

## 非 PM 用户常见盲区（自动填补）

以下内容在用户未提及时主动补充：

| 盲区类型 | 典型缺失 | 自动补充内容 | 对应章节 |
|---------|---------|------------|---------|
| 交互细节 | 只说"用户点击按钮" | 补充：点击后的即时反馈、加载态、成功/失败提示 | §9.x.1 |
| 状态机 | 只描述成功场景 | 补充：空态/加载/失败/禁用态的展示方案（6 种状态） | §9.x.2 |
| 数据规格 | 只说"有个输入框" | 补充：字段类型/长度/必填/验证规则 | §11 |
| 文案 | 把"button_submit"当作文案 | 区分技术字段名 vs 用户看到的文案 | §15 |
| 权限边界 | 只设计管理员视角 | 补充：不同角色看到什么/能做什么 | §4 / §16 |
| 边界条件 | 只描述正常情况 | 补充：空值/超限/网络异常/并发冲突 | §9.x.3 |
| 删除/覆盖确认 | 直接执行破坏性操作 | 补充：二次确认文案 + 不可撤销说明 | §15.2 |
| 安全合规 | 不考虑敏感字段 | 补充：脱敏/审计日志/凭证有效期/限流锁定 | §16 |
| 状态流转 | 只描述单一状态 | 补充：状态机图 + 触发动作 + 操作人 | §13 |
| 按钮状态 | 只描述"有个按钮" | 补充：查看/编辑/加载/无权限模式下按钮可见性 | §12 |
| 校验规则 | 只说"必填" | 补充：必填/格式/枚举/长度/唯一性/权限 + 失败提示 | §14 |
| 非功能需求 | 不提性能/兼容性 | 补充：性能 P95 / 可用性 / 兼容性 / 可观测性 | §17 |
| 埋点指标 | 不提怎么衡量 | 补充：埋点事件表 + KPI（PV/UV/成功率/失败率） | §18 |
| 接口契约 | 只描述功能不提接口 | 补充：接口列表（方法/路径/入参/出参/权限） | §19 |
| 风险依赖 | 不提潜在风险 | 补充：风险/影响/解决方案/责任人 | §21 |

## 通用写作规则

```
1. 不跳阶段    必须基于已确认的概念稿
2. 主动填盲区  自动识别并补充用户没提到但开发需要知道的内容
3. 双受众分离  技术/开发说明 vs 用户界面文案，永远单独定义
4. 标注不猜测  信息不足时写 [待补充]，不要编造数据
5. 图表优先    能用流程图表达的不用文字，能用表格的不用列表
```
