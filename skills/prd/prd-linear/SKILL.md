# Prd Linear — Linear Issue 级单功能 PRD

> 单一职责：生成可直接粘贴到 Linear Description 的**单个功能点**规范化需求描述。
> 不做：1 页对齐（→ `prd-lite`）、C 端 8 章（→ `prd-standard`）、B 端 12 章（→ `--mode enterprise`）、Spec-First 四件套（→ `prd-spec-first`）、线框图（→ `prd-proto`）

## 黄金原则

1. **单一功能点**：一个 Issue 只描述一个功能，可在一个迭代内完成；多功能拆多 Issue
2. **唯一解读**：数值、状态、文案写死；不同人读完结论必须一致
3. **写死不写虚**：拒绝"尽快、友好提示、合理、优化一下"这类模糊词
4. **图文一致**：有图优先给图（原型/流程/状态机）；图与文字冲突时以文字为准并注明
5. **回写原则**：评论区讨论改动必须回写正文并登记到变更记录

```markdown
# [模块] 动词 + 对象

> 必填字段（在 Linear 侧栏）：Assignee（产品负责人）、Priority、目标 Cycle/版本、Labels

---

[为什么做，解决谁的什么问题，1-3 句，附关键数据]
```

## GWT 验收写法示例

```
❌ Given 用户操作导出，When 点击按钮，Then 导出成功
   （太空泛，"成功"没定义）

✅ Given 用户在订单列表页且已选中 ≤ 500 条订单，
   When 点击"批量导出 Excel"按钮，
   Then 系统在 3 秒内生成 .xlsx 文件并触发浏览器下载，
        文件名格式为"订单导出_YYYYMMDD_HHmmss.xlsx"，
        表头包含订单号/下单时间/金额/状态 4 列。
```

## 红线自检清单（生成后必须自动扫一遍）

> **每次生成完 PRD，逐条检查并把违规行标注出来给用户确认修改**

### A. 禁止出现（发现即标红）

| 检查项 | 违规示例 | 应改为 |
|---|---|---|
| 模糊词-尽快 | "尽快响应" | "≤ 500ms 响应" |
| 模糊词-友好提示 | "友好提示" | 具体文案 + 展示位置 |
| 模糊词-合理 | "合理时间内" | 具体数值 + 单位 |
| 模糊词-大概 | "大概 3 秒" | "≤ 3 秒" 或 "3±0.5 秒" |
| 模糊词-优化一下 | "优化下体验" | 具体交互变更描述 |
| 模糊词-体验更好 | "让体验更好" | 具体指标 + 目标值 |
| 模糊词-正常情况下 | "正常情况下应..." | 明确前置条件 |
| 未定项-TBD | "文案 TBD" | 待定必须标 `@产品` + 确定时间 |
| 未定项-待定 | "上限待定" | 同上 |
| 未定项-后面再说 | "细节后面再说" | 同上 |
| 空引用 | 仅写"参考竞品 X" | 补上具体行为描述 |

### B. 必须做到（缺一项即标黄）

- [ ] 标题格式为 `[模块] 动词 + 对象`
- [ ] 主流程步骤 ≥ 3 且每步是"角色-动作"结构
- [ ] 异常与边界表已填写（至少覆盖：空值 / 超长 / 无权限 / 数据不存在）
- [ ] 数据规则表所有字段的"必填/取值范围/默认值"都写死
- [ ] 权限矩阵已列出所有涉及角色
- [ ] 文案清单每条文案带引号、含标点
- [ ] 验收标准 ≥ 3 条，且全部使用 Given/When/Then 结构
- [ ] 验收标准每条含具体数值或准确文案
- [ ] 非功能要求含性能量化（X 条 ≤ Y 秒）
- [ ] "明确不做"至少列 1 项
- [ ] 影响范围的 5 项全部有答案（不能是空）

### C. 结构自检

- [ ] 一个 Issue 只描述一个功能点（若发现"和 XX 一起"、"顺便加 XX"→ 建议拆分）
- [ ] 全文术语与"名词定义"表一致
- [ ] 数值、状态、文案在正文和表格中一致（无冲突）

## 输出规范

1. 生成路径默认 `./output/PRD-Linear-[模块]-[对象].md`（除非用户指定）
2. 生成完成后**必须自动运行红线自检**，把违规项列成如下格式给用户：

```
✅ 红线自检通过 8/11 项
⚠️  违规 3 项，请确认：
    L23: "友好提示用户重试" → 建议改为具体文案 + 展示位置
    L45: "尽快返回结果" → 建议改为 "≤ 500ms 返回"
    L67: "文案 TBD" → 建议标 @产品 并注明确定时间
```

3. 用户确认修改后，再输出最终版本

## 与其他 PRD 模式的边界

| 场景 | 推荐 |
|---|---|
| Linear/Jira Issue 单功能规范化描述 | **本 skill (`--mode linear`)** ⭐ |
| 1 页对齐方向、立项沟通 | `prd-lite` |
| C 端完整 8 章 PRD | `prd-standard` |
| B 端 SaaS / 私有化严格 12 章 | `--mode enterprise` |
| Spec-First 四件套（proposal/specs/design/tasks） | `prd-spec-first` |
| 含 ASCII 线框图 | `prd-proto` |
| 银行 / 金融需规 | `prd-xqy` |
| 想法模糊，需对话教练 | `prd-diagnose` + `prd-concept-draft` |
| PRD 完成后做质量自检 | `prd-quality-check` |
| 含 LLM/Agent/RAG | `@ai-product-architect` |

## 何时该拆成多个 Linear Issue

- 出现"顺便"、"同时也"、"关联做 XX"→ 拆分信号
- 主流程步骤超过 10 步 → 检查是否可拆成前置 + 主 + 后置
- 涉及跨模块（前端 + 后端 + 数据）且各方独立 → 按端拆分并用"依赖 Issue"关联
