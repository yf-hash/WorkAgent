# Prd Diagnose — 产品想法三镜诊断

> 单一职责：判断一个产品想法是否清楚到可以开始写概念稿。
> 不做：写概念稿（→ `prd-concept-draft`）、写实现稿（→ `prd-implementation-draft`）

> 来源：[chituai/prd-writer](https://github.com/chituai/prd-writer)（MIT License）

## Step 0：资质核查

```
> "能先跟我说说你这个产品/功能的核心想法是什么吗？一两句话就好——想解决谁的什么问题？"
```

| 用户回应 | 判断 | 处理方式 |
|---------|------|---------|
| 能说清楚谁/用什么/怎么更好 | ✅ 可以继续 | 进入三镜诊断 |
| 模糊但有方向 | ⚠️ 需引导 | 追问 1-2 个定向问题 |
| 完全没有方向 | ❌ 还没准备好 | 建议先思考：解决什么问题？谁有这个问题？ |

## 三镜诊断（每次只问 1-2 个问题）

### 镜头一：用户视角

```
核心问题（选 1-2 个追问）：
- 用户现在怎么解决这个问题？用什么工具/方法？
- 你的方案比现有方式好在哪里？好到值得让用户换吗？
- 你跟真实用户聊过吗？他们怎么说？
- 会用这个产品的人，一天会用几次？在什么场景下用？
```

### 镜头二：商业视角

```
核心问题（选 1-2 个追问）：
- 这个产品怎么赚钱？免费增值/订阅/按次付费/广告？
- 已有竞品吗？你跟他们的差异是什么？
- 目标用户规模大概多少？够撑起一个产品吗？
- 做这个产品的目的是什么？是商业变现、积累用户，还是内部工具？
```

### 镜头三：技术视角

```
核心问题（选 1-2 个追问）：
- 你们有这个产品需要的核心技术能力吗？
- 你觉得最难实现的功能是哪个？
- 如果只做一个核心功能先上线，是哪个？（MVP 思维）
- 预计上线时间线是多久？
```

## 产品形态建议（如用户未确定）

| 产品形态 | 最适合场景 | 限制 |
|---------|-----------|------|
| Web App | 复杂功能/B2B 工具/最快上线 | 移动体验弱 |
| 微信小程序 | 中国用户/社交裂变/免安装 | 功能受限/依赖微信 |
| 原生 App | 高频使用/需要设备能力/清晰变现模型 | 开发周期长/需过审 |
| AI 插件/技能 | 增强现有工具/不适合独立产品 | 依赖宿主平台 |

## 输出格式

```markdown
## 三镜诊断小结

**用户镜**：✅ / ⚠️ / ❌ [一句话总结]
**商业镜**：✅ / ⚠️ / ❌ [一句话总结]
**技术镜**：✅ / ⚠️ / ❌ [一句话总结]

**当前理解**：
[用 2-3 句话复述用户的想法，包括用户/问题/解法/差异化]

**下一步建议**：
- 三镜全通 → 进入概念稿（调用 `prd-concept-draft`）
- 有镜头 ⚠️ → 用户决定补足后再继续，或带着假设继续
- 有镜头 ❌ → 建议先做用研/调研，暂不开始 PRD
```

**必须等用户确认或补充后才继续到下一步。**
