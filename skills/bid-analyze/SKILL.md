# Bid Analyze — 标书 Phase 1 招标文件拆解

> 单一职责：标书七阶段第 1 阶段（招标文件深度拆解）。
> 下游：`bid-clarify` 处理澄清问题。

## 三色标记体系

| 标记 | 级别 | 含义 | 处理方式 |
|------|------|------|----------|
| 🔴 红色 ★ | 废标项 | 实质性响应条款，任何一条不满足直接出局 | 100% 响应，零容忍 |
| 🟡 黄色 ▲ | 高分项 | 重要评分条款（标注"权重 X 分"），拉开差距的关键 | 重点投入，详细展开 |
| 🔵 蓝色 | 基础项 | 一般技术条款，基础响应即可 | 标准响应 |

> ⚠️ 不要跳过"投标人须知"和"评标办法"中的技术相关条款，废标陷阱常藏于此。

## 重点扫描领域

技术参数、功能要求、性能指标、部署架构、安全要求、实施范围、验收标准、人员资质、案例要求

## 技术要求清单结构

逐条整理为结构化清单，字段：章节号 / 条款号 / 原文 / 初稿响应 / 偏离类型 / 备注

## 模糊/歧义条款识别规则

| 类型 | 示例 |
|------|------|
| 无具体数值 | "支持高并发"、"具备高可用性" |
| 无边界定义 | "兼容所有操作系统" |
| 不合理要求 | "提供 7×24 小时驻场服务" |
| 前后矛盾 | 同一指标在不同章节要求不一致 |

## 输出物

- `bid-analysis-[项目名].md` — 三色分析报告 + 评分解析 + 投标决策建议
- `技术要求原始清单.xlsx` — 结构化需求清单
- `技术澄清问题清单（初稿）.docx` — 歧义条款清单（流转到 `bid-clarify`）

## 投标决策建议

```markdown
## 投标可行性评估

### 废标风险
- 红色废标项：N 条
- 我方能完全响应：N 条
- 风险条款：N 条（列举 + 风险等级）

### 评分预估
- 当前能拿分数：估算 X / 100
- 高分项中我方薄弱：N 条
- 关键技术差距：[列举]

### 决策建议
- ✅ 强烈建议投：废标 0 风险 + 预估得分 > 80
- ⚠️ 谨慎投：1-2 条风险 + 预估得分 60-80
- ❌ 建议放弃：> 3 条废标风险 或 关键能力缺失
```
