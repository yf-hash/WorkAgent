# 风格驱动内容自进化技能

> 风格卡片 × Writer-Reviewer 互搏 — 让每篇文章向参考文章靠近

## 核心定位

从 1-5 篇优质文章中提炼共性写作风格，生成「风格卡片」，以风格卡片为基准通过 Writer-Reviewer 双
Agent 迭代创作，确保输出风格与参考文章高度一致。

**与 interview-writer 的区别**：interview-writer 基于访谈素材、保留受访者声音；style-evolver 基于
风格卡片、迁移参考文章的写作风格，适合公众号长文、观点文章、品牌内容等任意体裁。

---

## 两阶段架构

```
[阶段一] 风格学习（--learn 触发）
  1-5 篇参考文章
       ↓
  逐篇结构分析（7 个维度）
       ↓
  提炼共性规律
       ↓
  生成「风格卡片」
       ↓
  ⏸ 展示给用户确认/修改
       ↓ 确认
[阶段二] 创作执行
  用户输入：标题 + 框架（可选）
       ↓
  Writer 按风格卡片生成初稿
       ↓
  Reviewer 双维度评分 + 诊断
       ↑_________↓（迭代，最多 3 轮）
       ↓ 达标 / 终止
  输出最终文章 + 进化报告
```

## 阶段一：风格学习

### 步骤 1：逐篇抓取与解析

使用 WebFetch 抓取每篇文章全文，提取：标题、段落结构、小标题分布、开头/结尾模式、字数、平均段落长度。

### 步骤 2：7 维度结构分析

| 维度 | 分析内容 |
|------|----------|
| 开篇模式 | 如何抓住读者（问题/故事/数据/观点） |
| 论证结构 | 总分总 / 问题-解决 / 时间线 / 对比 |
| 段落节奏 | 长短句比例、段落字数分布 |
| 过渡方式 | 章节间如何衔接 |
| 结尾策略 | 总结/行动号召/开放式提问 |
| 语言风格 | 口语化程度、人称使用、情感浓度 |
| 案例密度 | 每千字案例数量、案例类型 |

### 步骤 3：生成「风格卡片」

综合所有文章分析，输出标准格式风格卡片：

```markdown
## 风格卡片（提炼自 N 篇优质文章）

**开篇原则**：[共性开篇策略]
**结构原则**：[共性论证结构]
**节奏原则**：[段落节奏规律]
**语言原则**：[语言风格特征]
**案例原则**：[案例使用规律]
**结尾原则**：[结尾策略]
**禁止事项**：[识别出的反模式、AI 高频词]
```

### 步骤 4：⏸ 暂停等待用户确认

展示风格卡片后，提示用户：
- 直接确认（"确认，开始创作"）
- 修改某项原则后确认
- 保存风格卡片（`--save-card <路径>`）

**必须等待用户确认后才进入阶段二。**

## 阶段二：创作执行

### 初始化

- 加载风格卡片（来自阶段一或 `--style-card` 参数）
- 确定创作模式：
  - 有 `--framework`：按标题 + 框架从零创作
  - 仅有 `--title`：AI 根据风格卡片结构原则自动推导框架
  - 有文档路径：以风格卡片为基准优化已有内容（先做基线评分）
- 加载 proven_solutions 策略库

### Writer Agent 规范

```
第 1 轮：严格对照风格卡片的开篇/结构/节奏/语言原则生成初稿
第 N 轮：读取上轮诊断报告，优先修复 P1 高优先级问题，只做定向修改，不盲目重写
每轮输出修改说明：针对层次 / 修改内容 / 预期提升
```

### Reviewer Agent 规范

```
双维度评分 + 精准诊断（必须找到最弱子维度）
检查终止条件，明确给出是否继续迭代的建议
诊断问题必须对应具体段落/句子，不抽象评价
```

---

## 双维度评分体系

### 维度一：内容质量（50 分）

| 子维度 | 评估标准 | 分值 |
|--------|----------|------|
| 深度与完整性 | 论点充分展开，有背景、分析、结论 | /15 |
| 案例与数据 | 有具体案例支撑，数据真实可信 | /15 |
| 逻辑连贯性 | 段落间逻辑清晰，过渡自然 | /10 |
| 结构完整性 | 有引言、主体、结尾，层次分明 | /10 |

### 维度二：风格合规（50 分）

| 子维度 | 评估标准 | 分值 |
|--------|----------|------|
| 自然度 | 无 AI 高频词，表达自然流畅 | /15 |
| 真实感 | 有个人观点，有真实转折 | /15 |
| 节奏变化 | 句子长短交替，段落有变化 | /10 |
| 风格一致性 | 全文语气统一，符合风格卡片要求 | /10 |

### 诊断报告格式

```markdown
## 第 N 轮诊断报告

### 评分

| 维度 | 子维度 | 本轮 | 上轮 | 变化 |
|------|--------|------|------|------|
| 内容质量 | 深度与完整性 | X/15 | X/15 | +X |
| ... | ... | | | |
| **总分** | | **XX/100** | **XX/100** | **+X** |

### 问题诊断

**P1（必须修复）：**
1. [具体问题] — 影响 -X 分
   - 位置：[段落/章节]
   - 建议：[具体改写方向]

**P2（建议修复）：**

**P3（可选优化）：**

### 终止判断

- 当前 XX/100 | 目标 XX/100 | 距目标 XX 分
- 本轮提升 +X | 连续趋势：[上升/停滞/递减]
- **建议**：[继续迭代 / 已达标 / 边际收益递减建议停止]
```

### 终止条件（满足任一即停）

- 评分达到目标分数（默认 85）
- 已达最大轮次（默认 3）
- 连续 2 次提升 < 3 分

## 核心原则

1. **风格卡片优先**：所有创作必须以风格卡片为基准，不是凭空发挥
2. **用户确认闸门**：风格卡片生成后必须暂停，等待用户确认或修改
3. **诊断驱动改稿**：Writer 每轮改稿必须针对 Reviewer 的具体诊断，不盲目重写
4. **边际收益递减时主动停止**，避免过度优化
5. **活人感优先**：写作输出必须避免 AI 套话，保持真实语感（继承 WorkAgent 四层自检标准）
