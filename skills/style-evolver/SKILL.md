# 风格驱动内容自进化技能

> 风格卡片 × 横纵调查 × Writer-Reviewer 互搏 — 素材驱动，风格对齐，迭代精进

## 核心定位

从 1-5 篇优质文章中提炼共性写作风格，生成「风格卡片」；风格确认后，通过横纵双轴技术调查夯实内容素材；最终以风格卡片为基准通过 Writer-Reviewer 双 Agent 迭代创作。

**三阶段核心逻辑**：
- 阶段一（风格学习）确定**怎么写**
- 阶段二（技术调查）确定**写什么**
- 阶段三（创作迭代）完成**写出来**

**与 interview-writer 的区别**：interview-writer 基于访谈素材、保留受访者声音；style-evolver 基于风格卡片 + 技术调查，适合技术文章、观点文章、品牌内容等需要主动研究的体裁。

---

## 三阶段架构

```
[阶段一] 风格学习（--learn 触发）
  1-5 篇参考文章
       ↓
  逐篇结构分析（7 个维度）
       ↓
  提炼共性规律
       ↓
  生成「风格卡片」
       ↓
  ⏸ 展示给用户确认/修改
       ↓ 确认
[阶段二] 技术调查（--skip-research 时跳过）
  从标题/框架推断核心技术议题
       ↓
  横向搜索（同类方案/竞品对比/用户口碑）
  纵向搜索（技术起源/演进历程/关键节点）  ← 并行执行
       ↓
  汇总调查摘要（纵向发现 + 横向发现 + 关键素材）
       ↓
  ⏸ 展示给用户确认/补充
       ↓ 确认
[阶段三] 创作执行
  用户输入：标题 + 框架（可选）
  调查素材：优先用于案例/数据支撑
       ↓
  Writer 按风格卡片生成初稿
       ↓
  Reviewer 双维度评分 + 诊断
       ↑_________↓（迭代，最多 3 轮）
       ↓ 达标 / 终止
  输出最终文章 + 进化报告
```

## 阶段一：风格学习

### 步骤 1：逐篇抓取与解析

使用 WebFetch 抓取每篇文章全文，提取：标题、段落结构、小标题分布、开头/结尾模式、字数、平均段落长度。

### 步骤 2：7 维度结构分析

| 维度 | 分析内容 |
|------|----------|
| 开篇模式 | 如何抓住读者（问题/故事/数据/观点） |
| 论证结构 | 总分总 / 问题-解决 / 时间线 / 对比 |
| 段落节奏 | 长短句比例、段落字数分布 |
| 过渡方式 | 章节间如何衔接 |
| 结尾策略 | 总结/行动号召/开放式提问 |
| 语言风格 | 口语化程度、人称使用、情感浓度 |
| 案例密度 | 每千字案例数量、案例类型 |

### 步骤 3：生成「风格卡片」

综合所有文章分析，输出标准格式风格卡片：

```markdown
## 风格卡片（提炼自 N 篇优质文章）

**开篇原则**：[共性开篇策略]
**结构原则**：[共性论证结构]
**节奏原则**：[段落节奏规律]
**语言原则**：[语言风格特征]
**案例原则**：[案例使用规律]
**结尾原则**：[结尾策略]
**禁止事项**：[参见下方 AI 高频词与反模式禁用列表]
```

**禁止事项默认包含以下 AI 高频词（来自 op7418/Humanizer-zh）：**

> 此外、至关重要、深入探讨、强调、持久的、增强、培养、获得、突出（动词用法）、
> 格局（抽象名词）、充满活力的、证明（抽象用法）、宝贵的、织锦（比喻用法）、
> 首先/其次/最后（排比导语）、值得注意的是、不容忽视的是、毋庸置疑

在阶段一分析参考文章时，若发现文章刻意回避了某些词汇，额外将其加入禁止列表。

### 步骤 4：⏸ 暂停等待用户确认

展示风格卡片后，提示用户：
- 直接确认（"确认，开始调查"）
- 修改某项原则后确认
- 保存风格卡片（`--save-card <路径>`）

**必须等待用户确认后才进入阶段二。**

## 阶段二：技术调查（`--skip-research` 时跳过）

风格确认后立即进入，目的是让 Writer 在充足事实/数据支撑下创作，而不是凭空发挥。

### 理解写作意图

从 `--title` 和 `--framework` 推断核心技术议题。例如：
- 标题含"RAG"→ 调查 RAG 技术发展 + 各 RAG 方案对比
- 标题含"Agent"→ 调查 Agent 范式起源 + 主流框架横向对比
- 无明显技术词→ 围绕文章核心论点，调查支撑性数据和反例

### 横纵双轴并行搜索

| 搜索轴 | 目标 | 来源优先级 |
|--------|------|-----------|
| **纵向**（时间深度） | 技术/概念起源、关键论文、演进节点、当前状态 | arXiv 论文 > 官方博客 > 权威媒体原创 > 转载 |
| **横向**（同期广度） | 同类方案/竞品识别、核心差异、用户口碑、生态位 | GitHub Issues/Reddit/知乎（真实用户声音）> 官方宣传 |

**学术类议题必查 arXiv**（技术范式、算法、AI 模型等）：
```bash
curl "https://export.arxiv.org/api/query?search_query=all:关键词1+AND+all:关键词2&max_results=10"
```
返回 XML，包含标题/作者/摘要/日期/PDF 链接；找到关键论文后用 WebFetch 读取 `https://arxiv.org/abs/论文ID` 获取细节。

### 信息充分性自检

- 纵向：能还原清晰的技术演进脉络？有没有明显断层？
- 横向：主要方案/竞品都覆盖了吗？对比维度够清晰？
- 来源：关键事实有可靠来源，不靠单一来源下判断

不够就继续补搜，不凑合。

### ⏸ 暂停，输出调查摘要等待用户确认

```markdown
## 技术调查摘要

**主题**：[文章核心技术议题]

**纵向发现**（技术演进）
- 起源：[技术诞生背景、提出者、时间节点]
- 关键演进：[主要版本/论文/里程碑，按时间排列]
- 当前状态：[最新进展、尚未解决的核心问题]

**横向发现**（同类对比）
- 主要方案：[列举 2-5 个同类技术/产品]
- 核心差异：[各方案的本质区别]
- 用户口碑：[社区中被提及最多的优缺点]
- 生态位：[研究对象在整体版图中的位置]

**关键素材**（可直接用于写作）
- [数据/案例/引用 1]
- [数据/案例/引用 2]
- ...

**来源清单**：[URL 列表]
```

用户可：直接确认进入创作 / 要求补充某个方向 / 跳过直接创作。

## 阶段三：创作执行

### 初始化

- 加载风格卡片（来自阶段一或 `--style-card` 参数）
- 加载技术调查摘要（来自阶段二，`--skip-research` 时为空）
- 确定创作模式：
  - 有 `--framework`：按标题 + 框架从零创作
  - 仅有 `--title`：AI 根据风格卡片结构原则自动推导框架
  - 有文档路径：以风格卡片为基准优化已有内容（先做基线评分）
- 加载 proven_solutions 策略库
- 确认 `--mode` 参数，调整各子维度的权重侧重（见下方模式说明）

**调查素材使用原则**：调查摘要中的数据/案例/引用优先用于填充「案例与数据」子维度，Writer 直接嵌入文章，符合风格卡片「案例原则」即可，不强行堆砌。

### 三种创作模式

| 模式 | 侧重 | Reviewer 重点诊断 |
|------|------|------------------|
| `quality` | 内容深度、案例数据、逻辑结构 | 内容质量子维度为 P1 优先 |
| `humanize` | 去 AI 味、活人感、灵魂注入 | 风格合规子维度为 P1 优先，依据 Humanizer-zh 24 种模式逐一扫描 |
| `balance` | 两维度均衡推进 | 两维度中最低子维度优先 |

**`humanize` 模式额外要求（基于 op7418/Humanizer-zh 六大原则）：**

1. **表明立场** — 不只报告事实，要对事实作出反应，允许主观判断
2. **变换节奏** — 长短句交替，两项并列优于强制三项，段落结尾多样
3. **承认复杂性** — 真实的人有混合感受，不要只有单一立场
4. **适当用"我"** — 第一人称表明真实的人在思考，非不专业
5. **允许一些混乱** — 完美结构感觉像算法，跑题和题外话是人性体现
6. **感受要具体** — 不是"这令人担忧"，而是描述担忧来自何处、何种情境

### Writer Agent 规范

```
第 1 轮：严格对照风格卡片的开篇/结构/节奏/语言原则生成初稿
第 N 轮：读取上轮诊断报告，优先修复 P1 高优先级问题，只做定向修改，不盲目重写
每轮输出修改说明：针对层次 / 修改内容 / 预期提升
```

### Reviewer Agent 规范

```
双维度评分 + 精准诊断（必须找到最弱子维度）
检查终止条件，明确给出是否继续迭代的建议
诊断问题必须对应具体段落/句子，不抽象评价

humanize 模式下：额外扫描 24 种 AI 写作模式（见下方），
标注具体模式编号（如 #7 AI词汇、#1 意义膨胀），对应 SC-* 策略修复
```

## 双维度评分体系

### 维度一：内容质量（50 分）

| 子维度 | 评估标准 | 分值 |
|--------|----------|------|
| 深度与完整性 | 论点充分展开，有背景、分析、结论 | /15 |
| 案例与数据 | 有具体案例支撑，数据真实可信 | /15 |
| 逻辑连贯性 | 段落间逻辑清晰，过渡自然 | /10 |
| 结构完整性 | 有引言、主体、结尾，层次分明 | /10 |

### 维度二：风格合规（50 分）

| 子维度 | 评估标准 | 分值 |
|--------|----------|------|
| 自然度 | 无 AI 高频词，无 24 种 AI 模式残留 | /15 |
| 真实感 | 有个人观点，有真实转折，六大人性原则体现 | /15 |
| 节奏变化 | 句子长短交替，段落有变化 | /10 |
| 风格一致性 | 全文语气统一，符合风格卡片要求 | /10 |

### 诊断报告格式

```markdown
## 第 N 轮诊断报告

### 评分

| 维度 | 子维度 | 本轮 | 上轮 | 变化 |
|------|--------|------|------|------|
| 内容质量 | 深度与完整性 | X/15 | X/15 | +X |
| ... | ... | | | |
| **总分** | | **XX/100** | **XX/100** | **+X** |

### 问题诊断

**P1（必须修复）：**
1. [具体问题，如：#7 AI词汇"此外"出现 5 次] — 影响 -X 分
   - 位置：[段落/章节]
   - 建议：[具体改写方向，使用 proven_solutions 策略 ID]

**P2（建议修复）：**

**P3（可选优化）：**

### 终止判断

- 当前 XX/100 | 目标 XX/100 | 距目标 XX 分
- 本轮提升 +X | 连续趋势：[上升/停滞/递减]
- **建议**：[继续迭代 / 已达标 / 边际收益递减建议停止]
```

### 终止条件（满足任一即停）

- 评分达到目标分数（默认 85）
- 已达最大轮次（默认 3）
- 连续 2 次提升 < 3 分

## 24 种 AI 写作模式速查（Humanizer-zh，供 Reviewer 扫描）

### 内容模式（#1–#6）

| # | 模式 | 关键词/症状 |
|---|------|------------|
| 1 | 意义膨胀 | 标志着/见证了/体现了/至关重要的/关键转折点 |
| 2 | 知名度堆砌 | 列出媒体机构名称却无具体引用内容 |
| 3 | 表面 -ing 分析 | 象征着…/反映了…/展示了…（无来源的分析性短语） |
| 4 | 宣传性语言 | 充满活力的/令人叹为观止的/必游之地/迷人的 |
| 5 | 模糊归因 | 专家认为/观察者指出/行业报告显示（无具名来源） |
| 6 | 公式化"挑战与展望" | 尽管面临挑战…仍继续蓬勃发展 |

### 语言模式（#7–#12）

| # | 模式 | 关键词/症状 |
|---|------|------------|
| 7 | AI 高频词汇 | 此外/至关重要/深入探讨/格局/增强/培养/宝贵的/充满活力的 |
| 8 | 系动词回避 | serves as/作为/充当/设有/拥有（替代"是/有"） |
| 9 | 否定排比 | 不仅是 X，更是 Y / 这不仅仅关于 X，而是 Y |
| 10 | 三段式强迫 | 任何强行凑成三项的列举 |
| 11 | 同义词循环 | 同一指代物反复用不同词替代（主人公/主角/中心人物/英雄） |
| 12 | 虚假范围 | 从 X 到 Y，涵盖一切（两端无实质尺度关系） |

### 风格模式（#13–#18）

| # | 模式 | 症状 |
|---|------|------|
| 13 | 破折号滥用 | 每句多个 em dash |
| 14 | 粗体滥用 | 每个术语都加粗 |
| 15 | 行内标题列表 | **标签：** 重复标签内容的格式 |
| 16 | 表情符号装饰 | 🚀💡✅ 装饰标题或列表项 |
| 17 | 三段式被动收尾 | -ing 短语附在句尾制造虚假深度 |
| 18 | 过度行间空白 | 每句话单独成段，人为制造戏剧感 |

### 交流与填充模式（#19–#24）

| # | 模式 | 症状 |
|---|------|------|
| 19 | 聊天机器人套语 | 希望对您有帮助！/当然！/请告诉我 |
| 20 | 截止日期免责 | 截至我最后的训练更新/虽然具体细节有限… |
| 21 | 谄媚语气 | 好问题！/您说得完全正确！ |
| 22 | 填充短语 | 为了实现这一目标/值得注意的是/在这个时间点 |
| 23 | 过度对冲 | 可能潜在地或许/可以被认为是相当 |

## 核心原则

1. **风格卡片优先**：所有创作必须以风格卡片为基准，不是凭空发挥
2. **调查驱动内容**：先摸清技术来龙去脉和横向竞品，再动笔——素材决定内容深度下限
3. **双重确认闸门**：风格卡片生成后暂停一次，技术调查完成后再暂停一次，各需用户确认
4. **诊断驱动改稿**：Writer 每轮改稿必须针对 Reviewer 的具体诊断，不盲目重写
5. **边际收益递减时主动停止**，避免过度优化
6. **活人感优先**：去 AI 味的目标不是"无菌干净"，而是"有声音、有立场、有灵魂"（Humanizer-zh 核心观点）
