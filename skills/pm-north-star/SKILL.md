# PM North Star — 北极星指标设计

> 单一职责：北极星指标设计的 4 个原则和实操方法。
> 不做：AARRR 漏斗指标（→ `pm-growth-aarrr`）、北极星看板（→ `dashboard-northstar`）

## 设计原则

```
好的北极星指标必须满足：

1. 反映用户获得的核心价值（不是收入）
2. 可量化、可分解、可追踪
3. 与商业目标强相关
4. 团队能影响它
```

## 知名公司北极星示例

| 公司 | 北极星指标 | 解读 |
|------|-----------|------|
| Slack | DAU 发送的消息数 | 消息发出 = 真实协作发生 |
| Airbnb | 被预订的夜晚数 | 夜晚 = 房东和房客同时获得价值 |
| Spotify | 每月收听分钟数 | 时长 = 用户被音乐留住 |
| Notion | 每周协作的团队数 | 团队 = 多人协同价值放大 |
| Uber | 完成的乘车次数 | 完成 = 司乘双边都满足 |
| YouTube | 每日观看时长 | 时长 = 内容粘性 |
| Dropbox | 上传文件的活跃用户数 | 上传 = 真实数据托管 |

## 反面案例（不该作为北极星）

```
❌ 注册用户数：滞后指标，可被刷量
❌ 月收入：财务指标不是价值指标
❌ 页面浏览量：不代表用户得到价值
❌ DAU 数字本身：没有体现"做了什么"
```

## 北极星 + 护栏指标

```
北极星单独存在会被钻空子：
- "DAU 发送消息数" → 可能群发垃圾信息
- "观看时长"      → 可能推荐成瘾内容

护栏指标防止异化：
- 用户体验护栏：NPS / 卸载率 / 投诉率
- 商业护栏：付费用户增长率 / 单位经济效益
- 健康护栏：消息互动率 / 内容举报率

北极星 + 护栏 = 完整指标系统
```

## 与 AARRR 漏斗关联

```
北极星位于 Activation/Retention 交集处：
- 太靠 Acquisition → 容易刷量
- 太靠 Revenue     → 容易伤害用户
- 应该是"用户高频获得核心价值"的瞬间

示例（Slack）：
- A 获客：注册团队数
- A 激活：发出第一条消息
- 北极星：DAU 发送消息数 ← 高频价值
- R 留存：周活团队
- R 营收：付费团队
- R 推荐：邀请加入团队
```

## 拆解方法

```
北极星 → 输入指标（Input Metrics）

示例：DAU 发送消息数 = DAU × 人均消息数
  ├── DAU 提升路径：
  │    ├── 新用户激活率
  │    ├── 老用户留存率
  │    └── 唤回成功率
  └── 人均消息数提升路径：
       ├── 团队数 / 用户
       ├── 频道数 / 团队
       └── 消息深度（线程参与）

每个输入指标对应可执行的产品改进项。
```

## 设计自检清单

- [ ] 这个指标反映"用户获得价值"了吗？
- [ ] 我们的团队/产品能影响它吗？
- [ ] 它能拆成 3-5 个输入指标吗？
- [ ] 有护栏指标防止异化吗？
- [ ] 全公司能用一句话解释它吗？
