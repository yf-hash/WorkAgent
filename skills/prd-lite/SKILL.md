# Prd Lite — 一页纸 PRD

> 单一职责：从模糊想法 → 一页 PRD，控制在 1 页以内。
> 不做：详细字段规格、Spec-First 工作流、线框图（分别走 `prd-standard` / `prd-spec-first` / `prd-proto`）

## 黄金原则

1. **问题优先**：先说清楚要解决什么问题，再说解法
2. **用户视角**：每个功能点都能对应到用户需求
3. **可测试**：成功指标量化（X% → Y%，时间范围）
4. **刚好够用**：精炼而不精简，避免歧义但不过度设计

## 一页纸模板

```markdown
# [功能名] — 一页纸 PRD

**日期**：YYYY-MM-DD | **作者**：[PM 姓名] | **状态**：草稿/评审中/已批准

## 背景与问题
[1-2 句话说明背景，附关键数据支撑]
当前问题：[具体描述，附用户反馈或数据]

## 目标用户
[用户角色] 在 [场景] 下，需要 [需求]，但目前 [障碍]。

## 解决方案
[一句话描述方案]
核心功能（MVP）：
1. [功能 1]
2. [功能 2]
3. [功能 3]

## 成功指标
- 主指标：[指标名] 从 X% 提升到 Y%（[时间范围]内）
- 护栏指标：[不能变差的指标]

## 不在范围
- [排除项 1]
- [排除项 2]
```

## 写作要点

- 全文 ≤ 500 字，能在 5 分钟内读完
- 每节最多 3-5 个要点，超出就移到 Full PRD
- 信息不足处写 `[待补充]`，不要编造
- 一页纸做完后，根据需要升级到：
  - 详细 PRD → `prd-standard`
  - Spec-First 工作流 → `prd-spec-first`
  - 含线框图 → `prd-proto`
  - 企业 B 端 SaaS → `/pm-prd-enterprise`

## 适用与不适用

| 适用 | 不适用 |
|---|---|
| 立项前 1 小时对齐 | 工程实施输入（应升级 standard） |
| 跨团队同步进展 | B 端 SaaS / 私有化（应用 enterprise） |
| 客户/老板快速 review | 含界面交互细节（应用 proto） |
