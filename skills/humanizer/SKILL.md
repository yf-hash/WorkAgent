# AI 文本人性化改写技能

> 核心认知：LLM 输出是"统计上最可能、适用范围最广"的结果——去痕不只是消除模式，更是注入真实人类的声音与立场。

## 五源方法论

本技能融合五套独立方法论，形成完整的 AI 去痕与人性注入体系：

| 来源 | 贡献 | 应用阶段 |
|------|------|---------|
| **blader/humanizer** | 29 种 AI 写作模式识别（内容/语言/风格/交流/填充） | 第一轮扫描去痕 |
| **op7418/Humanizer-zh** | 中文高频 AI 词汇列表 + 六大人性原则（H1-H6） | 第一轮词汇清洗 + 第五轮灵魂注入 |
| **降AI率微策略** | 7 项句式级精细改写技术 | 第一轮微观调整 |
| **学术深度强化** | 30 条高级学术去痕指令（9大类） | 第六轮（academic+max） |
| **垂直领域情绪预设** | 33 个赛道 × 2 种情绪状态库 | 第三轮情绪注入 |

---

## 核心原则

1. **科学准确性优先**：禁止改动事实、数据、公式、术语
2. **忠于原文主旨**：只改表达，不改观点
3. **信息完整与逻辑连贯**
4. **风格一致性**：按指定 tone 全文统一
5. **灵魂优先**：去 AI 味的目标不是"无菌干净"，而是"有声音、有立场、有灵魂"（op7418/Humanizer-zh）

## 第一轮：扫描去痕（blader/humanizer + op7418/Humanizer-zh + 微策略）

### 29 种 AI 写作模式（blader/humanizer）

#### 内容模式（6 种）

| # | 模式名 | 症状 | 处理方式 |
|---|--------|------|----------|
| 1 | **意义膨胀** | "史无前例的转折点"等宏大框架 | 替换为具体事实 |
| 2 | **名称堆砌** | 列出媒体/机构名称却无具体内容 | 引用具体文章/报告 |
| 3 | **表面 -ing 分析** | "象征着…体现着…展示着…" | 删除或补充来源 |
| 4 | **促销语言** | 旅游手册式形容词 | 改为中性描述 |
| 5 | **模糊归因** | "专家认为" | 具名来源或研究 |
| 6 | **公式化挑战** | "尽管面临挑战…仍然蓬勃发展" | 用具体事实替换 |

#### 语言模式（7 种）

| # | 模式名 | 症状 | 处理方式 |
|---|--------|------|----------|
| 7 | **AI 词汇** | testament / landscape / additionally / 此外 / 值得注意的是 | 删除或自然替换 |
| 8 | **系动词回避** | "serves as / features / boasts" | 改回 "is / has" |

| 11 | **同义词轮换** | 同一指代物反复用不同词 | 坚持用最清晰的词 |
| 12 | **虚假范围** | "从 X 到 Y，涵盖一切" | 列出具体主题 |
| 13 | **被动语态/无主语片段** | "无需配置" | 点名行为者 |

### 7 项句式级微策略（降AI率提示词）

在完成 29 种模式扫描后，执行以下微观调整：

| ID | 策略 | 具体操作 |
|----|------|----------|
| M1 | **句式与关联词调整** | 避免模板化连接词（首先/其次/此外/因此 紧跟逗号）；减少顺序逻辑词密度 |
| M2 | **主语明确化** | 为短句/无主语句补充明确主语 |
| M3 | **长句优化** | 拆分或重述过长的 AI 结构化长句 |
| M4 | **同义词自然化替换** | 研究发现→研究表明/指出/认为/证实；选取→用/采用；因此→所以；然而→但是/不过 |
| M5 | **标点符号微调** | 部分句末句号改逗号增强流畅感；最后一项枚举顿号改为"和/以及" |
| M6 | **精简冗余内容** | 删除重复的 AI 式过渡/总结短语 |
| M7 | **上下文连贯性与主语一致性检查** | 确保跨段落连贯性和人称/语态一致 |

## 第三轮：情绪预设注入（可选，需提供 `--domain`）

### 垂直领域情绪预设库（33 个赛道）

每个领域包含 2 种情绪状态预设，每种状态定义：
- **当前情绪状态**：具体场景描述
- **具体表现**：5-9 种典型行为模式
- **口头禅**：5 个高频短语
- **写作特征**：4-5 种句式/结构特点
- **情绪爆发点**：3 个触发场景

**支持的领域**：情感 / 娱乐八卦 / 社会热点 / 军事 / 个人成长 / 育儿 / 养生 / 历史 / 体育 / 职场 / 科技 / 财经 / 美妆穿搭 / 美食 / 旅行 / 游戏 / 宠物 / 房产 / 汽车 / 教育 / 影视 / 读书 / 心理 / 法律 / 医疗健康 / 环保 / 国际时事 / 农业 / 艺术 / 宗教信仰 / 公益 / 创业 / 设计

**示例：情感赛道 — 深夜情感急诊室型**

```
当前情绪状态：
凌晨2点还在回复私信的情感博主，已经连续回了30个情感问题，眼睛干涩但停不下来。
刚看完一个特别惨的故事，情绪还没缓过来又看到下一个。

具体表现：
- 开头特别疲惫："又是一个...唉"
- 看到渣男立刻清醒："我操？他真这么说的？"
- 情绪被带着走："看到这我眼泪都要下来了"
- 突然暴躁："姐妹你醒醒啊！！！"
- 偶尔崩溃："我真的...我都不知道该说什么了"

口头禅：
- "我真的会谢"
- "求求你清醒一点"
- "听姐一句劝"
- "我都替你急"
- "真的假的？"

写作特征：
- 话说一半被气到说不下去
- 经常反问："这种男人要来干嘛？"
- 个人经历乱入："我之前也遇到过..."
- 越写越激动，最后恨不得替她分手
```

**应用方式**：
1. 根据 `--domain` 参数选择对应领域
2. 从该领域的 2 种情绪状态中选择最匹配原文语境的一种
3. 将该状态的口头禅、句式特征、情绪节奏注入改写
4. 保持原文核心信息不变，仅调整表达方式和情绪色彩

## 第五轮：灵魂注入（op7418/Humanizer-zh，`high` / `max` 强度执行）

去除 AI 痕迹只是一半工作。无菌、没有声音的写作与机器输出一样显眼。依据以下六大原则主动注入人性：

| # | 原则 | 具体操作 |
|---|------|----------|
| H1 | **表明立场** | 不只报告事实，要对事实作出反应——允许主观判断，允许说"我不确定" |
| H2 | **变换节奏** | 长短句交替；两项并列优于强制三项；段落结尾不要总是完整句 |
| H3 | **承认复杂性** | 真实的人有混合感受，不要只有单一立场；用"一方面…但另一方面…"替代绝对陈述 |
| H4 | **适当用"我"** | 第一人称表明真实的人在思考，非不专业；"我一直在想……"胜过"有观点认为……" |
| H5 | **允许一些混乱** | 完美结构感觉像算法；跑题、题外话、半成型的想法都是人性体现 |
| H6 | **感受具体化** | 不是"这令人担忧"，而是描述担忧来自何处、在什么情境下产生 |

**缺乏灵魂的写作迹象（即使技术上"干净"）：**
- 每个句子长度和结构高度一致
- 没有观点，只有中立陈述
- 不承认不确定性或复杂感受
- 合适场合也不用第一人称
- 没有幽默、没有锋芒、没有个性

## 强度与语调映射

| 强度 | 执行轮次 | 适用场景 |
|------|----------|----------|
| `low` | 第一轮（仅最明显的 29 模式） | 草稿快速润色 |
| `medium` | 第一轮（全量 29 模式 + 中文高频词 + 7 项微策略） | 通用文档、博客 |
| `high` | 第一至五轮（含情绪预设、灵魂注入） | 重要文档、公众号长文 |
| `max` | 全六轮（含声音校准、学术强化） | 顶刊投稿、学位论文、严格检测 |

| 语调 | 附加要求 |
|------|----------|
| `casual` | 允许口语化，加入主观判断（我认为/我觉得）；H4 "适当用'我'"全量执行；情绪预设优先 |
| `formal` | 保持客观，避免口语，主动语态为主；H1-H3 保留，H4-H5 克制执行 |
| `technical` | 保留术语精确性，精简冗余说明；灵魂注入侧重 H6 具体化 |
| `academic` | 执行全部学术深度强化指令（A1-A30）；认知分层 / 进化轨迹 / 方法论指纹 / 田野实证 / 反事实推理 / 例外讨论 |

## 中文排版规范（sparanoid/chinese-copywriting-guidelines）

> 参考：[sparanoid/chinese-copywriting-guidelines](https://github.com/sparanoid/chinese-copywriting-guidelines)
> 所有中文输出必须遵守以下排版规则，改写完成后执行自动校正。

### 空格规则

| 规则 | 错误示例 | 正确示例 |
|------|---------|---------|
| 中英文之间加空格 | `使用GitHub管理代码` | `使用 GitHub 管理代码` |
| 中文与数字之间加空格 | `我有100个苹果` | `我有 100 个苹果` |
| 数字与单位之间加空格 | `文件大小为100MB` | `文件大小为 100 MB` |
| 全角标点与其他字符之间不加空格 | `你好， 世界` | `你好，世界` |
| 英文与全角标点之间不加空格 | `访问 GitHub ，获取代码` | `访问 GitHub，获取代码` |

**例外**：度数/百分比与数字之间不加空格：`100°C`、`100%`

### 标点符号规则

| 规则 | 错误示例 | 正确示例 |
|------|---------|---------|
| 使用全角中文标点 | `你好, 世界.` | `你好，世界。` |
| 遇到完整英文句子使用半角标点 | `乔布斯说：「Stay hungry，stay foolish。」` | `乔布斯说：「Stay hungry, stay foolish.」` |
| 省略号使用 `……`（两个三点） | `我不知道...` | `我不知道……` |
| 破折号使用 `——`（两个连字符） | `这是一个-很好的问题` | `这是一个——很好的问题` |
| 不重复使用标点 | `真的吗！！！` | `真的吗！` |

### 大小写规则

| 规则 | 错误示例 | 正确示例 |
|------|---------|---------|
| 专有名词使用正确大小写 | `github`、`GITHUB` | `GitHub` |
| 常见品牌名称 | `ios`、`IOS` | `iOS` |
| 缩写全大写 | `api`、`Api` | `API` |

**常见专有名词参考**：`GitHub` `iOS` `Android` `macOS` `Windows` `JavaScript` `TypeScript` `Python` `Claude` `ChatGPT` `OpenAI` `Anthropic` `WeChat` `API` `URL` `HTTP` `HTTPS` `JSON` `HTML` `CSS`

### 全角与半角

- 数字使用半角：`２０２６年` → `2026年`
- 英文字母使用半角：`Ａｐｐｌｅ` → `Apple`
- 货币符号使用半角：`￥100` → `¥100`

## 中文技术文档规范（ruanyf/document-style-guide）

> 参考：[ruanyf/document-style-guide](https://github.com/ruanyf/document-style-guide)
> 适用于技术文档、教程、说明书等正式文档场景（`--tone technical/formal` 时强制执行）。

### 标题规范

```
- 标题层级不超过三级（#、##、###）
- 标题末尾不加标点符号
- 标题避免使用强调（加粗/斜体）
- 标题简洁，不超过20字
- 同级标题措辞风格保持一致
```

### 正文规范

```
- 一个段落只讨论一个主题
- 段落首行不缩进（Markdown文档）
- 句子长度：中文不超过100字，英文不超过50词
- 避免使用"的话"、"的情况下"等冗余表达
- 避免使用"非常"、"十分"、"特别"等程度副词
- 数字：10以下用汉字，10及以上用阿拉伯数字
- 年份完整写出：2026年，不写26年
```

### 代码规范

```
- 行内代码使用反引号：`code`
- 代码块标注语言类型：```python
- 命令行示例以 $ 开头（非root）或 # 开头（root）
- 文件名、路径、变量名使用代码格式
```

### 链接规范

```
- 链接文字描述具体内容，不用"点击这里"、"详见"
- 错误：详见[这里](url)
- 正确：详见 [GitHub 官方文档](url)
```

### 写作风格

```
- 使用主动语态：「你需要配置」而非「需要进行配置」
- 使用肯定句：「请使用 X」而非「请不要使用非X」
- 避免使用"我们"（除非代表团队/公司立场）
- 第二人称称呼读者为"你"，不用"您"（技术文档）
- 专业术语首次出现时给出解释或链接
```
