# PRD Generator — 产品需求文档知识库

## PRD 写作黄金原则

```markdown
1. 问题优先：先说清楚要解决什么问题，再说解法
2. 用户视角：每个功能点都能对应到用户需求
3. 可测试：验收标准用 Given/When/Then 写，开发和测试能直接用
4. 刚好够用：精炼而不精简，避免歧义但不过度设计
5. 活文档：PRD 随迭代更新，记录决策变更历史
```

## Lite PRD 模板（一页纸）

```markdown
# [功能名] — 一页纸 PRD

**日期**：YYYY-MM-DD | **作者**：[PM 姓名] | **状态**：草稿/评审中/已批准

## 背景与问题
[1-2句话说明背景，附关键数据支撑]
当前问题：[具体描述，附用户反馈或数据]

## 目标用户
[用户角色] 在 [场景] 下，需要 [需求]，但目前 [障碍]。

## 解决方案
[一句话描述方案]
核心功能（MVP）：
1. [功能 1]
2. [功能 2]
3. [功能 3]

## 成功指标
- 主指标：[指标名] 从 X% 提升到 Y%（[时间范围]内）
- 护栏指标：[不能变差的指标]

## 不在范围
- [排除项 1]
- [排除项 2]
```

## 用户旅程 + Mermaid 流程图（workflow 模式）

```markdown
# 用户旅程：[功能名]

## 主要流程
```mermaid

    A[用户进入页面] --> B{已登录?}
    B -- 否 --> C[跳转登录]
    B -- 是 --> D[展示主界面]

    E --> F[填写表单]

    I --> J[跳转详情页]
```

## 情绪旅程
| 步骤 | 用户感受 | 优化机会 |
|------|---------|---------|
| 进入页面 | 🤔 迷茫 | 清晰的价值主张 |
| 注册 | 😤 摩擦 | 减少必填字段 |
| 首次使用 | 😊 满足 | 强化 Aha Moment |
```

## 功能决策框架

```markdown
拒绝一个需求的合理理由：
1. 不符合目标用户群
2. 解决的问题不够大（影响 <5% 用户）
3. 与产品定位/策略冲突
4. 技术成本高于用户价值
5. 可用第三方集成代替

接受一个需求的信号：
1. 多个高价值用户提出相同需求
2. 当前痛点导致明显流失
3. 竞品已有且用户明确对比
4. 解锁关键商业场景（企业/合规/集成）
```
