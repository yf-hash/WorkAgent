# Solution Architecture — 解决方案架构设计知识库

> 售前架构师（SA / Solution Engineer / Sales Architect）的核心交付物：
> **客户化的、端到端的、可实施的解决方案蓝图**。区别于 PM 的产品架构（多客户通用），
> 也区别于研发的技术架构（实现细节），SA 的方案要让客户能看懂、能签字、能实施。

---

## 一、SA Blueprint 12 章标准结构

```
1. 执行摘要（Executive Summary）
   - 一页纸：客户挑战 / 我方方案 / 量化收益 / 总投入
   - 给经济决策人（EB）看，5 分钟读完

2. 业务背景
   - 客户业务概述 + 行业地位 + 战略目标
   - 引用客户公开资料（避免假设）

3. 现状分析（As-Is）
   - 现有 IT 架构图 + 关键组件清单
   - 已有工具 / 厂商 / 集成
   - 痛点量化（来自 discovery-call 阶段输出）

4. 目标架构（To-Be）
   - 我方主推架构图（建议用 arch-diagram skill 生成）
   - 关键能力清单
   - 与现状的差异点

5. 部署模式
   - 公有云 / 私有化 / 混合 / SaaS 决策矩阵
   - 客户已有云资源 / 数据中心利旧情况
   - 国产化 / 信创合规要求

6. 集成方案
   - SSO（SAML / OIDC / OAuth）
   - 用户同步（SCIM / LDAP / AD）
   - 业务系统集成（API / 消息队列 / 数据库直连）
   - 与客户现有 [具体系统名] 的对接细节

7. 容量规划
   - 用户规模 / 数据规模 / 并发规模
   - Year 1 / Year 3 容量增长预测
   - 资源清单（CPU / Mem / Disk / Network）

8. 高可用与灾备
   - 可用性目标（99.9% / 99.95% / 99.99%）
   - 双活 / 主备 / 多地多中心
   - RPO（数据丢失目标）/ RTO（恢复时间目标）

9. 安全与合规
   - 客户合规要求清单（等保 / 行业标准）
   - 数据保护（加密 / 脱敏 / 权限）
   - 审计 + 日志保留期

10. 实施路线图
    - Phase 1（30 天）：试点 / PoC
    - Phase 2（60 天）：核心场景上线
    - Phase 3（90 天）：全量推广
    - 每 Phase 的里程碑 + 验收标准 + 责任分工

11. 商业模型与报价
    - License / 订阅 / 一次性 / 混合模式
    - 三档报价（标准 / 推荐 / 企业版）
    - 服务包（实施 / 培训 / 运维 / SLA）

12. 假设、风险与下一步
    - 已识别的关键假设（如客户提供 X 才能实施 Y）
    - 风险矩阵（识别 + 概率 + 影响 + 应对）
    - 明确 Next Step（合同 / PoC / 二轮深谈）
```

## 二、现状评估（As-Is）方法

### 2.1 信息来源（按可信度）
1. 客户提供的架构图 / 文档（最优）
2. discovery-call 阶段访谈记录
3. 客户公开技术博客 / 招聘 JD
4. 同行 / 我方过往合作经验推断（标"⚠️ 待验证"）

### 2.2 必须问清楚的 10 个问题
```
① 当前 [对应业务领域] 用什么工具？厂商是谁？版本号？
② 这套系统部署在哪里？公有云 / 私有云 / 混合？
③ 与哪些其他系统集成？怎么集成（API / 数据库直连 / FTP）？
④ 数据规模？日活用户？峰值并发？数据增长速度？
⑤ 用户体系怎么管理？SSO 用什么协议？
⑥ 安全合规要求（等保级别 / 行业标准 / 数据出境限制）？
⑦ 运维团队规模？目前每天投入多少时间在这套系统上？
⑧ 当前最大的 3 个痛点（量化）？
⑨ 已知的限制（预算 / 时间 / 厂商绑定 / 政策）？
⑩ 决策流程 / 关键时间节点 / 验收标准？
```

## 三、目标架构（To-Be）设计原则

### 3.1 三层透视
```
业务层：客户业务流程 → 我方解决的环节
应用层：我方产品组件 + 客户已有系统的协作
基础设施层：部署位置 / 资源规划 / 网络隔离
```

### 3.2 客户化关键决策点

| 决策点 | 选项 | 决策依据 |
|--------|------|---------|
| 部署模式 | SaaS / 私有化 / 混合 | 数据敏感性 / 合规 / 已有 IT 投资 |
| 数据存储 | 客户侧 / 我方云 / 客户指定云 | 合规 + 数据主权 |
| 用户认证 | 集成 SSO / 独立账号 | 客户 IT 治理水平 |
| 高可用方案 | 单中心 / 双活 / 异地容灾 | 业务连续性需求 + 预算 |
| 国产化 | 全栈 / 部分 / 非必需 | 政策要求 + 客户行业属性 |
| 扩展性 | 单租户 / 多租户 / SaaS 化 | 集团客户分子公司隔离要求 |

### 3.3 架构图绘制
- 使用 `arch-diagram` Skill 生成主架构图（云上架构 / K8s 部署架构）
- 用 `mermaid-chart` / `diagram-plantuml` 生成集成时序图（SSO 流程 / 数据同步流程）
- 用 `visio-builder` 生成给客户看的部署拓扑（VLAN / 防火墙 / 跨网段）

## 四、非功能需求清单（NFR Checklist）

售前方案最容易丢的部分。每条都要明确量化：

```
性能：
  □ 接口响应时间（P50 / P95 / P99）
  □ 并发用户数 / TPS
  □ 数据处理吞吐量
  □ 大数据查询超时阈值

可用性：
  □ 系统可用性 SLA（99.9% / 99.95% / 99.99%）
  □ 计划停机窗口（每月 / 每季）
  □ 非计划停机响应承诺

可扩展性：
  □ 横向扩展能力（节点 / 实例）
  □ 多租户隔离方案
  □ 数据分片策略

安全：
  □ 传输加密（TLS 1.2+ / 国密 SM2/SM4）
  □ 存储加密（KMS / 客户托管密钥）
  □ 权限模型（RBAC / ABAC）
  □ 审计日志留存期（90 天 / 1 年 / 5 年）

合规：
  □ 等保（二级 / 三级）
  □ 行业标准（金融 GB/T 36651 / 医疗 HIPAA / 个保法）
  □ 数据本地化要求
  □ 客户合规审计配合（年度 / 季度）

可观测：
  □ 监控指标体系
  □ 日志聚合方案
  □ 告警通知渠道
  □ 客户侧观测能力（仪表盘 / API）

可维护：
  □ 升级机制（在线 / 停机）
  □ 备份恢复方案（频率 / 验证）
  □ 故障排查工具链
```

## 五、实施路线图设计

### 5.1 三阶段经典模板（90 天）

```
Phase 1：试点验证（Day 1-30）
  目标：验证可行性 + 建立信任
  内容：
    - 单一场景 / 单一团队 / 受限数据
    - 关键能力 PoC
    - 量化基线建立（性能 / 准确率 / 业务指标）
  验收：
    - PoC 报告通过 + 关键指标达到承诺值
    - 内部 Champion 公开认可
  里程碑：T+30 转 Phase 2 决策会议

Phase 2：核心上线（Day 31-60）
  目标：核心场景生产化
  内容：
    - Phase 1 验证过的场景全量化
    - 1-2 个新增场景试点
    - 用户培训 + 流程对接
  验收：
    - 业务负责人签字
    - SLA 达成率 ≥ 承诺
  里程碑：T+60 转 Phase 3 决策会议

Phase 3：全量推广（Day 61-90+）
  目标：覆盖目标用户 / 业务范围
  内容：
    - 剩余场景上线
    - 优化迭代
    - 知识转移给客户运维
  验收：
    - 整体使用率 ≥ 70%
    - 客户运维独立处理 80%+ 工单
  里程碑：项目验收 + 续约谈判启动
```

### 5.2 风险节点识别

```
🔴 高风险节点：
  - Phase 1 → Phase 2 切换（首次遇到真实数据）
  - 跨系统集成（依赖客户 IT 配合）
  - 用户大规模培训（人员阻力）

🟡 中风险节点：
  - 性能调优（真实负载下性能差异）
  - 权限模型上线（业务流程变更阻力）
```

## 六、报价框架（与方案绑定）

### 6.1 三档定价模型

| 档位 | 适用客户 | 内容 | 报价信号 |
|------|---------|------|---------|
| **标准版** | 中小客户 / 单一场景 | 核心模块 + 基础服务 | 客户预算锚点 |
| **推荐版** | 主流客户 / 多场景 | 核心 + 重要扩展 + 标准服务 + 培训 | 我方主推（客户最常选）|
| **企业版** | 战略客户 / 全场景 | 全模块 + 高级服务 + 驻场 + 高 SLA | 价值锚点（让推荐版显得划算）|

### 6.2 报价构成 7 项

```
1. 软件 License / 订阅费（按用户 / 节点 / 数据量）
2. 实施服务费（一次性 / 按 Phase）
3. 培训费（管理员培训 / 终端用户培训）
4. 年度服务费（升级 / 维护 / 支持）
5. SLA 增值费（24×7 / 4 小时响应 / 现场驻场）
6. 定制开发费（按工时 / 按模块）
7. 第三方组件 / 硬件 / 云资源（透传 / 含税）
```

### 6.3 折扣谈判预案

```
首次报价：含 0% 折扣，留 20-30% 谈判空间
谈判第 1 轮：5-10% 标准折扣（不要轻给）
谈判第 2 轮：换条件给 10-15%（如多年合同 / 推荐客户 / 案例使用权）
最终底线：留 5-10% 给销售总监 / VP 关键时刻拍板
```

## 七、客户化定制要点（按行业）

### 7.1 金融
- 强调：等保三级 + 国密支持 + 数据本地化 + 监管报告
- 弱化：不讲"公有云优势"，讲"私有云 + 容器化"
- 关键人：CIO / CISO / 业务总 / 监管报送负责人

### 7.2 政府 / 央国企
- 强调：信创认证 + 全栈国产 + 党政合规 + 项目化交付
- 必备：项目实施方案、可研报告、概算估算
- 关键人：分管副总 / 信息中心主任 / 财务负责人

### 7.3 医疗
- 强调：互联互通 + 数据安全 + 临床场景适配
- 必备：行业资质（医疗器械软件）+ 同行案例
- 关键人：信息科长 / 业务主任 / 医务处

### 7.4 制造
- 强调：工厂部署 + 离线 / 弱网 + OT-IT 融合
- 必备：工业现场实施经验 + 硬件兼容性
- 关键人：信息总监 / IT 与运维 / 工厂厂长

### 7.5 SaaS / 互联网
- 强调：API + 集成生态 + 自助化 + 弹性扩缩容
- 弱化：少强调"项目实施"，多强调"快速上手"
- 关键人：CTO / 工程总监 / 安全负责人

## 八、方案评审清单（提交前必查）

```
□ 客户视角
  □ 客户能 5 分钟读完执行摘要并理解核心
  □ 客户业务术语正确（避免我方产品行话）
  □ 客户的 3 个核心痛点都被回应

□ 完整性
  □ 12 章结构完整
  □ 所有数字可追溯（容量 / 性能 / 报价）
  □ 假设条件明确列出

□ 可信度
  □ 客户案例真实可查（同行业 / 同规模）
  □ 性能数据有 PoC 或基准测试支撑
  □ 时间表合理（不夸张）

□ 商业可行
  □ 三档报价齐全
  □ 服务包对应明确
  □ 折扣谈判空间预留

□ 风险透明
  □ 关键假设明确（避免后期纠纷）
  □ 风险矩阵 + 应对措施
  □ 不能做到的明说（避免承诺过度）
```

## 九、与其他 Skill 的边界

| 选择 | 用前者 | 用后者 |
|------|-------|-------|
| `solution-architecture` vs `proposal-generator` | 技术架构方案（SA 主笔）| 商业方案三大类（投标 / 可研 / 初步设计）|
| `solution-architecture` vs `arch-diagram` | 完整方案文档（含架构图）| 单纯生成架构图 |
| `solution-architecture` vs `prd --mode enterprise` | 售前面向客户 | PM 内部产品规格 |
| `solution-architecture` vs `discovery-call` | 第 3+ 次会议（架构落地）| 第 1-2 次（需求挖掘）|
| `solution-architecture` vs `gap-analysis` | 完整方案蓝图 | 客户需求 vs 产品能力的对照表 |
