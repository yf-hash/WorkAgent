# Security Questionnaire — 安全问卷应答知识库

> 客户（特别是金融 / 医疗 / 政府 / 大企业 SaaS 采购方）签约前会发一份
> 200-500 条的安全问卷，覆盖访问控制、数据保护、运维流程、合规资质、事故响应
> 等数十个维度。售前 / 安全合规岗位的高频任务。
> 区别于 `rfp-response`：本 Skill 专注**安全维度的深度问卷**，与合规证据强绑定。

---

## 一、行业标准问卷模板

| 模板 | 全称 | 适用场景 | 题量 |
|------|------|---------|------|
| **CAIQ** | Consensus Assessment Initiative Questionnaire | 云服务商通用（CSA 出品）| ~250 条 |
| **SIG** | Standard Information Gathering | 第三方风险（Shared Assessments 出品）| Lite 200 / Core 1000+ |
| **VSA** | Vendor Security Alliance Questionnaire | 中小企业供应商评估 | ~150 条 |
| **CAIQ Lite** | CAIQ 简化版 | 快速评估 | ~70 条 |
| **客户自定义** | 客户内部 IT 部门拟定 | 大客户专属 | 50-300 条不等 |

**应答顺序建议**：
- 优先答 CAIQ（覆盖最广）→ 其他问卷 80% 内容可复用 CAIQ 答案
- 客户自定义问卷优先级最高（影响签约），CAIQ / SIG 可作为兜底证据

## 二、问题分类与应答策略

### 2.1 13 大问题类别

| 类别 | 典型题数 | 应答关键 |
|------|---------|---------|
| 公司治理与组织 | 10-15 | 组织架构 / 安全团队规模 / 报告线 |
| 风险管理 | 10-20 | 风险评估流程 / 频率 / 输出 |
| 合规资质 | 10-30 | 持有证书清单 + 年审记录 |
| 数据分类与保护 | 20-30 | 加密 / 脱敏 / 留存 / 销毁 |
| 访问控制 | 30-50 | RBAC / SSO / MFA / 审计 |
| 物理安全 | 10-20 | 数据中心 / 办公环境 / 访客管理 |
| 网络安全 | 20-40 | 边界防护 / 隔离 / WAF / DDoS |
| 应用安全 | 20-40 | SDLC / 代码审计 / 渗透测试 / SAST/DAST |
| 运维与变更管理 | 15-30 | 变更流程 / CMDB / 备份 / 灾备 |
| 事件响应 | 10-20 | IR 流程 / 通知 SLA / 演练频率 |
| 业务连续性 | 10-20 | BCP / DR / RPO / RTO |
| 第三方管理 | 10-20 | 子处理者清单 / 评估流程 |
| 隐私合规 | 15-30 | GDPR / CCPA / 个保法 / 数据主体权利 |

### 2.2 应答模式四级

| 模式 | 标签 | 何时用 | 示例措辞 |
|------|------|--------|---------|
| **完全披露** | ✅ Full Disclosure | 已有公开认证 / 行业标准 | "我方已通过 SOC 2 Type II 审计，报告附后（NDA 后提供完整版）" |
| **部分披露** | ⚠️ Partial | 涉及商业机密但需要回应 | "我方采用业界标准的 [X] 加密方案，具体实现细节为商业机密" |
| **诚实承认** | ❌ No / Not Applicable | 当前确实不具备 | "我方暂未实施 [Y]，预计 [日期] 完成。在此期间通过 [补偿措施] 缓解" |
| **签 NDA 后再答** | 🔒 Under NDA | 高敏感信息 | "签署 NDA 后我方提供完整答复 + 证据材料" |

**铁律**：
- 不能答的题（涉及客户其他案例 / 内部架构 / 商业机密）→ 走 NDA，不要含糊带过
- 不具备的能力 → 诚实承认 + 补偿措施 + 时间表，绝对不能造假
- 历史事件 → 必须诚实披露（客户能查 CISA / NIST 漏洞库 / 媒体报道）

## 三、合规证据映射表

每个问题至少链接 1 份证据。

| 问题类别 | 主要证据来源 |
|---------|------------|
| 安全治理 | 信息安全方针、组织架构图、岗位说明书 |
| 合规资质 | SOC 2 Type II 报告、ISO 27001 证书、等保备案、PCI AOC |
| 加密 | 加密算法白皮书、KMS 架构图 |
| 访问控制 | RBAC 矩阵、SSO 配置、审计日志样本 |
| 渗透测试 | 第三方渗透测试报告（脱敏版）、年度执行记录 |
| 事件响应 | IR Playbook、过往事件复盘报告（脱敏）、通知 SLA |
| 业务连续性 | BCP 文档、DR 演练报告、RTO/RPO 数据 |
| 第三方 | 子处理者清单、第三方评估报告 |
| 隐私 | 隐私政策、DPIA 报告、DPA 模板 |

**证据准备清单**（一次准备，长期复用）：
```
必备文档（每年更新）：
  ✅ SOC 2 Type II 报告（脱敏版 + NDA 完整版）
  ✅ ISO 27001 证书 + 适用范围说明
  ✅ 等保三级备案证明（如适用）
  ✅ 最新一次渗透测试报告（≤12 个月）
  ✅ 网络安全保险证书
  ✅ 隐私政策 + DPA 模板
  ✅ 信息安全方针文档
  ✅ 业务连续性 / 灾备方案
  ✅ 子处理者清单
  ✅ 数据流图 / 数据地图

按需提供：
  - 国密合规证明
  - 行业资质（HIPAA / PCI 等）
  - 年度合规自查报告
  - IR 历史事件汇总（脱敏）
```

## 四、敏感问题红线

### 4.1 必须诚实披露的（不披露 = 法律风险）

```
❗ 数据驻留：哪些国家 / 地区 / 数据中心
❗ 子处理者清单：用了哪些第三方（云 / 邮件 / CDN / 监控）
❗ 数据出境：是否有数据跨境传输 + 法律基础（SCC / DPA）
❗ 历史事故：12-24 个月内是否发生过数据泄露
❗ 政府请求：过去是否收到过政府数据请求
```

### 4.2 可走 NDA 后披露的

```
🔒 详细架构图（含 IP / 端口 / 内部命名）
🔒 SOC 2 完整报告（含 Auditor 详细发现）
🔒 渗透测试详细发现
🔒 客户清单（仅按行业 / 规模透露）
🔒 加密算法实现细节
```

### 4.3 可拒答的

```
🚫 单一客户的特定数据（违反 NDA）
🚫 未发布的产品 roadmap
🚫 员工个人信息（除非 KYC 必需）
🚫 商业利润 / 财务详情（除非上市公司公开数据）
```

## 五、应答 KB 复用机制

```
Step 1: 建立"安全问卷标准答案库"
  → 250 条 CAIQ 全部维护标准答案
  → 每条答案 3 个版本：
    - 完整版（≤500 字 + 证据链接）
    - 简化版（≤100 字，用于快速过审）
    - 拒答版（涉密时的标准措辞）

Step 2: 分配维护责任
  → 安全 / 合规 → 加密 / 审计 / 合规资质 / 事件响应
  → IT 运维 → 物理安全 / 网络 / 备份 / 灾备
  → 法务 → 隐私 / 合规 / 第三方 / 跨境
  → HR → 员工背调 / 安全意识培训
  → 工程 → 应用安全 / SDLC / 代码审计

Step 3: 季度更新
  → 证书续期 → 立刻更新答案
  → 重大事件后 → 补充答案中
  → 每季度 review 一次（避免出现陈旧数据）

Step 4: 检索与匹配
  → 收到新问卷 → 关键词匹配现有 KB
  → 匹配率 80%+ 视为成熟 KB（典型 CAIQ 复用率 ~95%）
  → 无法匹配的题 → 立即走专家分配流程
```

## 六、应答 SOP（标准操作流程）

```
T-15 天：拆题 + 分配
  □ 把问卷拆解到 13 大类
  □ 每类分配负责人 + 截止日期
  □ 标记敏感问题（需法务 / 高管 review）

T-12 天：第一轮草稿（80%）
  □ 用现有 KB 直接复用 → 标"✅ KB 复用"
  □ 需更新的题 → 责任人补全
  □ 新题 → 起草后内部 review

T-8 天：交叉评审
  □ 不一致项核对（同一指标不同处答案要一致）
  □ 措辞红线扫描（"100%"、"完全"、"绝对"等）
  □ 证据链接检查（每个引用的文档可访问）

T-5 天：法务 + 高管终审
  □ 法务：跨境 / 子处理者 / 历史事件
  □ CISO / 安全总：技术细节准确性
  □ 销售总监 / VP：商业敏感度

T-3 天：客户化定制
  □ 把通用答案改成客户行业语言
  □ 增加客户行业相关案例引用（不违反 NDA 前提）

T-1 天：终检 + 提交
  □ 文件命名：[公司]_[客户]_SecurityQuestionnaire_v[版本]_[日期].xlsx
  □ 索引页 / 目录 / 版本说明
  □ 附件清单（证书 / 报告打包）
```

## 七、年度续答 SOP

大客户每年都要重答一遍同一份问卷。

```
T+0：客户发新问卷
T+3：与去年问卷做 diff
  → 新增题目 → 重点 review
  → 内容变化 → 客户需求变化信号
T+5：用最新版 KB 重新生成答案
T+7：补充证据（证书续期 / 新增认证 / 新事件）
T+10：提交
```

## 八、与其他 Skill 的边界

| 选择 | 用前者 | 用后者 |
|------|-------|-------|
| `security-questionnaire` vs `compliance-checklist` | 客户主动发起的问卷应答（被动）| 我方主动建立合规体系（主动）|
| `security-questionnaire` vs `rfp-response` | 纯安全维度的深度问卷 | 综合 RFP（含部分安全题）|
| `security-questionnaire` vs `bid-writer` | 安全问卷专项 | 招标文件全流程 |
| `security-questionnaire` vs `pm-ai-security-product` | 客户对我方安全的评估 | 我方安全产品的产品方法论 |
