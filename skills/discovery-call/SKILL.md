# Discovery Call — 售前需求挖掘知识库

> 售前最大的机会损失发生在**第一次客户会议**：要么没问对问题（错过痛点），
> 要么没记对内容（后续脱节），要么没识别决策链（功夫白费）。
> 本 Skill 提供一套结构化的售前调研工作流。

---

## 一、会前准备（T-3 ~ T-1）

### 1.1 客户背调清单
```
公司层（必查）：
  □ 公司官网 + 招股书 / 年报 / 季报
  □ 主营业务 + 营收规模 + 员工规模 + 总部地点
  □ 最近 12 个月新闻（融资 / 高管变动 / 战略发布）
  □ 招聘岗位（技术栈 / 团队规模 / 在建项目暗示）
  □ 公开技术博客 / GitHub / 招标公告

个人层（决策链每人）：
  □ LinkedIn / 脉脉 / 个人公众号
  □ 公开演讲 / 文章 / 微博
  □ 入职时长（决策权重 + 风险偏好）
  □ 之前合作背景（与我方 / 我方对手）

竞争层：
  □ 客户已用哪些同类产品 / 服务
  □ 已知的对手在跟（参考行业群 / 圈内消息）
  □ 我方关系深度（是否有内部 Champion）
```

### 1.2 议程设计（60-90 分钟标准）

```
0-5 分钟    | 寒暄 + 议程对齐（不开门见山卖东西）
5-15 分钟   | 客户介绍他们的业务（让对方说，建立基线）
15-50 分钟  | 我方提问（SPIN 主导，70% 时间在听）
50-65 分钟  | 我方简介（不是 Demo，是"我们如何理解你的痛点"）
65-80 分钟  | 探索具体场景（一两个深挖）
80-90 分钟  | Next Step 明确（永远不要无尾会议）
```

**反模式**：
- ❌ 一上来就放产品 PPT
- ❌ 客户没说完痛点就跳到方案
- ❌ 聊完没有具体下一步（"再联系"=失败）

## 二、SPIN 提问框架

| 阶段 | 提问类型 | 目的 | 示例 |
|------|---------|------|------|
| **S** Situation | 情境提问 | 了解现状（事实）| "你们目前 SOC 团队有几人？告警平均一周多少条？" |
| **P** Problem | 问题提问 | 暴露问题 | "告警量这么大，团队怎么处理优先级？" |
| **I** Implication | 影响提问 | 放大痛点 | "如果一个高危告警被淹没，对业务最坏会怎样？" |
| **N** Need-payoff | 需求-成效 | 引导对方说出价值 | "如果误报能降到 50 条，你们会怎么用回这部分时间？" |

**提问铁律**：
1. **70-30 法则**：70% 时间客户说，30% 时间我们说
2. **问题密度**：S 类 ≤ 30%，I + N 类 ≥ 50%（这是售前 vs 销售的差异）
3. **追问优先**：客户给的每个回答，至少追问一次"具体来说……"
4. **避免封闭式**：不要问"你们要不要 X"，要问"你们现在怎么解决 X"

## 三、MEDDIC 资格评估（机会健康度）

每场会议结束后，对照 MEDDIC 6 项打分（每项 1-5 分），总分 ≥18 分 = 高质量机会。

| 字母 | 维度 | 关键问题 | 不达标信号 |
|------|------|---------|----------|
| **M** Metrics | 量化指标 | 客户痛点能用数字描述吗？预期改进多少？ | 客户只说"想提高效率"——没量化 = ⚠️ |
| **E** Economic Buyer | 经济决策人 | 谁能签字付款？我们见过吗？ | 只接触执行层 = ⚠️ |
| **D** Decision Criteria | 决策标准 | 客户用什么维度评估候选方案？ | 客户说"看综合"——没标准 = ⚠️ |
| **D** Decision Process | 决策流程 | 几个会议节点？审批层级？预计时间表？ | 客户说"快了"——无时间表 = ⚠️ |
| **I** Identify Pain | 真实痛点 | 不解决会怎样？业务影响多大？ | 客户回避负面后果 = ⚠️ |
| **C** Champion | 内部冠军 | 客户内部有人主动帮我们推吗？ | 没有内部支持者 = 高风险 |

**Win Score 计算**：6 项加总 ÷ 30 × 100% = 赢单概率粗估
- 80%+ → 投入售前主力
- 50-80% → 标准投入
- <50% → 重新评估或弃单

## 四、客户角色识别（DMU / DMP）

DMU = Decision Making Unit（决策单元），通常 4-8 人。

| 角色 | 关心什么 | 我方应对策略 |
|------|---------|------------|
| **Economic Buyer** 经济决策人 | ROI / 总成本 / 战略对齐 | 给 Business Case + 高管见面 |
| **User Buyer** 使用者 | 是否好用 / 学习成本 / 工作压力 | Demo + 试用 + 培训 |
| **Technical Buyer** 技术把关 | 架构 / 安全 / 集成 / 性能 | 技术深度方案 + 架构图 |
| **Coach / Champion** 内部冠军 | 帮我方推动 / 自身利益 | 重点维护 + 弹药供给 |
| **Blocker / Antagonist** 阻挠者 | 反对变革 / 偏向对手 / 个人利益 | 识别 + 中立 + 隔离 |
| **Influencer** 影响者 | 各类外部顾问 / 内部专家 | 提前接触 + 信息一致 |

**陷阱识别**：
- 「单点接触」：只跟一个人沟通 → 风险极高
- 「Champion 失踪」：内部冠军突然不响应 → 多半已变阵
- 「过度技术化」：见的都是 Tech Buyer，没有 Economic Buyer → 单子卡住

## 六、回声邮件模板（24 小时内发出）

```
主题：[客户公司] x [我方公司] 沟通纪要 | [日期]

[客户负责人] 您好：

非常感谢您今天抽时间与我们交流。结合您分享的内容，我整理了三个核心要点：

1. 业务挑战：[一句话概括客户最迫切的痛点 + 量化数据]
2. 评估要点：[客户提到的最关心的 2-3 个评估维度]
3. 时间表：[客户提到的关键节点]

我们承诺的下一步：
- [Action 1，谁，什么时候完成]
- [Action 2]

如有遗漏或需要补充，请您指正。期待 [下次会议时间] 的进一步交流。

[签名]
```

**铁律**：会后 24 小时内必发，48 小时之后客户对会议印象已模糊。

## 七、踩坑信号（识别风险）

| 信号 | 含义 | 应对 |
|------|------|------|
| 客户准时结束、不延长 | 兴趣度低 | 反思议程是否切中 |
| 客户全程不提对手 | 隐藏对手或没在认真选 | 直接问 "您还在看哪些方案" |
| 客户只让 Tech Buyer 来 | EB 没参与 → 决策权重低 | 主动要求高管会议 |
| 客户答应得太爽快 | 可能是礼貌而非真意 | 二访验证一致性 |
| Champion 突然回避 | 内部已变阵或被 reassign | 立即多线探查 |

## 八、与其他 Skill 的边界

| 选择 | 用前者 | 用后者 |
|------|-------|-------|
| `discovery-call` vs `user-research` | 售前商业语境（卖方-买方）| 产品研发语境（找需求做产品）|
| `discovery-call` vs `customer-success --mode onboarding` | 签约前需求挖掘 | 签约后实施动员 |
| `discovery-call` vs `pm-discovery` | 单一客户深度访谈 | PM 全流程的发现阶段（市场+多客户）|
| `discovery-call` vs `solution-architecture` | 第 1-2 次会议（搞清需求）| 第 3+ 次会议（架构方案落地）|
