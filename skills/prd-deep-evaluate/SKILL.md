# Prd Deep Evaluate — PRD 23 节深度评估

> 单一职责：基于 23 节企业模板对现有 PRD 做差距分析。
> 不做：通用 5 维度评分（→ `prd-quality-check`）、增量更新（→ `prd-incremental-update`）

> 评分基线：`templates/prd-template.md`（23 节标准）

## 三层评分清单

### 第一层：方向层（判断产品方向是否清晰）

| 检查项 | 标准 | 对应章节 |
|--------|------|---------|
| 文档信息完整 | 版本/作者/状态/评审人员是否齐全 | §1 |
| 需求背景清晰 | 当前问题/业务影响/用户痛点/建设必要性是否说明 | §2 |
| 产品目标量化 | 是否有可衡量指标（基线/目标值/衡量方式） | §3 |
| 用户角色明确 | 是否有具体角色画像（普通用户/管理员/审计），不是"所有人" | §4 |
| 范围边界清晰 | 是否明确说了"本期不做"以及原因 | §5 |

### 第二层：结构层（判断文档结构是否完整）

| 检查项 | 标准 | 对应章节 |
|--------|------|---------|
| 功能位置 | 一级菜单/二级菜单/入口位置是否定义 | §6 |
| 前置依赖 | 前置条件 + 依赖服务表是否齐全 | §7 |
| 业务流程图 | 是否有 Mermaid 主流程 + 分支 + 异常流程 | §8 |
| 优先级功能列表 | 是否有 🔴/🟡/⚪ 的功能分级 | §5.1 |
| 关键页面线框图 | 核心页面是否有 ASCII 布局草图 | §10 |
| 功能详情章节 | 每个核心功能是否有独立详细描述 | §9 |

### 第三层：细节层（判断细节是否足够支撑开发）

| 检查项 | 标准 | 对应章节 |
|--------|------|---------|
| 状态完整性 | 每个功能是否覆盖 6 种状态（默认/加载/成功/失败/禁用/空） | §9.x.2 |
| 边界条件 | 是否覆盖空输入/溢出/网络/权限/并发/格式 | §9.x.3 |
| 字段说明 | 字段表是否含控件/类型/长度/必填/默认/校验提示 | §11 |
| 按钮状态 | 不同页面模式（查看/编辑/加载/无权限）下按钮状态是否定义 | §12 |
| 状态流转 | 是否有状态机图 + 流转表 | §13 |
| 校验规则 | 必填/格式/枚举/长度/唯一性/权限 — 失败提示是否齐全 | §14 |
| 文案规范 | 通用提示文案 + 技术/用户文案分离 | §15 |
| 安全合规 | 脱敏/审计/加密/凭证有效期/限流是否覆盖 | §16 |
| 非功能需求 | 性能/可用性/兼容性/可观测性/可扩展性 | §17 |
| 埋点指标 | 埋点事件 + KPI 是否定义 | §18 |
| 接口数据 | 接口列表 + 数据字段表是否齐全 | §19 |
| 验收标准 | 功能验收 + 安全质量验收 checklist | §20 |

## 输出格式

```markdown
## PRD 23 节评估报告

**总分**：[X]/10

### 第一层：方向层 — [X]/10
✅ [通过项]：[简短说明]
❌ [问题项]：[具体问题描述] → 建议：[如何改进]
⚠️ [待完善项]：[说明]

### 第二层：结构层 — [X]/10
（同上格式）

### 第三层：细节层 — [X]/10
（同上格式）

---

## 主要问题汇总（按优先级）
1. [最重要的问题] — 影响：[说明]
2. [次要问题]
3. [可选改进项]

---

## 后续行动选项
A. 直接补充/修改薄弱的章节（调用 `prd-implementation-draft` 增补）
B. 对整个文档进行全面重写（调用 `prd-concept-draft` + `prd-implementation-draft`）
C. 只给出改进建议，你自己来修改
D. 做小范围变更（调用 `prd-incremental-update`）
```
