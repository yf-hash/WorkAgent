# Churn 流失分析 + Save Playbook

## 核心定义

| 类型 | 定义 |
|------|------|
| **Logo Churn** | 客户完全离开（账号关闭）|
| **Revenue Churn** | 总 ARR 下降（含降级 + 减席位）|
| **Net Revenue Retention（NRR）** | 100% + 升级 - 降级 - 流失 |
| **Gross Revenue Retention（GRR）** | 100% - 降级 - 流失（不含升级）|
| **Voluntary Churn** | 客户主动选择离开 |
| **Involuntary Churn** | 信用卡失败 / 自动续约失败 / 合规违约等 |
| **Product Churn** | 客户留下但不再使用核心功能 |

## 健康度目标基线（B 端 SaaS 常见标准）

| 指标 | 优秀 | 良好 | 警告 | 危险 |
|------|------|------|------|------|
| GRR | > 95% | 90-95% | 85-90% | < 85% |
| NRR | > 120% | 100-120% | 90-100% | < 90% |
| Logo Churn（年） | < 5% | 5-10% | 10-15% | > 15% |

## 流失分类与归因

### 第 1 步：分类（5 类）

| 类别 | 占比目标 | 性质 | 典型缓解 |
|------|----------|------|----------|
| 1. 产品不达标 | < 30% | 可改 | 产品改进 |
| 2. 价格 / 商业模型 | < 20% | 可改 | 定价调整 |
| 3. 客户成功失败 | < 20% | 可改 | CSM 改进 |
| 4. 客户内部变化 | 不可控 | 接受 | 关系维护 |
| 5. 竞品迁移 | < 10% | 部分可改 | 差异化 |

### 第 2 步：根因 5 Whys

对每个流失客户做：

```
为什么流失？→ "用得少"
为什么用得少？→ "没解决核心问题"
为什么没解决？→ "我们方案在场景 X 不够好"
为什么场景 X 不够好？→ "我们 PRD 阶段没收集这场景"
为什么没收集？→ "ICP 偏移，这类客户不在画像里却卖给他们了"
```

### 第 3 步：流失漏斗

```
全部客户
   ↓
风险客户（CHI ≤ 40）
   ↓
触发 Save Play
   ↓
分支 1：挽留成功 → 留存
分支 2：挽留失败 → Logo Churn
分支 3：自然到期 → 不续约
```

## CHI（客户健康指数）设计

CHI 是 0-100 的合成分数，每周自动计算：

```
CHI = 
  使用频率得分 × 30%
+ 功能广度得分 × 20%
+ 关键事件得分 × 15%  (登录 / 出席培训 / 续约对话)
+ 反馈情绪得分 × 15%  (NPS / 工单情绪)
+ 财务行为得分 × 10%  (按时付款 / 加购)
+ Champion 得分 × 10%  (Champion 在职 + 活跃)
```

### CHI 分层与行动

| CHI 区间 | 标签 | 行动 |
|----------|------|------|
| 80-100 | Healthy（健康）| 升级机会 / 推荐 / Case Study |
| 60-79 | Stable（稳定）| 维持现状 + QBR |
| 40-59 | At Risk（风险）| Save Play 1（CSM 主动联系）|
| 20-39 | Critical（危急）| Save Play 2（销售 + CSM + PM 三方）|
| 0-19 | Lost（基本失去）| Save Play 3（管理层介入）|

## Save Playbook（按风险等级）

### Save Play 1：At Risk（CSM 主动）

**触发**：CHI 40-59，连续 2 周。

**Day 0**（同天行动）：
- CSM 拉取使用数据 + 工单 + 健康度看板
- CSM 发"关心邮件"约电话（不要叫"挽留电话"）
- 准备 2-3 个针对性建议

**Day 7**（1 周内）：
- 30 分钟客户电话：听问题、给建议、约定下一步
- 邮件总结 + Action Items

**Day 14-30**：
- 跟进 Action Items
- 提供专属培训 / 文档
- 引入产品团队解答深度问题

**Day 60**：
- 第二次评估，CHI 上升 → 转入 Stable
- CHI 仍下降 → 升级到 Save Play 2

### Save Play 2：Critical（多方协作）

**触发**：CHI 20-39，或客户明确表达不续约意向。

```
Day 0：
  CSM 通报销售 + PM + 管理层
  组成 Save Squad（3-5 人）
  分配每人 1 个 Action

Day 7：
  Squad 集体复盘
  发起客户高层会议申请

Day 14：
  客户高层会议
  - 我们 CXO 出席
  - 客户决策人出席
  - 焦点：诚恳听 + 给一个承诺

Day 30-60：
  执行客户承诺
  CHI 周更
  每 2 周 Squad 复盘
```

### Save Play 3：Lost / 即将到期

**触发**：CHI < 20 或客户已通知不续约。

- 不再花大力气挽留
- 做漂亮的"离场":
  - 数据导出协助
  - 离场访谈（Win-Back 数据金矿）
  - 关系维护（写在 Win-Back 名单）
- 6 个月后 Win-Back 尝试

## Win-Back（回流）策略

流失客户 6-12 个月后：

| 时机 | 触发 |
|------|------|
| 你方有重大产品改进 | "我们去年您提的 X 问题已经解决了"|
| 竞品出问题 | "听说您切换的方案 ___，我们能协助" |
| 客户 Champion 跳槽 | 跟到新公司续 |
| 客户业务扩张 | 客户预算重新启动 |

Win-Back 转化率 B 端通常 5-15%，远高于冷启动新客户。

## 反模式

- ❌ **流失发生后才发现**：CHI 不到位
- ❌ **CSM 一人扛**：没有 Save Squad 机制
- ❌ **客户说"价格贵"就调价**：80% 案例真实根因不是价格
- ❌ **不做离场访谈**：丢失最值钱的数据
- ❌ **Win-Back 名单只有名字没有触发条件**：等于没名单
