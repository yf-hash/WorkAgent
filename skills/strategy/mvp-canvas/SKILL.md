# MVP Canvas — MVP 设计画布知识库

把"做最小可行版本"从口号变成可执行的方法论。

---

# 一、MVP 不是什么（最常见误区）

```
❌ MVP = 功能少的产品                ← 量级误区
❌ MVP = Beta 版/内测版               ← 阶段误区
❌ MVP = 凑合能用的丑陋版本           ← 质量误区
❌ MVP = 技术可行性验证              ← 视角误区（混淆 PoC）
❌ MVP = 给少数用户试用的版本         ← 范围误区

✅ MVP = 用最小成本验证最致命假设的产品形态
```

**核心问题**：你要验证的"最致命假设"是什么？

---

# 二、MVP / MLP / RAT 三个层级

| 概念 | 全称 | 目的 | 时机 |
|------|------|------|------|
| **RAT** | Riskiest Assumption Test | 验证单一最致命假设 | 想法刚出 |
| **MVP** | Minimum Viable Product | 验证产品-用户契合度 | 早期 |
| **MLP** | Minimum Lovable Product | 验证愿意付费/推荐 | PMF 后 |

```
想法 → RAT 验证 → 假设成立？
                     ├─ 否 → Pivot 或放弃
                     └─ 是 → 做 MVP → 用户来用？
                                       ├─ 否 → 调整 → 再做 MVP
                                       └─ 是 → 做 MLP → PMF
```

# 三、Riskiest Assumption Test（最致命假设）

## 3.1 假设盘点矩阵

```
              | 致命度高              | 致命度低
  ────────────┼──────────────────────┼─────────────────────
  验证成本低   | ⭐ 优先验证          | 顺手验证
  验证成本高   | 想办法降本验证        | 暂时不管
```

## 3.2 致命度评分

```
对每个假设打 3 个分（1-5）：
  - 商业影响：假设错了对业务多致命？
  - 不确定度：现在我们多不确定？
  - 验证成本：验证它要多少时间/钱？

致命度 = (商业影响 × 不确定度) ÷ 验证成本
```

## 3.3 典型假设清单（按类型）

```
价值假设（用户真的想要吗）：
  - 这个痛点真的存在且足够痛
  - 用户愿意改变现有行为
  - 用户能感知到我们的价值

增长假设（如何获取/留存用户）：
  - 我们能以可承受的 CAC 获客
  - 用户用过后会留下来（留存假设）
  - 用户会推荐给别人（病毒系数）

商业假设（能赚到钱吗）：
  - 用户愿意为此付费
  - 价格点合理（既不太低也不太高）
  - 单位经济模型成立（LTV > CAC × 3）

可行假设（我们能做出来吗）：
  - 技术能力达标
  - 关键合作伙伴/资源可获得
  - 监管/合规可通过
```

# 四、MVP 九种类型选择

按"伪装度"和"投入"递增：

```
1. 解释性视频（Explainer Video）
   案例：Dropbox 的 3 分钟视频，一夜涨 7.5 万注册
   适合：产品概念抽象、需要先吸引早期 Adopter

2. 落地页（Landing Page / Smoke Test）
   案例：Buffer 一开始只是个落地页 + "立即注册"
   适合：验证用户是否愿意留邮箱/付费

3. 众筹（Crowdfunding）
   案例：Pebble Watch、Oculus Rift
   适合：硬件、有形产品、需要预付费验证

4. 数字原型（Digital Prototype）
   工具：Figma + Maze / Penpot + Useberry
   适合：验证交互流程，不需要真实数据

5. 门童 MVP（Concierge）
   案例：Food on the Table 创始人亲手为每个用户买菜
   适合：服务流程未自动化，先手工跑通

6. 绿野仙踪 MVP（Wizard of Oz）
   案例：Zappos 创始人接单后跑去店里买鞋寄出去
   适合：用户感受是自动化，背后是手工

7. 单功能 MVP（Single Feature）
   案例：Foursquare 只有"签到"一个功能
   适合：聚焦单点价值
   适合：原产品已存在，验证某个新功能

8. 拼凑 MVP（Piecemeal / Frankenstein）
   案例：Groupon 用 WordPress + AppleScript + 邮件凑出来
   适合：用现成工具拼接最小流程

9. 混凝土 MVP（Concrete / Single Use Case）
   案例：早期 Airbnb 只租气垫床
   适合：选最小细分市场跑通
```

**选择决策树**：
```
能用一句话讲清楚价值？
  ├── 是 → 落地页 或 解释视频
  └── 否 → 数字原型

需要硬件/物流？
  ├── 是 → 众筹 或 门童
  └── 否 → 继续

后端复杂/未自动化？
  ├── 是 → 绿野仙踪
  └── 否 → 单功能 或 拼凑

用户群非常细分？
  └── 混凝土 MVP
```

# 五、Build-Measure-Learn 循环

```
        IDEAS
          │
          ▼
        BUILD
          │
          ▼
       PRODUCT
          │
          ▼
       MEASURE
          │
          ▼
        DATA
          │
          ▼
        LEARN
          │
          └────► 新 IDEAS
```

每轮循环 ≤ 2 周。学习产出三选一：
1. **Persevere**（坚持）：假设成立，进入下个验证
2. **Pivot**（转向）：假设不成立但发现新机会
3. **Stop**（终止）：假设不成立，无替代方向

# 六、伪 MVP 反模式识别

| 反模式 | 症状 | 修正 |
|--------|------|------|
| **大爆炸 MVP** | 想做的功能都做，只是少数能跑 | 砍到只剩 1 个核心假设 |
| **完美主义 MVP** | UI 抛光、动画精致，但没用户来 | 先验证有用，再做漂亮 |
| **PoC 当 MVP** | 技术能跑通，但用户不知道为啥要用 | 加上用户视角的价值传递 |
| **金鱼缸 MVP** | 只给团队/亲友用 | 触达真实陌生用户 |
| **永远 MVP** | 已经发布 1 年还叫 MVP | 设定退出标准 |
| **数据失明 MVP** | 没埋点、没指标 | MVP 上线时埋点已就绪 |

# 七、MVP 验证退出标准

每个 MVP 上线前必须明确：

```
退出条件 A（成功）：
  - 假设验证：[指标]达到[数值]
  - 例：注册转化率 ≥ 15%（30 天内）
  - 例：留存曲线在 D7 后趋于平缓且 ≥ 20%
  - 例：用户主动付费数 ≥ 50 个

退出条件 B（失败）：
  - 假设证伪：[指标]低于[数值]
  - 例：访问 → 注册 < 3%
  - 例：D1 留存 < 10%
  - 进入 Pivot 决策：A. 调整 MVP 再测 B. 转向新方向 C. 终止

时间盒：
  - MVP 验证最长周期 [N 周]
  - 到期未达成 A 也未触发 B → 进入复盘决策
```

# 八、MVP Canvas 模板（一页纸）

```
┌─────────────────────────────────────────────────────────────┐
│ MVP CANVAS: [产品/功能名]            日期：YYYY-MM-DD          │
├─────────────────────────────────────────────────────────────┤
│ 1. 最致命假设                                                │
│    "如果____不成立，整个想法都站不住脚"                        │
├─────────────────────────────────────────────────────────────┤
│ 2. 验证成功定义           │ 3. 验证失败定义                    │
│    [指标 ≥ 数值]          │    [指标 < 数值]                  │
├───────────────────────────┴──────────────────────────────────┤
│ 4. MVP 类型 + 一句话描述                                       │
│    [落地页/原型/门童/...] : [描述]                             │
├─────────────────────────────────────────────────────────────┤
│ 5. 包含的能力（5 项以内）   │ 6. 不包含的能力（明确排除）        │
│    ✅ ...                  │    ❌ ...                         │
├─────────────────────────────────────────────────────────────┤
│ 7. 早期用户来源            │ 8. 验证时长盒                     │
│    [渠道 + 触达方式]        │    [N 周]                        │
├─────────────────────────────────────────────────────────────┤
│ 9. 关键风险与应对                                             │
│    - [风险]：[应对]                                          │
├─────────────────────────────────────────────────────────────┤
│ 10. 学习产出（验证后填）                                       │
│     [Persevere / Pivot / Stop] + [下一步]                    │
└─────────────────────────────────────────────────────────────┘
```
