# Bid Check — 标书 Phase 6 合规与一致性核查

> 单一职责：标书七阶段第 6 阶段（合规 + 一致性 + 查重）。
> 上游：`bid-review` 评审通过的版本。
> 下游：`bid-export` 最终定稿移交。

## 合规性核查

- 对照招标文件逐条核查实质性响应，输出 ✅/❌ 符合性清单
- 废标条款确认（资质、保证金、格式）
- 格式规范检查（页数、字体、签章）

### 合规性核查清单

```markdown
## 实质性响应（🔴 红色废标项）
逐条对照「最终技术要求清单」中的红色条款：
- CL-001：✅ 已响应于第 X 章
- CL-002：✅ 已响应于第 X 章
- ...

## 废标条款
- [ ] 资质要求（注册资本 / 认证 / 业绩）
- [ ] 保证金支付凭证
- [ ] 投标文件格式（份数 / 装订 / 密封）
- [ ] 签章完整性（投标函 / 授权书 / 每页骑缝章）
- [ ] 联合体协议（如有）

## 格式规范
- [ ] 字体（招标方指定字号）
- [ ] 页数（不超过上限）
- [ ] 页眉页脚 / 图表编号
- [ ] 目录 / 页码 / 索引完整
```

## 一致性验证

| 类型 | 检查内容 |
|------|----------|
| 术语一致性 | 全文关键名词统一（产品名/技术名/客户行业术语） |
| 数据一致性 | 数字、日期、金额前后对照（标书内 vs 偏离表 vs 商务标） |
| 逻辑闭环 | 风险提出 → 应对措施存在性检查 |
| 承诺一致性 | 技术标与商务标承诺无矛盾 |

### 一致性扫描脚本（伪代码）

```python
# 术语一致性
terms = ["产品 X", "Product X", "产品 X 平台"]  # 应统一为一种
check_terms_consistency(text, terms)

# 数据一致性
extract_all_numbers(text)
check_cross_reference(技术标_data, 商务标_data, 偏离表_data)

# 承诺一致性
extract_promises(text)  # SLA / 培训 / 售后 / 实施周期
check_no_contradictions(promises)
```

## 查重检测风险分级

| 相似度 | 风险级别 | 处理 |
|--------|----------|------|
| >70% | 🔴 高风险 | 必须改写 |
| 40–70% | 🟡 中风险 | 建议改写 |
| <40% | 🟢 低风险 | 可接受 |

## 输出物

- `bid-check-report-[项目名].md`

## 修改后必须重核

任何修改后，相关章节的合规性 / 一致性 / 查重必须重新核查（避免按下葫芦浮起瓢）。
