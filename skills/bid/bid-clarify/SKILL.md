# Bid Clarify — 标书 Phase 2 澄清

> 单一职责：标书七阶段第 2 阶段（澄清问题与最终清单确认）。
> 上游：`bid-analyze` 的歧义条款清单。
> 下游：`bid-outline` 设计大纲。

## 核心原则

> 第 2 阶段澄清确认后的《最终技术要求清单.xlsx》是后续所有阶段的唯一依据。

## 内部评审辅助

- 逐条技术能力评估：能满足 / 有难度 / 需澄清
- 标注高风险项（废标风险优先）
- 生成内部评审会议议程模板

### 内部评审会议议程模板

```markdown
# [项目名] 技术评审会议

## 一、议程
1. 招标文件三色分析过审（30 min）
2. 红色废标项逐条评估（45 min）
3. 高分项能力差距讨论（30 min）
4. 澄清问题清单确认（15 min）

## 二、参会
- 技术负责人 / 售前架构师 / 产品经理 / 法务

## 三、决议事项
- [ ] 投/弃标决策
- [ ] 高风险项目处理方案
- [ ] 澄清问题清单定稿
- [ ] 各章节责任分配
```

## 正式澄清问题整理规范

- 格式：客观、中立、无引导性语气
- 排序：废标风险 > 评分影响 > 一般疑问
- 编号：CL-001 / CL-002 ...

> ⚠️ 不要在正式澄清前承诺任何无法实现的功能。

### 澄清问题模板

```markdown
[CL-001] 关于第 X 章第 X 条 "[原文]"

我方理解：[A 解读 / B 解读]
请确认：
A. 是否要求 [具体场景 1]
B. 是否包括 [具体场景 2]
C. 验收口径以 [标准 1] 还是 [标准 2] 为准
```

## 澄清回复解读

- 解析招标方正式澄清文件，逐条映射回原需求清单
- 标注变更条款，更新《最终技术要求清单.xlsx》

## 输出物

- `技术澄清问题（正式版）.docx`
- `最终技术要求清单.xlsx` — **后续所有阶段以此为准**
- `内部评审会议纪要.md`

## 关键检查

- [ ] 所有红色废标项已逐条标注响应方式
- [ ] 所有澄清问题已收到正式回复
- [ ] 最终清单已经内部评审通过
- [ ] 投/弃标决策已确认
