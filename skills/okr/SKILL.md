# OKR — 目标与关键结果知识库

把"季度目标制定 + 跟踪 + 评分"变成可重复的协作流程。

---

# 一、OKR 的"四个基石"

```
F.A.C.T.

Focus      → 聚焦 3-5 个 O，不是 20 个
Alignment  → 上下对齐 + 横向对齐
Commitment → 公开承诺、透明可追踪
Tracking   → 周/月跟踪、季末评分
```

—— John Doerr《Measure What Matters》

---

# 二、O 与 KR 的写法

## 2.1 Objective（O）

```
✅ 鼓舞性（让人想完成）
✅ 定性的方向（不是数字）
✅ 1 句话讲清
✅ 季度内可衡量是否达成

❌ "提升用户体验"           ← 没方向、不衡量
❌ "做完所有 P0 需求"       ← 是任务列表
✅ "让产品成为用户日常工具的首选"
```

## 2.2 Key Result（KR）

```
✅ 可量化（数字 / 百分比 / 是否）
✅ 是结果（Outcome）不是动作（Output）
✅ 有截止时间（季度末或更早）
✅ 2-5 个 / 一个 O（推荐 3）

❌ "发布 v2 版本"                    ← 这是动作
❌ "组织 5 场用户访谈"                ← 这是动作
✅ "v2 上线后 30 天，主漏斗转化 ≥ 18%"  ← 这是结果
✅ "通过用户访谈识别 1 个能 +5pp 留存的杠杆" ← 结果导向
```

## 2.3 Action vs Outcome 自检

| ❌ 动作型 | ✅ 结果型 |
|----------|----------|
| 发布 3 个新功能 | 用户对新功能"非常满意" ≥ 60% |
| 完成 10 次用户访谈 | 从访谈中提取 1 个被验证的杠杆 |
| 重构搜索 | 搜索点击率从 20% → 35% |
| 招聘 2 名工程师 | 团队 Velocity 从 30 SP → 45 SP |

# 三、Committed vs Aspirational

```
Committed（承诺型）：
  - 必须 100% 完成（评分 ≥ 0.7 算成功）
  - 资源已就位
  - 不达成是大问题

Aspirational（拉伸型）：
  - 鼓励"够一够"才能达成
  - 评分 0.6-0.7 已是优秀
  - 不达成是常态，重在学习
```

经典占比：60-70% Committed + 30-40% Aspirational。

# 四、对齐链路

## 4.1 自上而下 + 自下而上

```
公司 OKR （CEO + 高管层）
   ↓ 支撑                           ↑ 反馈
团队 OKR （部门 / 产品 / 工程 / GTM）
   ↓ 支撑                           ↑ 反馈
个人 OKR （按需，不强制全员）
```

## 4.2 横向对齐

跨团队的 OKR 互相支持时，应：
```
1. 列依赖关系（PM OKR 依赖 Engineering 在 W4 交付）
2. 双方明确签字
3. 跨团队定期同步
```

## 4.3 OKR 不应是

```
❌ 个人考核（一旦考核，团队会保守起步价值）
❌ 工资奖金挂钩（同上）
❌ 周报模板（OKR 是季度战略，不是日常进度）
❌ 上级下达（应该团队共创）
```

# 五、跟踪节奏

```
季度初 W0：起草 + 跨团队对齐
W1-W4：每周 Quick Check-in（10 分钟）
  - 每 KR 一句话：进度 / 阻塞 / 下一步
W5：月度 Review（30-60 分钟）
  - 数字 + 故事
  - 调整资源 / 重新优先级
W6-W9：每周 Check-in
W10：月度 Review
W11-W12：每周 Check-in，季末加紧
W13：季度评分 + 复盘 + 下季度起草
```

## 评分（季末）

```
0.0 ─ 0.3：未达成
0.4 ─ 0.6：部分进展
0.7 ─ 1.0：达成（Committed 应 ≥ 0.7）

综合 O 评分 = KR 评分平均

注意：
  - 1.0 全是不健康的（说明目标定低了）
  - 0.5 平均是健康（说明在拉伸）
  - 不要把评分当 KPI 考核
```

# 六、OKR vs KPI vs MBO

| 维度 | OKR | KPI | MBO |
|------|-----|-----|-----|
| 目的 | 聚焦战略目标 | 监控运营健康 | 任务分配 + 绩效 |
| 周期 | 季度 / 年度 | 持续监控 | 年度 |
| 与考核关系 | 不挂钩（建议） | 不挂钩 | 强挂钩 |
| 目标性质 | 鼓舞 + 拉伸 | 健康线 + 阈值 | 任务完成 |

健康的组织：OKR + KPI 同时存在
- OKR：让你"前进"
- KPI：让你"不出事"

# 七、OKR 反模式

## 7.1 数量过多

```
❌ 5 个 O × 5 KR = 25 个目标
✅ 2-3 个 O × 3 KR = 6-9 个目标
```

## 7.2 KR 是动作

```
❌ KR：发布 5 个新功能
✅ KR：新功能上线后 D30 留存 ≥ 40%
```

## 7.3 与考核挂钩

```
后果：团队保守起步价
解药：OKR 评分 ≠ 绩效评级
```

## 7.4 对齐流于形式

```
❌ 上层"提升用户体验"，下层"提升用户体验"
✅ 上层"NPS +20"，下层"召回流失用户 + 上线 Onboarding"
```

## 7.5 Cascading 太多层

```
❌ 公司 → 部门 → 小组 → 个人 全套 OKR
✅ 公司 + 部门即可，小组用 Sprint Goal，个人用 1 on 1
```

```markdown

**最后更新**：YYYY-MM-DD

## 上层 OKR（链接）
> 公司 O：[简述]

## 我们的 OKR

### O1：[鼓舞性目标]（支撑公司 O / KR_X）

| KR | 类型 | 起点 | 目标 | 当前 | Owner |

- ...
```
