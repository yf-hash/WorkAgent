# content-templates — 八大文体模板库

> 本 skill 被 `/content-generate` 命令调用。生成时通过 `--style {id}` 分派到对应文体章节。

## 通用生成规范（所有文体）

### 必须遵循

1. **引用素材池**：任何数字 / 能力 / 客户 / 案例 描述必须来自 M2 素材池
2. **不引用素材池的**：明确标 `[AI 合成 - 请人工确认]`
3. **不越过 forbidden 清单**：素材池的禁止项严禁出现
4. **保留出处**：每个关键事实来自哪份文档 / 哪个章节

### 通用禁用词（合规红线）

**绝对化用词**（广告法）：
```
最（最好 / 最佳 / 最强 / 最先进）
第一（业内第一 / 全球第一 / 国内第一）
唯一（唯一 / 独家 / 首个）
100%（100% 满意 / 100% 安全）
永远 / 绝对 / 完美 / 完全
```

**替代用语**：
- "最先进" → "行业领先" / "先进水平"
- "第一" → "领先" / "位居前列"
- "唯一" → "少有" / "较早"
- "100% 安全" → "全链路安全" / "多重安全保障"

**禁止行业措辞**（金融 / 医疗 / 保险 类客户内容）：
```
稳赚不赔 / 无风险 / 保底
根治 / 治愈 / 特效
保险特有：保证 / 承诺 / 免除责任
```

## 文体 1：产品推广文（promo）

### 章节结构

```
1. 标题（吸引点击，含关键卖点）
2. 引言（1 段，行业趋势 / 客户困境）
3. 产品定位一句话
4. 核心卖点（3-5 个，每个含场景 + 收益）
5. 客户价值链（获取 → 使用 → 收益）
6. 差异化对比（含 / 不含竞品名，取决于策略）
7. 典型场景（2-3 个客户故事）
8. 行动号召（CTA）
```

### 语气规范
- 商业化、有画面感、场景化
- 避免技术黑话
- 面向决策者 = 强调收益 / ROI

### 长度分配（1500 字为例）
- 引言：150 字
- 产品定位：50 字
- 核心卖点：500 字（每个 100-150）
- 客户价值链：200 字
- 差异化：200 字
- 典型场景：300 字
- CTA：100 字

### 必备要素
- [ ] 一句话价值主张
- [ ] 3 个以上具体收益（含数字）
- [ ] 至少 1 个客户场景
- [ ] 清晰 CTA

## 文体 2：产品解决方案文（solution-doc）

### 章节结构

```
1. 客户业务背景
2. 客户业务挑战 / 痛点（3-5 个）
3. 我方解决方案概览
4. 能力对应关系（痛点 → 我方能力表）
5. 部署形态（云 / 私有 / 混合）
6. 典型应用场景（分角色）
7. 客户收益（定性 + 定量）
8. 实施与服务
9. 后续建议
```

### 语气规范
- 专业、务实
- 面向 IT + 业务 = 平衡技术与业务

### 长度分配（3000 字）
- 业务背景 + 挑战：600 字
- 方案概览：400 字
- 能力对应表：600 字（表格 + 说明）
- 部署形态：300 字
- 应用场景：600 字
- 收益：300 字
- 实施：200 字

### 必备要素
- [ ] 痛点 → 能力对照表
- [ ] 部署形态说明
- [ ] 至少 2 个场景
- [ ] 收益含定量指标

## 文体 3：产品技术白皮书（tech-whitepaper）

### 章节结构

```
1. 摘要（Executive Summary）
2. 技术背景与挑战
3. 整体技术架构（图 + 分层说明）
4. 核心模块技术原理
   4.1 模块 A：原理 + 关键算法 + 数据流
   4.2 模块 B：...
   4.3 模块 C：...
5. 关键技术指标
   5.1 性能
   5.2 安全
   5.3 可扩展性
6. 安全设计
7. 性能说明（含压测数据）
8. 技术局限性 & 未来演进
9. 术语表 / 参考文献
```

### 语气规范
- 严谨、技术性强
- 面向技术受众 = 允许技术黑话，需要有严谨的数字与图表
- 承认局限（专业感的关键）

### 长度分配（8000 字）
- 摘要：300 字
- 背景与挑战：700 字
- 整体架构：1000 字（含 Mermaid）
- 核心模块：3000 字（每模块 800-1200）
- 技术指标：1000 字
- 安全设计：700 字
- 性能：600 字
- 局限：500 字
- 术语：200 字

### 必备要素
- [ ] 至少 1 张 Mermaid 架构图
- [ ] 每个核心模块含"原理 + 数据流"
- [ ] 关键性能指标含具体数字（来自 tech-metrics）
- [ ] 承认技术局限
- [ ] 术语表

## 文体 4：产品 PPT（ppt）

### 章节结构（20 页典型）

```
1. 封面
2. 议程
3-5. 客户背景与挑战（3 页）
6-8. 我方方案概览（3 页）
9-14. 核心能力深入（6 页，每个能力 1-2 页）
15-16. 差异化对比（2 页）
17-18. 客户案例（2 页）
19. 实施建议 & 下一步
20. Q&A / 联系方式
```

### 页面规范
- 每页 ≤ 5 个 bullet
- 每 bullet ≤ 15 字
- 视觉优先（配图建议）
- 备注话术（讲解要点）

```json

      "subtitle": "面向政企的分布式沙箱调度平台",
      "logo_position": "top-left",
      "note": "开场问候 + 议程简介"
    },
    {
      "page": 3,
      "type": "content",
      "title": "客户面临的三大安全挑战",
      "bullets": [
        "漏洞发现滞后 → 平均 45 天暴露窗口",
        "验证成本高 → 5 人团队全年验证 200 个漏洞",

```

### 必备要素
- [ ] 每页有 title / bullets / visual_suggestion / note
- [ ] 逻辑闭环（问题 → 方案 → 证据 → 行动）
- [ ] 至少 1 页架构图（visual_suggestion 明确）
- [ ] Q&A 页含常见问题预设

## 文体 5：产品解决方案白皮书（solution-whitepaper）

### 章节结构

```
1. Executive Summary（1-2 页）
2. 行业背景与趋势
   2.1 市场规模与增长
   2.2 政策 / 合规趋势
3. 行业业务痛点
   3.1 常见痛点 3-5 类
   3.2 客户现状调研（引用素材）
4. 完整解决方案
   4.1 方案定位
   4.2 业务架构
   4.3 技术架构
   4.4 部署模式
5. 落地路径
   5.1 分阶段实施
   5.2 里程碑
   5.3 客户参与度
6. 案例参考
   6.1 案例 A
   6.2 案例 B
7. 收益价值
   7.1 业务收益
   7.2 技术收益
   7.3 ROI 测算
8. 实施建议
9. 附录：术语 / FAQ
```

### 语气规范
- 系统、正式、有品牌感
- 面向客户决策者 + 技术负责人
- 允许一定营销笔调，但主体保持专业

### 长度分配（12000 字）
- Summary：500
- 行业背景：1500
- 业务痛点：1500
- 完整方案：4000
- 落地路径：1500
- 案例：1500
- 收益：1000
- 实施建议：300
- 附录：200

### 必备要素
- [ ] Executive Summary（1-2 页可独立看）
- [ ] 行业数据引用（含来源）
- [ ] Mermaid 业务 + 技术架构 2 张图
- [ ] 至少 2 个案例
- [ ] ROI 定量测算
- [ ] 分阶段落地路径

## 文体 6：产品活动推文（activity-tweet）

### 章节结构（公众号版）

```
1. 标题（吸引点击，含表情 or 数字）
2. 引子（一段有画面感的场景）
3. 核心亮点（3-5 个，每个 1-2 句）
4. 详情说明（图 + 文字）
5. 福利 / 行动号召
6. 引导下一步（阅读原文 / 扫码 / 添加）
```

### 语气规范
- 轻量、活泼、有网感
- 允许 emoji（🎉 🚀 💡 ✨）
- 段落短，配空行
- 用第二人称（"你"）
- 面向读者的收益 > 产品自夸

### 长度分配（1000 字）
- 标题：≤ 20 字
- 引子：150 字
- 亮点：400 字
- 详情：300 字
- 福利 + CTA：150 字

### 必备要素
- [ ] 3 个以上短段落分隔
- [ ] 至少 1 个 emoji（视品牌调性）
- [ ] 明确福利 or 收益
- [ ] 清晰 CTA

## 文体 7：企业 PR 稿（pr）

### 章节结构（新闻稿标准范式）

```
1. 导语（Lead，5W1H：Who / What / When / Where / Why / How）
   - 一段（3-5 句），核心信息全部在此
2. 事件背景
3. 核心信息深入（版本 / 功能 / 客户 / 数据）
4. 企业观点（引用创始人 / 高管 的话）
5. 产品亮点（3-5 个 bullet）
6. 展望（未来规划 / 战略方向）
7. 关于我们（Boilerplate）
8. 联系方式（媒体联系人 / 邮箱 / 电话）
```

### 语气规范
- 客观、正式、新闻体
- 第三人称 / 被动语态
- 引用有名有姓（避免"某某表示"）
- 避免营销词汇（"重磅""震撼")

### 长度分配（1000 字）
- 导语：150 字
- 背景：150 字
- 核心信息：300 字
- 企业观点：200 字（含引用）
- 亮点：150 字
- 展望：100 字
- 关于我们 + 联系：50 字

### 必备要素
- [ ] 导语含 5W1H
- [ ] 至少 1 段引用（含姓名 + 职位）
- [ ] "关于我们" 段落
- [ ] 媒体联系方式

## 文体 8：产品技术科普文（tech-popular）

### 章节结构

```
1. 是什么（一句话定义）
2. 解决什么问题（用户场景 + 痛点）
3. 怎么工作（技术原理，由浅入深）
   3.1 类比 / 比喻（帮助初学者）
   3.2 逐层深入
4. 举个例子（具体案例）
5. 局限与坑（承认边界）
6. 演进方向 / 拓展阅读
```

### 语气规范
- 通俗 + 专业平衡
- 大量使用类比 / 比喻
- 允许口语化，但保持技术准确
- 面向开发者 / 技术爱好者

### 长度分配（3000 字）
- 是什么：200
- 解决什么问题：500
- 怎么工作：1500
- 举例：500
- 局限：200
- 拓展：100

### 必备要素
- [ ] 至少 3 个类比 / 比喻
- [ ] 至少 1 段可运行的示例代码 or 具体流程
- [ ] 承认局限与坑
- [ ] 拓展阅读链接

## 通用生成后处理

生成初稿后，Agent 应自查：
- [ ] 是否符合文体规范章节结构
- [ ] 是否有绝对化用词（未过合规校验前先自查）
- [ ] 引用素材池的比例（越高越安全）
- [ ] 是否含禁止提及内容
- [ ] 篇幅是否在容忍范围内（± 20%）

## 反模式（生成时）

- ❌ 不看文体模板就写 —— 违规
- ❌ 引用不来自素材池的数字 —— 违规（等 M4 校验会打回）
- ❌ 用绝对化词 —— 违规（M4 会命中）
- ❌ PR 稿写成推文风 —— 违规
- ❌ 白皮书没有承认局限 —— 缺乏专业感
- ❌ PPT 没有 note 备注 —— 售前 / 汇报者不会用
