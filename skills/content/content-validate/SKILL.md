# content-validate — 内容五类校验工具箱

> 本 skill 被 `/content-validate` 命令调用。

## 一、事实一致性校验规则

### 遍历初稿的"事实"

以下类型的表述算"事实"，都要对比素材池：

| 类型 | 举例 |
|---|---|
| 具体数字 | "100 个沙箱"、"P95 500ms"、"500 家客户" |
| 产品能力 | "支持分布式调度"、"支持 SAP 集成" |
| 客户 / 案例 | "某银行客户"、"制造业头部客户" |
| 技术指标 | "国产化率 100%"、"等保三级" |
| 融资 / 团队 | "员工 500 人"、"融资 5000 万" |

### 判定规则

| 情形 | 判定 |
|---|---|
| 素材池有 + 完全一致 | ✅ |
| 素材池有 + 简化描述 | 🟡 |
| 素材池有 + 夸大描述 | 🔴 |
| 素材池有 + 完全冲突 | 🔴 |
| 素材池无 + 客观事实（如"AI 是未来趋势"） | ⚪ 合成，可保留 |
| 素材池无 + 具体数字 or 客户名 | ⚠️ 强烈建议核实 |

## 二、合规风险扫描词库

### 广告法（绝对化用词，🔴 高风险）

```
最（最好 / 最佳 / 最强 / 最先进 / 最快 / 最高 / 最全 / 最专业）
第一（业内第一 / 全球第一 / 国内第一 / 行业第一）
唯一（唯一 / 独家 / 首创 / 首个 / 领先第一）
100%（100% 满意 / 100% 安全 / 100% 可靠）
永远 / 绝对 / 完美 / 完全 / 全面 / 全部
彻底 / 顶级 / 王牌 / 极致 / 无敌
```

### 广告法（推断性用语，🟠 中风险）

```
必然 / 必定 / 肯定
稳赚不赔 / 无风险 / 保底
根治 / 治愈 / 特效
```

### 未授权披露（🔴 高风险）

依赖 M2 素材池的 forbidden 清单：
- 具体客户真名（除非授权）
- 内部估算数字
- 内部人员真名
- 未上线的探索性能力
- 竞品负面评价（可能被诉不正当竞争）

### 行业禁语（依受众）

**金融**：
```
保证收益 / 保本 / 保底
稳赚 / 无风险
承诺 / 免责
```

**医疗**：
```
根治 / 治愈 / 特效
最有效 / 独一无二疗法
```

**保险**：
```
保证 / 承诺免赔
独家责任 / 全额赔付（非合同条款）
```

**教育**：
```
包过 / 保证升学 / 100% 通过
```

## 三、文体风格评分规则

### 10 分制评分维度

对比 `content-templates` 里对应 style 的规范：

| 维度 | 权重 | 满分 |
|---|---|---|
| 章节结构完整 | 3 分 | 3 |
| 语气匹配（关键） | 3 分 | 3 |
| 长度在容忍范围 | 2 分 | 2 |
| 必备要素齐全 | 2 分 | 2 |

### 语气匹配（3 分）

对每种 style 检查"是否有该文体的特征词"：

| Style | 特征词（应有） | 反特征词（不应有） |
|---|---|---|
| promo | "价值 / 收益 / 场景" | "技术架构 / 算法 / 协议" |
| solution-doc | "痛点 / 方案 / 部署" | "文青 / emoji / 感叹号" |
| tech-whitepaper | "架构 / 算法 / 指标 / 局限" | "尊敬的 / 优惠 / 福利" |
| ppt | 有 title/bullet 结构 | 大段文字 |
| solution-whitepaper | "行业 / 落地 / ROI / 案例" | 过度技术黑话 |
| activity-tweet | emoji + 短段落 + "你 / 我们" | 严谨技术表述 |
| pr | 第三人称 / 引用 / 5W1H | 第一人称营销词 |
| tech-popular | 类比 / 比喻 / 举例 | 过度术语堆砌 |

**判定**：特征词占比 > 30% + 反特征词占比 < 5% → 3 分

## 四、完整性 checklist

依 style 的必备要素：

### promo
- [ ] 一句话价值主张
- [ ] 3+ 具体收益（含数字）
- [ ] 至少 1 客户场景
- [ ] 清晰 CTA

### solution-doc
- [ ] 痛点-能力对照表
- [ ] 部署形态说明
- [ ] 2+ 场景
- [ ] 收益含定量

### tech-whitepaper
- [ ] Mermaid 架构图
- [ ] 每模块含"原理 + 数据流"
- [ ] 关键指标含具体数字
- [ ] 承认局限
- [ ] 术语表

### ppt
- [ ] 每页有 title/bullets/visual/note
- [ ] 逻辑闭环
- [ ] 至少 1 页架构图
- [ ] Q&A 页含预设问题

### solution-whitepaper
- [ ] Executive Summary（1-2 页独立可看）
- [ ] 行业数据引用
- [ ] 2 张 Mermaid 架构图
- [ ] 2+ 案例
- [ ] ROI 定量测算
- [ ] 分阶段落地路径

### activity-tweet
- [ ] 3+ 短段落
- [ ] 至少 1 个 emoji（视调性）
- [ ] 明确福利 / 收益
- [ ] 清晰 CTA

### pr
- [ ] 5W1H 导语
- [ ] 至少 1 段引用（含姓名+职位）
- [ ] "关于我们" 段落
- [ ] 媒体联系方式

### tech-popular
- [ ] 3+ 类比 / 比喻
- [ ] 至少 1 段示例代码 or 具体流程
- [ ] 承认局限
- [ ] 拓展阅读

## 五、引用可追溯规则

对每条引用记录其 (Fact → Source) 映射：

```json
{
  "fact": "支持 100 个沙箱并发",
  "location": "§ 3.2",
  "source": {
    "found_in_pool": true,
    "material_id": "M-001",
    "material_source": "./output/pm-pipeline/vulnhunter-20260827/04-PRD.md § 3.2"
  }
}
```

- `found_in_pool: true` + `material_id`：✅ 引用可追溯
- `found_in_pool: false` + 是客观事实：⚪ AI 合成，可保留
- `found_in_pool: false` + 是具体数字 / 客户 / 案例：❌ 自定义假设，标记删除或核实

**关键指标**：可追溯率 = 有 material_id 的引用数 / 总引用数

## 六、总体判定规则

```python
def overall_verdict(results):
    if any_red_in(results.fact) or any_red_in(results.compliance):
        return "🔴 需重写"

    if results.style_score < 7:
        return "🔴 需重写"

    if results.completeness_missing_required > 0:
        return "🔴 需重写"

    if any_yellow_or_gray(results):
        return "🟡 有修改建议"

    return "✅ 通过"
```

## 七、反模式

- ❌ 无素材池却宣称"事实一致" —— 违规
- ❌ 校验后无关键行动清单 —— 违规
- ❌ 报告只列问题不给改写建议 —— 违规
- ❌ 🔴 项默认通过 —— 严重违规
- ❌ 文体评分没解释 —— 违规
- ❌ 引用可追溯率不算 —— 违规
