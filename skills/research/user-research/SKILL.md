# User Research — 用户研究知识库

把"做用户研究"从模糊期望变成可执行的方法论组合。

---

# 一、用户研究 vs 市场研究

```
用户研究（本知识库）：
  对象：单个用户 / 用户群
  关心：行为 / 动机 / 痛点 / Job-to-be-Done
  方法：访谈 / 问卷 / 卡片分类 / 旅程 / 画像
  输出：用户洞察 / 持续改进方向

市场研究（market-research）：
  对象：市场 / 行业 / 竞品
  关心：规模 / 趋势 / 竞争格局
  方法：竞品分析 / TAM / 行业报告
  输出：战略决策依据
```

新人 PM 最常犯错：把"市场研究"当"用户研究"做（看二手报告而不见真实用户）。

---

# 二、研究方法选择决策树

```
你想要什么？
  ├── 探索新机会，不知道用户痛在哪
  │   → 访谈（定性）
  │
  ├── 验证某个假设是否成立
  │   → 问卷（定量）
  │
  ├── 决定信息架构 / 导航分组
  │   → 卡片分类
  │
  ├── 看用户在使用流程中的痛点
  │   → 用户旅程地图
  │
  ├── 让团队对"目标用户"有统一画像
  │   → 用户画像
  │
  └── 早期产品找种子用户 / Founder
      → Founder Discovery（含 LinkedIn / Reddit 工具）
```

# 三、用户访谈

## 3.1 适用

```
✅ 0→1 探索（不知道痛点）
✅ 重大改版前（理解用户决策）
✅ 流失用户调研（为什么走）
❌ 验证规模（用问卷）
❌ A/B 选哪个（用实验）
```

## 3.2 研究问题设计

```
What do we NOT know?
  → 我们想了解但不确定的事

错误示例：
  ❌ "用户喜欢蓝色还是红色按钮？"（应该用 A/B）
  ❌ "用户每周用几次？"（应该看埋点）

正确示例：
  ✅ "用户在创建项目时遇到什么阻碍？"
  ✅ "用户决定续约 / 流失的关键时刻是什么？"
```

## 3.3 Screener（参与者筛选）

```
筛选漏斗：
  100 个邀请 → 30 个填问卷 → 15 个符合 → 10 个完成访谈 → 8 条有效

筛选维度：
  - 行为（用过 / 没用过）
  - 频率（每周 / 每月）
  - 角色（决策者 / 使用者）
  - 排除（员工 / 测试者 / 竞品员工）

激励：
  - C 端：¥100-300 现金 / 礼品卡
  - B 端：¥500-2000 / 行业洞察报告
```

## 3.4 访谈结构（45-60 分钟）

```
Phase 1: Warm-up（5min）
  破冰 + 自我介绍 + 目的告知 + 录音同意

Phase 2: 背景了解（10min）
  日常工作流 / 工具链 / 现有方案

Phase 3: 核心探索（25min）
  具体场景的故事化提问
  - "上次你 [行为] 是什么时候？能描述吗？"
  - "那次发生了什么？感受如何？"
  - "你怎么解决的？为什么这么做？"

Phase 4: 深挖追问（10min）
  - "为什么？"
  - "然后呢？"
  - "还有什么？"
  - "如果没有这个工具呢？"

Phase 5: 总结（5min）
  谢谢 + 后续联系 + 最终 1 个问题
```

## 3.5 访谈技巧

```
✅ DO：
  - 让用户讲故事（具体的过去事件）
  - 听 5 倍于说
  - "How do you feel about that?"
  - 沉默是金（让用户填补空白）

❌ DON'T：
  - 引导性问题（"你不喜欢 X 对吧？"）
  - 假设性问题（"如果有 X 你会用吗？"）
  - 推销产品
  - 反驳用户
```

## 3.6 分析框架

### 亲和图（Affinity Diagram）
```
1. 把每条访谈洞察写在便利贴
2. 团队一起把相似的归类
3. 给每类起名字
4. 找出 Top 3 主题
```

### JTBD 提取
```
当我 [情境]
我想要 [动机]
以便 [期望结果]

例：
  当我在跨时区开会
  我想要快速看到所有人空闲时间
  以便不用问每个人就能定时间
```

### 痛点强度评分
```
| 维度 | 1-5 分 |
|------|------|
| 频率：多久遇到一次 | |
| 影响：每次损失多少 | |
| 现有方案满意度 | |
| 愿意付费吗 | |
| 总分 | |

> 15 分 = 真痛点，值得做
< 10 分 = 弱需求，跳过
```

# 四、用户问卷

## 4.1 适用

```
✅ 验证假设的规模（多少人有这个痛点）
✅ 量化排序（哪个功能最想要）
✅ NPS / CSAT（满意度量化）
❌ 探索新机会（用访谈）
❌ 复杂决策原因（问卷答案肤浅）
```

## 4.2 题目类型

```
单选 / 多选：分类
量表（1-5 / 1-7 / 1-10）：程度
开放问题：补充洞察
矩阵：多维度评分
NPS：推荐度
排序：优先级
```

## 4.3 设计原则

```
✅ 题目数量 ≤ 10（多了流失）
✅ 单一问题（不要"你喜欢 A 还是 B 还是觉得没差？"）
✅ 中性措辞（不引导答案）
✅ 分支跳转（不相关的不问）
✅ 必填 ≤ 60%（让用户能跳过）

测试：
  - 内部 5 人试填（找歧义）
  - 50 个种子用户预测试
  - 大规模发出（≥ 200 才有统计显著性）
```

## 4.4 工具

```
- Tally / Typeform（C 端）
- Google Forms（免费）
- SurveyMonkey（专业）
- 腾讯问卷 / 金数据（中国）
- Qualtrics（企业）
```

# 五、卡片分类（Card Sort）

## 5.1 适用

```
✅ 决定网站 / App 的导航分组
✅ 设计信息架构
✅ 验证现有架构是否合理
```

## 5.2 三种方法

```
开放式（Open）：
  - 用户自己分类自己起名
  - 适合：从零设计 IA

封闭式（Closed）：
  - 我方给类别，用户分到类别
  - 适合：验证已有 IA

混合式（Hybrid）：
  - 我方给类别，用户可以新增
  - 适合：迭代改进
```

## 5.3 工具

```
- OptimalSort（专业）
- Maze（含其他方法）
- Miro（手工）
```

## 5.4 样本

```
开放式：≥ 30 人
封闭式：≥ 15 人
分析：聚类树状图（Dendrogram）
```

# 六、用户旅程地图（Journey Map）

## 6.1 结构

```
Phase   感知 → 考虑 → 决策 → 使用 → 推荐

每个 Phase：
  - User Action（用户做了什么）
  - Touchpoint（在哪个渠道 / 界面）
  - Thoughts（在想什么）
  - Emotions（情感曲线 😊 😐 😠）
  - Pain Points（痛点）
  - Opportunities（机会）
```

## 6.2 当前态 vs 理想态

```
当前态（Current State）：
  描述用户实际经历，含痛点

理想态（Future State）：
  我们目标设计的旅程

Gap：当前 - 理想 = 待改进项
```

## 6.3 应用

```
- Onboarding 优化
- 体验问题诊断
- 跨部门对齐（销售 / 产品 / 客服 谁负责哪段）
```

# 七、用户画像（Persona）

## 7.1 一个画像必备

```
- 名字 + 头像（让团队记得）
- Demographics（年龄 / 角色 / 公司规模）
- Goals（目标）
- Frustrations（挫败）
- Tech Comfort（技术熟悉度）
- A Day in the Life（典型一天）
- Quote（一句典型话）
```

## 7.2 数据驱动

```
✅ 基于 ≥ 10 次真实访谈
✅ 基于真实埋点 / CRM 数据
✅ 反映行为而非设想

❌ "我们想象的目标用户"
❌ 一个画像描述所有用户
```

## 7.3 画像数量

```
推荐 2-3 个（最多 5 个）
更多 → 团队记不住
更少 → 覆盖不全
```

# 八、Founder Discovery（创始人 / 早期用户发现）

## 8.1 适用

```
0→1 创业 + 找早期 Adopter：
  - 不知道目标用户在哪
  - 需要 5-10 个种子用户
  - 需要测试 PMF 假设
```

## 8.2 渠道

```
Reddit / HackerNews / Indie Hackers / V2EX
LinkedIn Sales Navigator
Product Hunt 创始人 / 早期用户
Twitter（Tech 圈）
垂直社群（飞书 / 微信群 / Slack 社群）
线下行业活动
```

## 8.3 触达脚本

```
"Hi [名字]，我看到你在 [社群] 提到 [痛点]。
我们正在做一个解决 X 问题的工具，特别想听听你的看法。
能 15 分钟聊聊吗？不卖东西，只是想理解你的工作流。"

注意：
  ✅ 个性化（看过 ta 的内容）
  ✅ 短（< 50 字）
  ✅ 明确价值交换
  ❌ 不要群发 / 复制粘贴
```

# 九、研究伦理

```
✅ 录音前书面同意
✅ 数据脱敏（不公开姓名）
✅ 用户可随时退出
✅ 数据 6 个月后销毁
✅ 不用于销售骚扰

合规：
  - GDPR（欧盟）
  - 个保法（中国）
  - 大客户：DPA + 数据保留协议
```
