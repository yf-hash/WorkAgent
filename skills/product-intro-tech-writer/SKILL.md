# 产品介绍-技术版 PPT 写作知识库

> 单一文档类型 | 受众：技术决策层 / IT 负责人 | 密级：可公开 | 篇幅：20-40 页

---

## 核心原则

1. **架构是核心**：必须含至少 2 张架构图（整体架构 + 关键模块）
2. **数据可信**：性能数据必须注明测试环境、并发模型、压测工具
3. **边界清晰**：可公开版本，禁止包含未发布功能 / 核心算法实现
4. **演讲节奏**：20-40 页适配 45-60 分钟的技术演讲

---

## 标准结构模板

```markdown
# [产品名] 技术介绍

## P1 封面
产品名 + 版本 + 演讲人 + 日期

## P2 议程
6-8 个一级主题

## P3-P4 行业技术趋势
（含技术演进图、关键挑战拆解）

## P5 产品定位
在技术栈中的位置 / 与同类产品的边界

## P6-P8 整体架构
P6: 分层架构图（接入层 / 业务层 / 数据层）
P7: 数据流图
P8: 关键技术选型说明

## P9-P14 核心模块（每 1-2 页一个）
每页结构：模块名 → 核心能力 → 关键设计 → 接口
建议覆盖 3-5 个核心模块

## P15-P17 关键技术亮点
每个亮点 1 页：技术名 → 解决什么问题 → 实现思路（高层）

## P18-P19 API 与集成
P18: API 概览（接口分组、调用方式）
P19: 典型集成场景（与上下游系统）

## P20-P21 性能与可扩展性
P20: 性能基线（含测试环境、并发数、TPS、延迟）
P21: 横向扩展机制

## P22-P23 安全设计
P22: 安全架构（认证 / 鉴权 / 加密 / 审计）
P23: 合规与认证

## P24-P25 部署模式
P24: 软件部署拓扑
P25: 硬件参考配置

## P26-P28 典型应用场景
每个场景 1 页：业务背景 → 技术方案 → 关键收益

## P29 兼容性
支持的 OS / 数据库 / 中间件 / 云平台矩阵

## P30 客户案例（技术视角）
重点讲技术挑战与解决方案，1-2 个案例

## P31 服务体系
售前 / 实施 / 售后 / 培训

## P32-P33 技术路线图
未来 1-2 年规划

## P34 Q&A 入口
联系方式 + 技术社区 + 文档入口
```

## 质量要求

| 维度 | 标准 |
|------|------|
| 篇幅 | 20-40 页 |
| 架构图 | 至少 2 张（整体 + 关键模块） |
| 性能数据 | 必须注明测试环境 |
| 技术深度 | 适合技术决策层，不到代码级 |
| 内容边界 | 禁止：核心算法实现 / 未发布功能 / 内部技术债 |
