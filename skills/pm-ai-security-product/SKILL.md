# AI / 网络安全产品 Skill

## 适用产品

- 安全大模型（Security LLM）
- AI 安全智能体（Security Agent）
- SAST / SCA / 软件成分分析
- 模糊测试（Fuzzing）
- 漏洞情报与威胁情报
- 攻防演练 / 红蓝对抗
- 渗透测试智能体
- SOC 智能体（自动化告警分析与响应）
- 模型统一接入平台
- 模型安全治理（输入过滤、输出审计、内容安全）
- 数字员工平台

## 设计维度

### A. AI 产品维度

- **模型能力边界**：能做什么、不能做什么、置信度多少
- **工具调用能力**：Tool Use / Function Call / MCP 集成
- **RAG / Text2SQL / Text2API**：检索增强、自然语言转结构化操作
- **任务规划与执行**：Agent 工作流、子任务拆解、多步推理
- **人机协同节点**：哪些动作必须人工确认（不可放权）
- **置信度与可解释性**：每条结论附置信度与依据
- **幻觉风险控制**：交叉验证、引用溯源、保守回退
- **输出审计**：所有 Agent 输出留痕，可追溯
- **Prompt / 上下文管理**：版本化、长上下文压缩、缓存
- **模型调用成本**：单 token 成本 → 单次任务成本 → 单客户成本

### B. 网络安全维度

- **资产范围**：明确扫描/检测/防护的对象边界
- **漏洞类型**：CWE/OWASP/CVE 映射
- **误报漏报**：FPR/FNR 量化，提供降误报与降漏报的人工反馈闭环
- **风险评级**：CVSS 3.x、业务影响打分、可利用性
- **证据链**：日志、流量、调用栈、可重放数据包
- **复现路径**：从原始证据到漏洞复现的完整步骤
- **修复建议**：分等级（紧急/重要/建议）、含代码示例
- **合规映射**：等保、SOC2、GDPR、个保法、CIS Benchmark
- **安全审计**：动作留痕、不可篡改、可追溯
- **权限和数据隔离**：多租户、敏感数据脱敏、最小权限

## 红线（注意事项）

- **不要把所有问题都交给大模型**——结构化能解决的不要交给非确定性模型。
- **高风险动作必须有人机确认**——删除资产、推送规则、阻断流量、对外发起请求等。
- **安全结论必须有证据链**——任何"发现 N 个高危"都要能追溯到具体证据。
- **企业场景必须支持审计追踪**——谁在什么时候做了什么、模型给出了什么、人工最终做了什么决定。
- **避免黑盒**——Agent 的关键决策点要可观察、可调参、可回滚。
