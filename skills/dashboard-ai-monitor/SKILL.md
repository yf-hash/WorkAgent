# Dashboard AI Monitor — AI 功能监控看板

> 单一职责：AI/LLM 功能的质量·成本·安全三维监控看板。
> 不做：AI 红队测试（→ `ai-red-team`）、AI 功能 PRD（→ `@ai-product-architect`）

## 看板模板

```
顶部：3 维度 KPI
  质量
    - 用户标"有用"率（vs 总输出量）
    - 引用准确率（生成式 RAG 必须监控）
    - Edit Distance（用户编辑了多少 AI 输出）
  成本
    - 日成本（$）
    - 单次成本（$/请求）
    - vs 预算（实际 / 预算 × 100%）
  安全
    - 拒答率（合理拒答 / 不当拒答）
    - 越权拦截数
    - Refusal 占比

中部：
  - 用户标记趋势（👍/👎 比例 12 周折线）
  - 模型延迟 P50/P95/P99
  - 失败模式分布（饼图：幻觉 / 越权 / 超时 / 工具调用失败 / 其他）

底部：
  - 失败案例 Top 10（自动归类 + 用户原始 query）
  - HITL 人工兜底量（哪些场景 AI 答不了，转人工）
  - Eval 集回归得分（每次模型升级后必跑）
  - 模型版本对比（A 版 vs B 版的质量/成本/延迟）
```

## 指标定义

### 质量指标

```
有用率：
  分子 = 用户点👍数 或 显式标"有用"数
  分母 = 总输出数（去除空响应）
  Benchmark：> 70% 优秀，60-70% 可接受，< 60% 需调优

引用准确率（RAG 必查）：
  分子 = 引用源真实存在且与回答相关的次数
  分母 = 总引用数
  Benchmark：> 95% 才能上线

Edit Distance：
  用户最终采纳的文本 vs AI 原始输出的 Levenshtein 距离
  低 = 用户基本认可；高 = 用户重写
```

### 成本指标

```
单次成本：
  ∑ (input_tokens × input_price + output_tokens × output_price + tool_call_cost)

成本/有用输出：
  日成本 / 日有用输出数
  这才是真实的"有效成本"

预警阈值：
  日成本环比上涨 > 30% → P1
  vs 预算 > 150% → P0
```

### 安全指标

```
合理拒答率：
  AI 主动拒答的请求中，确实应该拒答的比例
  Benchmark：> 95%

不当拒答率：
  AI 拒答了不该拒答的请求（过度安全）
  Benchmark：< 5%

越权拦截：
  AI 调用了不该调用的工具 / 访问了不该访问的数据
  Benchmark：= 0（任何越权都要报警）
```

## 失败模式自动归类

```
基于用户反馈 + 日志聚类：
  - 幻觉：AI 编造事实
  - 越权：AI 做了不该做的事
  - 超时：响应时间 > 阈值
  - 工具调用失败：MCP / Function 调用错误
  - 上下文丢失：长对话忘了前文
  - 格式错误：JSON 解析失败
  - 拒答错误：过度拒答 / 该拒不拒
```

## 配套：Eval 集回归

```
模型版本升级前必跑：
- 准备 N 条 golden cases（覆盖正/负/边界）
- 跑新版本 vs 旧版本
- 评分 ≥ 旧版本 才能上线
- 任何 regression（即使整体分数提升）都要标注
```

## 告警建议

```
P0（立即响应）：
  - 幻觉率 > 30%
  - 任何越权拦截
  - 日成本超预算 > 200%

P1（4 小时内）：
  - 有用率周环比下降 > 5pp
  - P95 延迟上涨 > 50%
  - 不当拒答率 > 10%

P2（每日关注）：
  - 失败案例 Top 10 出现新模式
  - HITL 兜底量上升趋势
```
