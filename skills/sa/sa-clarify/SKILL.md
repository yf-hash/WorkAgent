# sa-clarify — 客户调研澄清工具箱

> 本 skill 被 `/sa-clarify` 命令调用。

## 一、7 大信息类别调研 checklist

任何一份客户调研必须能回答以下 7 类信息；无法回答的即"缺失"，答案模糊的即"歧义"。

| # | 类别 | 判定标准 | 示例（合格 / 不合格） |
|---|---|---|---|
| 1 | 现有 IT 架构 | 有具体系统品牌 + 版本 + 年限 | ✅"SAP S/4HANA 3 年" ❌"用了一套 ERP" |
| 2 | 业务流程 | 至少 5 步 + 每步负责人 | ✅"车间主任每天 8 点排产" ❌"客户有生产流程" |
| 3 | 现存痛点 | 具体动作 + 频率 + 数字影响 | ✅"月末对账 3 天，出错率 5%" ❌"效率不高" |
| 4 | 约束条件 | 时间 / 预算 / 人力 / 硬件 具体 | ✅"3 月 31 日前上线，500 万预算" ❌"越快越好" |
| 5 | 合规要求 | 明确条款 + 等级 | ✅"等保三级 + 国产化 70%" ❌"注意合规" |
| 6 | 性能指标 | 并发数 + 数据量 + 响应 | ✅"5000 台并发 + P95 500ms" ❌"要好用" |
| 7 | 项目边界 | 显式的做与不做 | ✅"本次做 A/B/C，不做 D" ❌"—"（空） |

## 二、行业特化调研模板

### 政企 / 央企

```
【组织架构】部委级/司局级/处/科（决策链清晰）
【预算属性】财政预算/专项经费/信息化项目
【合规】等保X级/关基/网安审查/信创目录
【采购】招投标/入围/框架采购
【供应商资质】必备资质（等保测评/信创认证）
【交付】驻场/私有化/审计报告
【禁忌】数据出境/公有云依赖/境外品牌深度耦合
```

### 金融（银行 / 证券 / 保险）

```
【监管】银保监/证监会/央行
【合规】等保三级/关基/密评/PCI DSS/个保法/数安法
【核心系统】核心账务/清算/支付/风控（不轻易动）
【交易系统】T+0 / T+1 / 灾备两地三中心
【业务连续性】RPO/RTO ≤ 分钟级
【采购】总行 IT 采购 + 分行验收
【禁忌】开源 GPL / 数据泄露 / 单点故障
```

### 制造业（离散 / 流程）

```
【生产系统】MES/APS/WMS/QMS/SCM
【采集】PLC/SCADA/物联网
【集成】ERP（SAP/用友/金蝶）/ PLM / CRM
【工厂网络】OT/IT 隔离 / DMZ
【设备规模】台数 / 数据点 / 采样频率
【业务节奏】生产节拍 / 排产周期
【禁忌】停机 / 数据丢失
```

### 互联网 / SaaS

```
【规模】DAU / MAU / QPS / 数据量
【技术栈】前端框架 / 后端语言 / 数据库 / K8s
【发布节奏】双周 / 月度 / 灰度
【SLA】99.9% / 99.99%
【客户是研发】关注 API / SDK / 文档
【采购】年费 / 按量 / 席位
【禁忌】不透明黑盒 / 无 SDK / 无 SLA
```

## 三、伪需求识别 checklist

| 表面需求特征 | 追问 | 真实需求可能是 |
|---|---|---|
| "加个报表" | 谁看？看完做什么决定？ | 某个决策场景 |
| "换掉现有系统" | 现在系统哪里让你痛？ | 具体几个业务问题 |
| "支持 AI" | 具体哪个环节用 AI？替代什么人工？ | 某个降本增效点 |
| "移动端" | 用户在哪里用？做什么？ | 某个外出场景 |
| "支持我们某某牌" | 为什么必须这个牌子？ | 已有资产 / 政治因素 |
| "要炫酷" | 谁看？演示给谁？ | 汇报 / 招商 / PR 场景 |
| "要国产化" | 全国产还是部分？替换周期？ | 政策合规 / 供应链自主 |

## 四、需求冲突规则库

| # | 冲突模式 | 触发关键词 A | 触发关键词 B | 严重度 |
|---|---|---|---|---|
| C1 | 快 vs 稳 | 3 个月上线 / MVP | 十万并发 / 99.99% SLA | 高 |
| C2 | 简单 vs 定制 | 一键 / 标品 | 深度定制 / 我们特殊 | 中 |
| C3 | 便宜 vs 高端 | 预算有限 | 企业级 / 关基 | 高 |
| C4 | 国产化 vs 生态 | 全国产 / 信创 | 深度集成 SAP / Oracle / 微软 | 高 |
| C5 | 私有化 vs SaaS 敏捷 | 私有化 / 数据不出域 | 每周迭代 / 自动升级 | 高 |
| C6 | 广覆盖 vs 深功能 | 覆盖所有场景 | 某场景深入 | 中 |
| C7 | AI 智能 vs 隐私 | 大模型 / AI 分析 | 数据不出境 / 私有 | 高 |
| C8 | 老板拍板 vs 用户导向 | 老板要 | 用户不接受 | 高（隐性） |
| C9 | 自研 vs 快速 | 我们自己有底子 | 3 个月上线 | 中 |
| C10 | 大范围 vs 小团队 | 集团级 | 5 人小组做 | 高 |

## 五、合规约束扫描规则

### 硬扫词库（不允许 auto 假设）

**中国合规**：
```
等保 / 三级 / 四级 / 关基 / 关键信息基础设施
国产化 / 信创 / 全国产 / 自主可控 / 首创 / 二级安全
个保法 / PIPL / 数安法 / 网安法
数据不出境 / 数据本地化 / 数据不出园区
密评 / 商密 / 国密 / SM2 / SM3 / SM4
```

**国际合规**：
```
GDPR / CCPA / HIPAA / SOC2 / ISO27001 / ISO27701
PCI DSS / FIPS / FedRAMP
```

**行业专属**：
```
银保监令 / 证监会 12-2018 / 4号令
医疗器械注册 / 药监局
车联网数据分类
```

### 合规约束标记规则

- 扫描到 → 自动加入 constraints.compliance
- 如果客户未明说 → **不允许** auto 假设，必须列到"待确认项"
- 如果客户明说 → 加入报告 § 6.1，标注 "🔴 硬性"

## 六、业务痛点结构化模板

每条痛点应包含：

| 字段 | 说明 | 示例 |
|---|---|---|
| # | 痛点编号 | P1 |
| 描述 | 一句话 | 车间排产靠人工 Excel |
| 现在如何做 | 具体动作 | 车间主任每天 8 点排产 |
| 频率 | 每天/每周/每月 | 每天 |
| 影响 | 效率/成本/风险 | 效率低 + 出错率 5% |
| 优先级 | 高/中/低 | 高 |

## 八、反模式（禁止）

- ❌ auto 模式输出的合规假设未标【待确认】
- ❌ 报告没有"痛点列表"或"待确认项"
- ❌ 冲突检测栏空
- ❌ 假设项超过 30 条（说明信息缺失太多，应先跑 human）
- ❌ 把销售转述当客户明说（应加信心度）
