## 一、6 阶段实施模板

| # | 阶段 | 时长（3 月项目） | 关键动作 | 关键产出 |
|---|---|---|---|---|
| 1 | 准备 | 2 周 | Kickoff + 需求锁定 + 项目章程 | 项目章程签字 |
| 2 | 部署 | 4 周 | K8s / DB / 应用 部署 | 部署验收 |
| 3 | 集成 | 6 周 | SAP / LDAP / 短信 / 设备 联调 | 联调通过 |
| 4 | 数据迁移 | 3 周 | 清洗 + 迁移 + 校验 | 数据比对通过 |
| 5 | 培训 | 3 周 | 管理员 5 天 + 一线工作坊 | 培训完成率 100% |
| 6 | 上线 | 3-4 周 | 并行 + 灰度 + 全量 + 稳定期 | 客户签字验收 |

**总周期**：约 13-14 周（考虑阶段重叠可压缩到 12 周 = 3 月）。

**注意**：阶段之间存在重叠，用 Gantt 图表示。

## 二、RACI 职责矩阵

### R.A.C.I 定义
- **R (Responsible)**：执行者
- **A (Accountable)**：负责人 / 拍板人（每个活动只有一个 A）
- **C (Consulted)**：需要征求意见
- **S (Supporting)** or **I (Informed)**：支持者 / 被通知

### 标准活动 RACI 模板

| 活动 | 客户方 | 我方 |
|---|---|---|
| 需求确认 | 业务负责人（R）+ CIO（A） | 售前（C）+ 项目经理（C） |
| 硬件采购 | IT（R）+ 采购（A） | 售前（C） |
| 软件部署 | IT（S） | 部署工程师（R）+ 架构师（A） |
| 集成对接 | 各系统 owner（R） | 集成工程师（R）+ 架构师（A） |
| 数据迁移 | 业务（S） | 数据工程师（R）+ 项目经理（A） |
| 培训 | HR / 业务负责人（C） | 培训师（R） |
| 上线切换 | IT（S）+ 业务（S） | 项目经理（R）+ 架构师（A） |
| 验收 | CIO / 业务负责人（A） | 项目经理（R） |

## 三、上线切换策略

### 三种基本策略

| 策略 | 适用场景 | 风险 |
|---|---|---|
| **并行切换** | 关键业务 / 数据敏感 | 双录入负担，但最安全 |
| **灰度切换** | 用户量大 / 有分批可能 | 分批之间的不一致 |
| **一次性切换** | 简单业务 / 数据量小 | 高，一旦失败全面回滚 |

**推荐组合**：并行（2 周） → 灰度（2 周） → 全量（1 周） → 稳定期（1 周）

### 回滚计划要素
- **触发条件**：明确 P0 故障标准（如 > 4 小时、数据不一致率 > 1%）
- **回滚动作**：具体步骤
- **决策人**：谁能拍板回滚
- **回滚后**：数据同步 / 补录方案

## 四、培训计划模板

### 管理员培训（5 天）
D1 系统概览 + 架构 + 部署 | D2 权限 + 数据 | D3 集成配置 | D4 监控 / 告警 / 备份 | D5 故障排查 + Q&A

### 一线培训
- **形式**：小组工作坊（1.5h 讲 + 1.5h 实操）+ 视频（10 个短视频）+ 手册
- **考核**：每人完成 3 个典型场景演练
- **覆盖率**：目标 100%

### 培训材料 checklist
- [ ] 管理员手册（PDF 100+ 页）
- [ ] 一线操作手册（PDF 30 页）
- [ ] 培训视频（10 个 × 5-10 分钟）
- [ ] FAQ 文档（20-30 条）
- [ ] Cheat Sheet（一页纸速查）

## 六、变更控制流程

```
变更提出 → 项目经理评估 24h → 影响分类
   ↓
   ├── 小变更（≤3 人天）→ 项目经理决定 → 入 CHANGELOG
   └── 大变更 → 双方 Sponsor 签字 → 更新合同附件 → 入 CHANGELOG
```

## 八、反模式

- ❌ 阶段划分只列名不划时间 —— 违规
- ❌ RACI 缺 A（Accountable）—— 出事没人拍板
- ❌ 上线只讲切换不讲回滚 —— 违规
- ❌ 培训没有考核 —— 上线一定翻车
- ❌ 变更无书面流程 —— 后期扯皮
- ❌ 风险栏 < 5 条 —— 实施一定有意外
