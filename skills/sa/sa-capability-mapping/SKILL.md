# sa-capability-mapping — 方案拆解工具箱

> 本 skill 被 `/sa-solution-map` 命令调用。

## 一、覆盖度评级规则

### 三档评级

| 图标 | 覆盖度 | 判定标准 |
|---|---|---|
| ✅ | 完全覆盖 | 标品直接支持，无需配置或开发 |
| 🟡 | 部分覆盖 | 需配置 / 参数调整 / 少量二次开发（≤ 5 人天/模块） |
| 🔴 | 不支持 | 需大量定制 / 需第三方补齐 / 完全没有该能力 |

### 判定问题
- "本次交付版本能不能直接开这个功能给客户？" → 是 → ✅
- "配置一下 or 简单开发就能满足？" → 是 → 🟡
- "得写一大堆代码 / 集成外部？" → 是 → 🔴

### 边界

- 覆盖度评估**只看能力是否有**，不评价"好不好用"
- 客户"业务定制习惯"归到 🟡（需配置）
- 客户"完全没做过的特殊场景"归到 🔴

## 二、定制工作量分级

不出具体人天（避免被当报价依据），只分级：

| 级别 | 判定 | 参考人天范围 |
|---|---|---|
| 🟢 低 | 配置项 / 参数调整 / 小组件调整 | ≤ 5 人天 |
| 🟡 中 | 一个模块的功能扩展 / 一个新接口对接 | 5-30 人天 |
| 🔴 高 | 多模块联动 / 大型集成 / 新算法实现 | > 30 人天 |

**注意**：具体人天由实施团队评估，本 skill 只出定性。

## 三、竞品对照维度

### 必对比 6 维

| 维度 | 说明 |
|---|---|
| **功能** | 覆盖度对比（我方 vs 竞品在客户痛点上的覆盖） |
| **价格** | 客户方能感知的档位（高/中/低） |
| **交付** | 项目周期 / 实施难度 / 交付质量 |
| **品牌** | 客户方对品牌的信任度 |
| **生态** | 上下游生态 / 集成便利性 |
| **合规** | 客户当前合规要求下的适配度 |

### 竞品分类

| 类型 | 举例 | 应对策略 |
|---|---|---|
| **同类型商用** | 用友 / 金蝶 / SAP | 找差异化点 |
| **通用替代** | 客户用 Excel / 定制开发 | 讲效率提升 + 长期成本 |
| **客户自建** | 客户想自己写 | 讲交付风险 + 时间成本 |
| **开源方案** | 开源 MES 项目 | 讲企业级支持 + 合规 |

## 四、5 类项目风险 checklist

### 类别 1：外部依赖
- [ ] 有哪些第三方 API 依赖？（客户 SAP / 短信平台 / OAuth 等）
- [ ] 每个依赖的可用性 / SLA 如何？
- [ ] 客户是否掌握相关接口开放能力？

### 类别 2：集成风险
- [ ] 客户现有系统数据模型是否与我方兼容？
- [ ] 接口是否开放？文档是否齐全？
- [ ] 集成测试环境如何搭建？
- [ ] 数据迁移量级 / 数据清洗难度？

### 类别 3：定制开发风险
- [ ] 定制工作量总计（低/中/高个数）
- [ ] 定制会不会影响后续标品升级？
- [ ] 定制在客户方 IT 团队看来是加分项还是减分项？
- [ ] 变更控制机制有没有？

### 类别 4：合规风险
- [ ] 等保 / 关基 / 密评 / 国产化 / 数据本地化 每项是否有确定路径？
- [ ] 三方证明 / 认证 / 报告 谁出？何时出？
- [ ] 客户内部合规评审能不能通过？

### 类别 5：实施风险
- [ ] 客户 IT 人力是否到位？
- [ ] 客户业务方是否已经参与前期沟通？
- [ ] 培训计划 / 变更管理策略？
- [ ] 一线用户是否有抵触情绪？

**要求**：每类至少 1 条具体风险，含"缓解方向"。

## 五、方案定位一句话模板

严格按以下句式：

```
针对 {客户名} {项目名} 项目，
以 {我方核心产品或方案} 为核心，
配套 {关键定制或第三方能力}，
{时间承诺} 完成 {交付范围}，
通过 {差异化能力 1} 和 {差异化能力 2} 构建对 {主要竞品 A} {主要竞品 B} 的竞争壁垒。
```

### 好例子

> 针对远大制造老 MES 替换项目，以我方国产化 MES 标品为核心，配套 SAP 深度对接的定制模块，3 个月完成部署上线，通过智能排产和实时质检两个差异化能力构建对用友、西门子的竞争壁垒。

### 坏例子（不合规）

- ❌ "我们的方案能满足客户需求" —— 太空
- ❌ "以国产化 MES 为核心" —— 缺时间 / 差异化 / 竞品
- ❌ "对齐客户所有诉求" —— 无重点

## 六、常见错误

| 错误 | 症状 | 修正 |
|---|---|---|
| 覆盖度只看有没有 | 全部标 ✅ | 客户特殊场景至少 🟡 |
| 定制工作量给具体人天 | "80 人天" | 改为 "中" 或 "高"，具体让实施评估 |
| 竞品分析只夸不损 | 只写我方优势 | 必须写劣势 & 规避 |
| 风险只写不缓解 | 只列风险 | 每条风险必写缓解方向 |
| 定位陈词滥调 | "为客户提供最好的服务" | 用句式模板 |
