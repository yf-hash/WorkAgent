# sa-rfp-response — RFP 招标应答工具箱

> 本 skill 被 `/sa-rfp` 命令调用。

## 一、RFP 解析规则

### 顶层结构识别

RFP 通常有 5 大部分：

| 部分 | 关键词 |
|---|---|
| 招标概述 | 招标编号 / 招标方 / 项目名 / 预算 / 截止时间 |
| 商务需求 | 供应商资质 / 财务要求 / 履约保证 / 付款 |
| 技术需求 | 功能 / 性能 / 兼容性 / 安全 / 部署 |
| 服务需求 | 售后 / 培训 / SLA / 保修 / 升级 |
| 附件 | 报价表模板 / 应答表模板 / 偏离表模板 |

### 逐条编号规则

- 保留 RFP 原有编号（如 T1.1.1、S2.3）
- 提取原文（一字不改）
- 分类打标（技术 / 商务 / 服务）
- 标注是否评分项 + 分值

## 二、打分项识别规则库

### 常见打分项类型

| # | 打分项类型 | 特征 | 应答策略 |
|---|---|---|---|
| 1 | 技术能力评分 | "满足得 X 分，不满足 0 分" | 完全满足 + 引用具体模块 |
| 2 | 案例评分 | "近 3 年类似项目 ≥ N 个" | 附案例证明 + 客户联系人 |
| 3 | 资质评分 | "具备 XX 认证" | 附资质证书扫描件 |
| 4 | 人员评分 | "项目经理具备 X 年经验" | 附简历 |
| 5 | 交付评分 | "交付周期 ≤ X 月" | 匹配 or 稍缩短 |
| 6 | 价格评分 | 价格分公式 | 商务决定 |
| 7 | 服务评分 | "7×24 / 响应时长" | 承诺书面 |
| 8 | 定制评分 | "定制能力" | 展示历史定制案例 |

### 优势项 / 劣势项判定

- **优势项**：我方标品直接支持 + 分值高 → **重点展开** + 引用案例
- **劣势项**：我方需定制 or 资质缺失 → **规避话术** + 承诺补齐
- **中性项**：一般能力，普通展开

## 三、应答话术规范

### 完全满足（✅）

```
【应答】✅ 完全满足
【说明】我方方案 {模块/能力} {版本} 直接支持该需求，具体表现：
  1. {具体表现 1}
  2. {具体表现 2}
【依据】详见方案 § {章节}，及附件 {文档}。
```

**要点**：
- 明确"完全满足"四个字
- 引用方案具体章节
- 有数据 / 具体能力支撑
- 不夸张，不虚构

### 部分满足（🟡）

```
【应答】🟡 部分满足
【说明】
  - 满足部分：{哪部分满足，占 X%}
  - 未满足部分：{哪部分不满足}
  - 补齐路径：{通过 XX 方式补齐，需 Y 时间 / 工作量}
【建议】{我方建议调整或替代方案}
```

**要点**：
- 诚实标"部分满足"
- 明确划分满足 / 不满足
- 提供补齐路径

### 不满足（🔴）

```
【应答】🔴 不满足（提供替代方案）
【说明】
  - 不满足原因：{说明现有能力局限}
  - 替代方案：{可行的替代方案，含工作量}
  - 偏离登记：见《技术偏离表》条目 D{n}
```

**要点**：
- 诚实标"不满足"
- 必须给替代方案
- 关联偏离表

## 四、技术偏离表规范

### 三种偏离

| 偏离方向 | 说明 | 是否入表 |
|---|---|---|
| 完全满足 | 持平 | ❌ 不入表 |
| 负偏离（部分/不满足） | 低于要求 | ✅ 入表 + 补救方案 |
| 正偏离（超越） | 高于要求 | ✅ 入表（加分项） |

### 偏离表格式

```markdown
| 条目号 | RFP 原文 | 偏离方向 | 我方能力 | 影响 | 补救方案 |
|---|---|---|---|---|---|
| T1.5.3 | 5 秒内响应所有查询 | 负偏离（部分） | 普通查询 ≤ 5s，复杂 ≤ 10s | 小 | 预聚合优化到 5s，+2 周 |
| T1.5.5 | 支持 Oracle 数据库 | 负偏离（不满足） | 标品支持 OceanBase | 需定制 | 中间件适配，+15 人天 |
| T3.2.1 | 提供 7×24 小时热线 | 正偏离（超越） | 7×24 + 1h 响应承诺 | — | — |
```

## 五、禁止的应答黑话术

### 严禁：
- ❌ "完全满足" 但实际不满足（属于虚假应答，被查会取消资格）
- ❌ "支持"（含糊）代替"完全满足 / 部分满足 / 不满足"
- ❌ 抄袭其他厂商应答（招标方会对比）
- ❌ 用"最"、"唯一"等虚构性词汇
- ❌ 承诺不能兑现的 SLA / 交付周期

### 慎用：
- "尽最大努力"
- "基本满足"
- "行业领先"（除非有第三方报告）

## 六、应答优化建议

### 得分优化
- 高分项优势 → 应答字数占比 30%+
- 高分项劣势 → 应答需重点润色 + 附加案例
- 低分项 → 简洁应答，不浪费笔墨

### 视觉优化
- 使用表格 / 编号 / 加粗
- 关键得分点用图 / 案例数据背书
- 一份好的应答应"易读、可查、可核对"

### 附件建议
- 案例列表（含客户联系人）
- 资质证书扫描件
- 项目经理简历
- 白皮书 / 产品手册

## 七、常见错误

| 错误 | 后果 | 修正 |
|---|---|---|
| 应答"完全满足"但方案不支持 | 中标后交付失败 | 诚实标"部分满足" |
| 偏离表遗漏 | 中标后被指控隐瞒 | 系统性梳理 |
| 打分项分析缺失 | 无重点应答，中标概率降低 | 必须做打分项分析 |
| 应答话术空洞 | 招标方看不出实力 | 具体到模块 / 数据 / 案例 |
| 忽视商务 / 服务应答 | 技术满分商务扣分 | 三部分同等重视 |
