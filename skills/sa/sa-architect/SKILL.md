## 二、5 层架构规范

标准企业级应用架构分层：

```
┌─────────────────────────────┐
│ 1. 展现层 (Presentation)      │  Web / Mobile / 大屏 / 开放 API
├─────────────────────────────┤
│ 2. 应用层 (Application)       │  微服务 / 领域服务
├─────────────────────────────┤
│ 3. 集成层 (Integration)       │  ESB / API 网关 / 消息队列 / 适配器
├─────────────────────────────┤
│ 4. 数据层 (Data)             │  关系库 / 时序库 / 缓存 / 数仓
├─────────────────────────────┤
│ 5. 基础设施 (Infra)          │  K8s / 容器仓 / 监控 / 日志
└─────────────────────────────┘
```

**每层判定问题**：
- 展现层：客户端多端支持？开放 API 给谁？
- 应用层：微服务如何拆？按业务域 / 按能力？
- 集成层：ESB 还是网关？异步 or 同步？
- 数据层：只 OLTP 还是 OLTP + OLAP？时序 or 关系？
- 基础设施：国产化要求哪些？CNCF or 客户自选？

## 三、Mermaid 架构图规范

### 顶层技术架构（flowchart TB）
- 分 5 层（每层 subgraph）
- 层内组件平铺
- 层间用箭头表示调用方向
- 数据流用虚线

### 业务架构（flowchart TB）
- 业务域为顶层 subgraph
- 业务能力为二级节点
- 支撑关系用箭头

### 部署架构（flowchart LR / TB）
- 按环境划分 subgraph（生产 / 灾备 / 开发）
- 网络分区用不同背景色
- 明确"外部访问入口"位置

### 数据流（flowchart LR / sequenceDiagram）
- 使用 sequence 表示时序
- 使用 flowchart 表示 ETL 流程

## 四、部署形态选型

### 三种基本形态

| 形态 | 适合 | 硬件 | 交付 |
|---|---|---|---|
| **私有化** | 政企 / 金融 / 合规敏感 | 客户 IDC | 容器化 or 虚机 |
| **公有云** | 互联网 / 中小 | AWS/Azure/阿里/腾讯 | SaaS / IaaS |
| **混合** | 大型集团 / 多地 | 私有 + 公有 | K8s 联邦 |

### 部署选型 checklist

- [ ] 客户是否要求私有化？（合规硬约束）
- [ ] 客户是否有云基础设施？
- [ ] 是否需要跨地域？
- [ ] 是否有信创要求？（影响 K8s / 数据库选型）
- [ ] 是否有等保要求？（影响网络分区）
- [ ] RTO/RPO 要求？（影响灾备设计）

## 五、集成模式库

| 模式 | 适用场景 | 特点 | 举例 |
|---|---|---|---|
| **REST API** | 同步 / 请求响应 | 简单 / 通用 | 查询接口 |
| **消息队列** | 异步 / 事件驱动 | 解耦 / 可靠 | Kafka / RocketMQ |
| **ETL 定时** | 大批量 / 数据同步 | 简单 / 有延迟 | 每日 T+1 同步 |
| **CDC** | 实时数据同步 | 准实时 | 数据库变更捕获 |
| **文件交换** | 传统集成 / SFTP | 老系统 | 银行核心系统 |
| **专用协议** | 工业 / 特殊设备 | 领域深 | OPC UA / Modbus |

### 集成场景选型

- **实时业务事件** → 消息队列 or CDC
- **数据展示查询** → REST API
- **批量数据同步** → ETL 或 CDC
- **老系统对接** → 文件交换 / 数据库直连（不推荐）
- **工控设备** → OPC UA / Modbus

## 六、常见架构反模式

| 反模式 | 症状 | 修正 |
|---|---|---|
| 单体应用打包成微服务 | 5 个服务共用同一数据库 | 按业务域切分 |
| ESB 变成新单体 | 所有逻辑都写在 ESB | ESB 只做路由 / 转换 |
| 数据库当集成层 | 系统间通过共享库互通 | 上升到 API / MQ 层 |
| 缺乏容器化 | 每个环境不同部署脚本 | 统一容器化 |
| 监控是事后加 | 上线后才加监控 | 架构就要包含监控设计 |
