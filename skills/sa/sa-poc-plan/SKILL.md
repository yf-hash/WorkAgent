# sa-poc-plan — POC 方案工具箱

> 本 skill 被 `/sa-poc` 命令调用。

## 一、POC 范围界定规则

### 必测（🔴 P0）
- 客户 P0 痛点对应的能力
- 我方差异化能力（用于击败竞品）
- 高风险集成点（如客户 SAP / 复杂设备）
- 客户在 RFP / 调研中特别强调的点

### 可选（🟡 P1）
- 客户领导可能关注的展示性能力（如移动端 / 大屏 / AI）
- 二期规划中的探索性能力
- 提升客户体验的锦上添花

### 不测（明确写清楚，避免加需求）
- 已在其他客户案例验证的成熟能力
- 与本项目痛点无关的能力
- 后续版本才做的功能

## 二、环境要求模板

**关键原则**：每项必须有"责任人 + 截止时间"，否则 POC 一定延期。

### 客户方环境要求 checklist

| 类别 | 项 | 责任人角色 |
|---|---|---|
| 硬件 | 服务器（应用/数据/大屏） | 客户 IT |
| 网络 | 带宽 / VPN / 网段 | 客户网络 |
| 数据 | 测试数据集（真实脱敏） | 客户业务 |
| 账号 | 测试账号 / 权限 | 客户 IT |
| 集成 | SAP / LDAP / 短信 测试接口 | 客户各系统 owner |
| 现场 | 会议室 / 网络接入 / 权限证 | 客户行政 |

### 我方环境要求 checklist

| 类别 | 项 |
|---|---|
| 软件 | POC 版本软件包 |
| 部署 | 部署工程师 + 部署脚本 |
| 支持 | 现场/远程支持团队 |
| 材料 | 培训 PDF / 视频 / 操作手册 |
| 测试 | 测试脚本 / 数据 / 工具 |

## 三、测试用例格式

每个测试用例必须包含 6 要素：

```markdown
### T{n} - {用例名}
- **目标**：{用一句话说清测什么}
- **前提**：{需要哪些环境 / 数据 / 上游用例}
- **步骤**：
  1. {动作 1}
  2. {动作 2}
  ...
- **期望结果**：
  - {结果 1}（含数字）
  - {结果 2}（含数字）
- **通过标准**：{明确的通过判定}
- **不通过处理**：{fail 后怎么办}
```

**期望结果必须有数字**，不能是"响应快 / 准确"这类模糊表述。

## 四、验收判定标准

### 三档判定

| 结果 | 判定标准 | 后续动作 |
|---|---|---|
| ✅ 全通过 | 必测项 100% 通过 + 可选项 ≥ 50% 通过 | 进入商务合同 |
| 🟡 部分通过 | 必测项 ≥ 80% 通过 + 无 P0 失败 | 1 个月内整改补测 |
| 🔴 不通过 | 必测项 < 80% or 有 P0 失败 | POC 终止 |

### 签字环节
- 客户方：CIO + 业务负责人 + IT 负责人
- 我方：售前 + 项目经理

## 五、常见 POC 风险库

| # | 风险 | 概率 | 影响 | 缓解模板 |
|---|---|---|---|---|
| R1 | 环境延迟就位 | 高 | 高 | 提前 2 周 kickoff + 每周同步 |
| R2 | 客户业务方参与度低 | 中 | 高 | POC 汇报强制业务方在场 |
| R3 | 竞品同期 POC 施压 | 中 | 中 | 突出差异化能力测试 |
| R4 | 客户临时加需求 | 高 | 中 | 严格变更控制 |
| R5 | 三方系统不配合 | 中 | 高 | 提前建立联系 + 备用适配器 |
| R6 | 定制点开发延期 | 中 | 高 | 每周 demo + 提前预警 |
| R7 | 数据脱敏不彻底 | 中 | 高 | 双人复核 + 客户签字 |
| R8 | 客户 CIO 换人 | 低 | 高 | 前期建立多层次联系 |

## 六、POC 周期建议

| 项目规模 | 建议 POC 周期 | 说明 |
|---|---|---|
| 小（1-2 个模块） | 2 周 | 关注核心能力 |
| 中（3-5 个模块） | 4 周 | 覆盖集成 |
| 大（≥ 6 个模块 or 复杂集成） | 6-8 周 | 分阶段 POC |

## 七、POC 汇报会最佳实践

- 时间：验收签字前 1 天
- 参与方：客户 CIO + 业务负责人 + 我方项目经理
- 内容：
  - 5 分钟：项目背景 + POC 目标
  - 20 分钟：用例执行结果（重点讲通过项）
  - 10 分钟：数据 / 效果指标
  - 5 分钟：后续实施建议
  - 20 分钟：Q&A + 签字

## 八、反模式

- ❌ 只测能力不测集成 —— 上线一定翻车
- ❌ 不写"不测项" —— 客户会临时加
- ❌ 期望结果模糊 —— 验收扯皮
- ❌ 环境要求没截止时间 —— POC 延期常见原因
- ❌ 风险 < 5 条 —— POC 一定会出问题
