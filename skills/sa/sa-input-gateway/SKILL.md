# sa-input-gateway — 多源输入网关工具箱

> 本 skill 被 `/sa-intake` 命令调用。

## 一、输入源解析规则

### 销售转述文本（最常见）

**清洗规则**：
- 移除寒暄词：您好 / 感谢 / 期待 / 打扰 / 客套 / 敬请
- 保留数字与专有名词
- 分句 + 分类打标（现状 / 诉求 / 约束 / 疑问 / 竞争 / 预算 / 时间）

### 客户访谈转写

**假设格式**：说话人分离的对话
```
[销售] xxx
[客户] xxx
[客户 IT] xxx
```

**清洗规则**：
- 只保留客户方发言
- 提取每一轮客户回答的实质点
- 忽略"嗯 / 对 / 好的"等填充词

### RFP / 招标文件

**解析要点**（用 skill sa-rfp-response 深度解析）：
- 抬头识别客户名 + 项目名
- 目录结构提取（技术需求 / 商务需求 / 服务需求 / 附件）
- 关键条款识别（评分项 / 分值 / 资质要求 / 交付要求 / 时间要求）
- 招标编号 / 招标方 / 截止时间

### 客户现状 PPT

**解析要点**：
- 每页文本 + 结构化标题
- 组织架构页 → 干系人抽取
- 业务架构 / 技术架构 → 现有 IT 栈
- 痛点/挑战页 → pain_points

### Excel 需求清单

**解析要点**：
- 表头识别：需求名 / 优先级 / 状态 / 提出人 / 备注
- 优先级映射：P0/P1/P2 → high/medium/low
- 状态映射：已实现 / 已上线 → 现状；未满足 → 显性诉求

## 二、元信息抽取 12 类字段

### 抽取规则

#### 1. 客户名称
- 优先级：RFP 抬头 > PPT 首页 > 销售转述明确名称 > 用户 --client 参数
- 无法确定时：`"name": null, "requires_confirmation": true`

#### 2. 所属行业
枚举值：
```
政企 / 央企 / 国企
制造业（含离散/流程）
金融（银行/证券/保险）
互联网 / SaaS
零售 / 电商
医疗 / 医药
教育
能源 / 电力 / 石油
交通 / 物流
军工 / 军队
政法
其他
```

#### 3. 客户规模

**用户数估算**（依行业默认）：
| 行业 | 高 | 中 | 低 |
|---|---|---|---|
| 央企 | 10w+ | 1w-10w | < 1w |
| 银行 | 1w+ | 3k-1w | < 3k |
| 制造 | 5k+ | 1k-5k | < 1k |
| SaaS | 无标准 | 依产品 | — |

**其他规模指标**：员工数 / 营收 / 门店数 / 城市数

#### 4. 项目阶段
```
线索 → 意向 → PoC → 投标 → 合同 → 实施
```

判定信号：
- "感兴趣 / 了解一下" → 线索
- "要立项 / 出方案" → 意向
- "要 PoC / 试用" → PoC
- "招标 / 应答" → 投标
- "签合同 / 商务" → 合同

#### 5. 现有 IT 栈
- 老系统品牌（SAP / Oracle / 用友 / 金蝶 / 自研）
- 数据库（Oracle / MySQL / PG / OceanBase / GaussDB）
- 云平台（阿里 / 腾讯 / 华为 / AWS / 私有）
- 开发栈（Java / .NET / Go / Python）

#### 6-7. 显性诉求 vs 已知痛点

**区分规则**：
- 显性诉求 = "客户明说要什么"（"要 X 功能" / "要替换 Y"）
- 已知痛点 = "客户明说现在有什么问题"（"现在很慢" / "统计不准"）
- 隐性诉求 → 留给 M2 sa-clarify 处理

#### 8. 合规约束（关键，容易漏）

**必扫关键词**：
```
等保 / 三级 / 四级 / 关基
国产化 / 信创 / 全国产 / 自主可控
数据不出境 / 本地化部署 / 私有化
GDPR / PIPL / HIPAA / SOC2 / PCI DSS
数据主权 / 数据分级
两级两地 / 三地五中心
密评 / 国密算法
```

**扫描到即标记为硬性约束**，不可轻视。

#### 9. 预算线索

**信号识别**：
- 明确金额："200 万" → `{"amount": 2000000, "confidence": "high"}`
- 档位："中等预算" / "百万级" → `{"range": "1M-5M", "confidence": "medium"}`
- 无信号：`null` + `requires_confirmation: true`

#### 10. 期望上线时间

**解析**：
- 明确日期："2027-03-31 前"
- 相对时间："3 个月" → 计算 T+3m 目标日期
- 强度："必须 / 想要 / 希望"

#### 11. 关键干系人

**分类**：
- **决策人**：CIO / CTO / 副总裁 / 董事长
- **影响人**：技术负责人 / 部门总监
- **使用人**：业务操作员 / 一线员工

**信号**：出现姓名 + 职务 + 部门 → 加入 stakeholders 数组

#### 12. 竞争对手

**信号**：
- 客户主动提及："某某厂商也在报"
- 招标邀请名单
- 隐性："我们对比了几家" → `["未指名"]`

## 三、需求模糊等级判定

### 计分

12 个字段每个 1 分，可抽取到 1 分，缺失 0 分（`null` 或 `"未提供"`）。

### 分级

| 总分 | 等级 | 建议 |
|---|---|---|
| 0-5 | 🔴 高度模糊 | `/sa-clarify --mode human`（必须） |
| 6-8 | 🟠 部分明确 | `/sa-clarify --mode mixed`（推荐） |
| 9-12 | 🟢 RFP 明确 | `/sa-clarify --mode auto`（可选） |

### 特殊规则

- **合规字段** 不能靠假设补齐（等保 / 国产化 / 数据不出境）→ 一旦缺失，等级强制降到 🔴
- **RFP 已提供** 时，无论字段完整度如何，等级至少 🟠

## 五、常见解析陷阱

| 陷阱 | 症状 | 修正 |
|---|---|---|
| 把销售意愿当客户诉求 | "销售说客户可能会要 X" 变成 explicit | 加信心度标记，或放到 assumptions |
| 忽视否定 | 客户说"不需要 X"被漏掉 | 显式解析 excluded |
| 数字歧义 | "500 人" 是员工 / 用户 / 并发？ | 标记 requires_confirmation |
| 行业错分 | 电商 SaaS 分到 SaaS 还是电商？ | 主行业 + sub_industry |
| 合规词漏扫 | 客户在附件里提了信创 | 全文扫描而非只首页 |
