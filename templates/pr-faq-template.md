## 一、新闻稿（PR）— 1 页

> **写作规则**：用产品发布日的语气写。媒体一眼能读懂客户价值，否则需求不成立。

### 标题（≤ 10 字）

[一句话客户能理解的价值]

### 副标题（≤ 25 字）

[目标客户 + 关键能力 + 期望效果]

### 摘要段（≤ 4 句）

[发布日期] [城市] — [公司] 今日宣布 [产品 / 功能]，[一句话产品价值]。该 [产品 / 功能] [解决什么问题]，使 [目标客户] 能够 [取得什么效果]。

### 问题段（≤ 4 句）

直接讲客户痛点。**不要讲技术原理**，讲场景与代价。

### 解决方案段（≤ 4 句）

[产品 / 功能] 怎么解决：核心机制 + 客户使用路径 + 与现状的关键差异。

### 公司高管引用（≤ 2 句）

"[一句话内部信仰：为什么我们要做这件事]" —— [角色] [姓名]

### 客户引用（≤ 2 句）

"[客户用真实语气讲获得的价值]" —— [客户角色] [客户公司]（可用试点客户）

### 调用动作

[从哪里能开始用 / 多少钱 / 何时可用 / 联系谁]

## 二、FAQ — 通常 1-3 页

### 外部 FAQ（对客户）

| 客户视角问题 | 回答 |
|--------------|------|
| 这个产品和 [现有方案] 有什么不同？ | |
| 我需要为此付出什么（成本 / 学习曲线 / 部署）？ | |
| 数据 / 隐私 / 安全怎么保证？ | |
| 如果不喜欢能退吗？ | |
| 还有什么类似产品我应该考虑？ | |
| 我（客户某具体场景）能用吗？ | |

### 内部 FAQ（对老板 / 工程 / 销售）

| 内部视角问题 | 回答 |
|--------------|------|
| 这是不是真的客户问题？证据是什么？ | |
| 客户愿意付多少钱？ | |
| 工程实现难点 / 关键风险 / 模糊地带 | |
| 假设清单（先验证的假设）| |
| MVP 范围与不做范围 | |
| 上线节奏与里程碑 | |
| 如何衡量成功 / 失败 | |
| 商业模式（如何收费、单位经济） | |
| 法律 / 合规 / 数据风险 | |
| 销售如何售卖 / Demo 路径 | |
| 客户成功如何接住 | |
| 6 个月后这个项目是被看好还是被关掉 | |

## 评审标准

PR-FAQ 出来后，团队做"读稿评审"：

- [ ] **客户语言**：媒体读完一遍就懂客户价值（无术语）
- [ ] **新闻稿能否成立**：如果今天就发，竞品看到也不慌张吗？（要的是真差异）
- [ ] **客户引用是否真实**：能找到至少 1 个真实客户说同样的话吗？
- [ ] **FAQ 覆盖反对意见**：内部 / 销售 / 客户 / 投资人会问的都覆盖了吗？
- [ ] **假设清单完整**：每条假设有验证方式 + 截止日期吗？
- [ ] **不做范围明确**：写了"V1 不做什么"吗？

> 如果 PR-FAQ 评审不过，**不要写 PRD**。回到 `/pm-discovery` 或 `@research-analyst` 继续验证。
