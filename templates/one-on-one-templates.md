# 1:1 模板集

> PM 高频日常工件。三种典型 1:1：与上级 / 与研发 Lead / 与设计 Lead。
> 配套 Skill：`stakeholder`。

---

## 通用规则（必读）

1. **1:1 是被会议者的时间**。PM 是主人，但议程由对方关心的事驱动。
2. **不是周报会**。状态进度走异步文档（status update / Slack / 工单系统）。
3. **聚焦 3 件事**：阻塞 / 决策需求 / 反馈互换。
4. **结束前 5 分钟必聊 Action Items 与下次时间**。
5. **每月一次"非工作话题"**：职业发展 / 反馈给我 / 团队感受。

---

## 一、与上级（Manager）1:1 — 30 分钟

> 频率建议：每周 1 次。

```markdown
# 与 [Manager 姓名] 1:1 — YYYY-MM-DD

## 1. 我这周的关键进展（≤ 3 件，每件 1 句）
- ✅
- ⚠️
- 🚧

## 2. 我需要你做决定 / 协调的事
| # | 事项 | 我的提议 | 你的判断 / Action |
|---|------|----------|---------------------|
| 1 | | | |

## 3. 我担心 / 需要帮助的事
（不一定要现在解决，先让你知道）
-
-

## 4. 给我的反馈
（我做了什么需要继续 / 调整？）

## 5. 我给你的反馈
（你做了什么对我有帮助 / 期待你能调整的）

## 6. 职业发展 / 个人话题
（每月至少 1 次）

## 7. 下次 1:1 之前的 Action Items
| # | 谁 | 做什么 | 何时 |
|---|---|--------|------|
| 1 | 我 | | |
| 2 | 你 | | |
```

## 二、与研发 Lead 1:1 — 30 分钟

> 频率建议：每周 1 次，与 Sprint 节奏对齐。

```markdown
# 与 [研发 Lead 姓名] 1:1 — YYYY-MM-DD

## 1. 本 Sprint 进度感受
（不看燃尽图，听他主观感受）
- 风险点：
- 团队士气：
- 跨团队阻塞：

## 2. 下个 Sprint 准备情况
| 故事 | 是否清晰 | 阻塞 | 我的承诺 |
|------|----------|------|----------|
| | | | |

## 3. 技术债 / 架构投资
（每月至少 1 次：他想做什么技术投资，我能给多少容量）
-

## 4. 团队状态
（一句话：哪个工程师状态值得关注？）
-

## 5. 我做了什么让你工作更难
（直接问，听真话）
-

## 6. 你需要我做什么
（多半是"少改需求"、"早 1 周锁需求"、"挡住业务方")
-

## 7. Action Items
| # | 谁 | 做什么 | 何时 |
|---|---|--------|------|
```

## 三、与设计 Lead 1:1 — 30 分钟

> 频率建议：每周 1 次或双周。

```markdown
# 与 [设计 Lead 姓名] 1:1 — YYYY-MM-DD

## 1. 当前设计任务
| 任务 | 阶段 | 阻塞 | 何时收口 |
|------|------|------|----------|

## 2. 设计 vs 需求的张力
（哪里我们意见不一？哪里设计想做但我说"先不做"？）
-

## 3. 用户研究反馈
（最近的用研 / 可用性测试发现）
-

## 4. 设计系统投资
（每月至少 1 次：是否需要补组件库 / 设计规范）
-

## 5. 我做了什么让设计工作更难
（典型：需求晚 / 反复改 / 设计被业务方否决）
-

## 6. Action Items
| # | 谁 | 做什么 | 何时 |
|---|---|--------|------|
```

---

## 反模式（不要做）

- ❌ **当成周报会**：1:1 不是同步状态，是高带宽对话
- ❌ **PM 单方面讲**：80% 时间让对方说
- ❌ **跳过敏感话题**：反馈、不满、职业发展都要碰
- ❌ **取消重于一切**：临时事项再多也不能持续取消 1:1
- ❌ **不留 Action Items**：聊完不收尾等于没聊
