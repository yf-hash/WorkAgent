## 3. 客户痛点

1. **[高频任务 1] 井喷**：单大客户每月 N 次，重复率高但每次都要重新做
2. **[外部变化] 追不上**：[政策 / 技术 / 客户需求] 周期变化，文档常年滞后
3. **一致性差**：不同人处理同一类问题答案不同，客户起疑
4. **跨团队两张皮**：[法务 / 业务 / 技术] 关注点不同，沟通成本高

| 维度 | 量化价值 |

## 5. 典型场景

"客户发来 [N 题 / N 份 / N 项] 的 [任务类型]"
→ 上传素材 → AI 自动比对内部知识库 → 生成草稿 → 标注高风险项 → [使用角色] N 分钟完成复核签发。

### 场景 C：[低频自查任务]（季度）

## 9. FAQ（客户常问 10 条）

| 客户问题 | 推荐回答 | 注意事项 |
|----------|----------|---------|
| 我们数据放您那里安全吗？ | 私有化部署，部署在贵司内网，模型推理也在贵司机房，我们不接触一条数据。 | 一定要带"不接触一条"明确措辞 |
| AI 答错了谁负责？ | 我们提供合同模板将责任分层：高风险动作必须人工签核，签核人承担最终责任；AI 仅作为辅助。 | 不能含糊 |
| [外部变化] 跟不上怎么办？ | 我们每周日凌晨从指定权威源抓取更新，发现影响您业务的会主动推送通知。 | 列出权威源清单 |
| 多子组织数据怎么隔离？ | 默认多租户架构，子组织互不可见，集团层可以看汇总不能看明细。 | 现场画租户拓扑图 |
| 私有化部署要多少硬件？ | 单租户最小 N 台服务器（约 X 万），可降配但响应慢一倍。 | 给具体型号区间 |
| 现有 OA / 系统怎么集成？ | 标准 REST + Webhook，N 工时对接。 | 提供对接文档 |
| 实施周期？ | 标准实施 N 周：首周需求 + 知识库整理，中期部署 + 训练，后期试点上线。 | 列出阶段交付物 |
| 价格怎么算？ | 按 "[计量维度 1] + [计量维度 2]" 两维定价，[区间]。报价单 24 小时内发您。 | 不当场报具体数字 |
| 不签 PoC 直接买可以吗？ | 我们建议 N 周轻量级 PoC（[小金额]），验证您 N 份典型场景的准确率。如果失败全额退。 | 降低决策门槛 |
| 能否提供同行客户案例？ | 已有 N 家头部客户，部分允许背书，您方便的话我安排电话沟通。 | NDA 内案例 |

## 10. 竞品攻防话术（不贬低，给可验证差异）

### 客户说"我们已经在用 [国外同类 SaaS]"
"[国外同类] 在国际体系里很成熟，我们对它非常尊重。它的强项是 [国际化客户的统一框架]，我们的强项是 **[本地化深度 + 私有化部署完整性]**。建议您评估一下他们对 [本地标准 / 政策] 的覆盖深度——大多数本地客户最后会形成 [国外同类] + 我们的双系统组合。"

### 客户说"我们用通用 LLM 也能做"
"通用 LLM 通用能力很强，我们经常用它做日常文档。但它不替您扛三件事：**专业知识不专、审计链路不完整、数据出境违规风险**。这三件事您愿意让法务和审计部门承担风险吗？"

### 客户说"我们已经在用的厂商提供了同类模块"
"厂商的子模块是为他们自家产品做服务，**不是为您整个组织做横向赋能**。比如他们做不到您 [其他部门 / 其他业务] 的同等覆盖。我们做的是横向能力，是您的'外脑'，不是单一产品的'内嵌'。"

### 客户说"我自己人工做也挺快"
"工时不是问题，**风险才是问题**：人工的一致性、外部变化的及时性、审计的可追溯性，这三件事人工很难全做到。如果不信，我们 N 周 PoC 拿您过去 12 个月的真实素材做对比，让数据说话。"

## 11. 成交推进建议

| 客户表现 | 解读 | 推进动作 |
|---------|------|----------|
| 决策角色主动问 "私有化方案" | 强信号 | 现场画拓扑 + 留 1 周提交方案书 |
| 使用角色主动给真实素材 | 强信号 | 当晚做 PoC 反演结果，48 小时回访 |
| 法务总监问 "责任归属" | 决策风险点 | 提供合同模板 + 律师评审纪要 |
| 采购问 "价格" | 已进入预算评估 | 不当场报，发标准报价单 + 阶梯折扣 |
| 客户长时间不回 | 内部争议 | 找决策角色单独 30 分钟，不带销售 |

**典型成交节奏**：
- W1-2：决策角色演示 + 使用角色痛点确认
- W3-4：N 周 PoC（小金额，可冲抵后续合同）
- W5-8：PoC 反演结果 + 法务评审 + 报价
- W9-12：合同签署 + 实施 Kick-off

## 12. 不适合客户

诚实写出来，避免销售误判损耗：

- **[规模过小的客户]**：客单价无法覆盖私有化部署成本
- **不愿意做 PoC 的客户**：通常预算或决策权不实
- **要求公有云 SaaS 的客户**（数据敏感度低）：建议推荐 [国外同类] 或我们后期的 Lite 版本
- **没有专职 [对接岗] 的客户**：知识库整理阶段会卡壳，建议先做咨询服务

## 推荐话术结构（PPT&P 法则）

- **过去（Past）**：客户原来怎么做
- **问题（Problem）**：为什么现在不够用了
- **方案（Plan）**：我们的产品如何改变这个过程
- **效果（Performance）**：能带来什么可感知收益
- **保障（Promise）**：如何部署、运维、审计、交付
