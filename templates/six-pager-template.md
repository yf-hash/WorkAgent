# 6-Pager：{{项目 / 决策主题}}

> Amazon 风格的 6 页备忘录。**不允许 PPT、不允许子弹点**，强制完整段落叙述。
> 用于：复杂决策评审、立项汇报、年度计划。
> 配套 Skill：`working-backwards`、入口命令：`/working-backwards --mode six-pager`。

---

## 写作规则（必读）

1. **目标长度：6 页**，正文+附录。超过则砍 / 移到附录。
2. **完整句子**，不要子弹点 / 表格堆叠（表格只用于真正的数据对比）。
3. **会议形式**：开会前 20 分钟集体静默读稿，再讨论。不做 walkthrough。
4. **写作顺序**：写 PR-FAQ 在前，6-pager 在后；6-pager 是给老板做决策的，PR-FAQ 是给市场做承诺的。

---

## 1. 摘要 / Why now（约 ½ 页）

**三句话**回答：
- 这是什么决策 / 项目
- 你建议怎么做
- 为什么是现在

如果三句话讲不清楚，回去重写。

---

## 2. 客户问题（约 1 页）

**用客户能听懂的语言**描述问题。如果可能，写出一个真实客户的故事段落。

- 谁是客户（角色 / 行业 / 规模）
- 客户当前怎么做这件事
- 痛点强度（频率 × 损失）
- 客户付费意愿的证据（不要凭感觉）
- 这个问题为什么没有被既有方案解决

---

## 3. 解决方案 / 我们的提议（约 1.5 页）

讲清楚我们提议怎么做：

- 产品 / 决策的核心机制
- 客户使用路径（端到端用户旅程）
- 与现有方案的关键差异
- MVP 范围 vs V1 范围 vs 后续
- 不做范围（明确写出来）
- 关键技术 / 业务假设（每条带验证方式）

---

## 4. 成功指标（约 ½ 页）

我们怎么知道这件事成了 / 没成？

| 维度 | 指标 | 6 个月目标 | 12 个月目标 |
|------|------|-----------|------------|
| 北极星 | | | |
| 客户价值 | | | |
| 商业 | | | |
| 质量 | | | |

**砍掉项目的硬指标**：什么情况下我们就停（如 6 个月 PMF 信号 <40% 则 pivot）。

---

## 5. 风险与权衡（约 1 页）

| 风险 | 影响 | 缓解 | 责任人 |
|------|------|------|--------|
| 商业 | | | |
| 技术 | | | |
| 客户 | | | |
| 合规 / 安全 | | | |
| 团队 | | | |

**Pre-Mortem**：假设 12 个月后这个项目被关停，最可能的 3 个原因是什么？

---

## 6. 投入与节奏（约 1 页）

- 团队配置（含跨部门资源）
- 时间线（MVP / V1 / V2 三个里程碑）
- 预算（含人工 + 第三方 + 基础设施）
- 关键依赖（其他团队 / 第三方）
- 决策点（什么时候开下次会决定什么）

---

## 附录（不计入 6 页）

- A. 详细数据 / 客户访谈记录
- B. 竞品分析矩阵
- C. 财务模型（详细单位经济）
- D. 工程架构示意
- E. 替代方案及为何不选
- F. PR-FAQ（如已写）

---

## 评审清单

- [ ] 摘要三句话过关
- [ ] 客户问题有真实故事段落，不是想象
- [ ] 关键假设都有验证方式
- [ ] 成功指标含"砍项目"硬条件
- [ ] Pre-Mortem 列了 3 个最可能死因
- [ ] 决策点明确（不只是"开始做"）
