---

## 核心原则

1. **任务导向**：按"用户要完成什么"组织内容，而不是按技术模块
2. **截图必备**：每个关键步骤配截图，标注按钮位置和填写示例
3. **步骤可复现**：操作步骤用 1 / 2 / 3 编号，每步只做一件事
4. **错误也要写**：常见错误提示与处理方法必须列出
5. **角色明确**：每个功能注明"哪些角色可用"

## 操作步骤写作规范

| 规范 | 示例 |
|------|------|
| 一步一动作 | ✅ "1. 点击新建" / ❌ "1. 点击新建并填写表单" |
| 用动词开头 | ✅ "点击" / "填写" / "选择" |
| 标注关键字段 | "在 **用户名** 输入框填写 admin" |
| 截图配位置 | 截图后用红框 + 文字标注按钮位置 |
| 等待提示 | "等待 5-10 秒，系统返回 ..." |

---

## 质量要求

| 维度 | 标准 |
|------|------|
| 截图 | 每个功能至少 1 张，关键步骤必配 |
| 截图脱敏 | 用户名 / 邮箱 / 数据要打码 |
| 错误处理 | 每个功能至少列 1 个常见错误 |
| 时效性 | UI 改版后 7 天内更新截图 |
