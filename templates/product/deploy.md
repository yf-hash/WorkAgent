---

## 核心原则

1. **可复制粘贴**：所有命令用代码块呈现，可直接复制运行
2. **环境前置**：先讲环境准备，再讲安装，避免装到一半发现缺依赖
3. **配置表格化**：关键配置项用表格说明字段含义和默认值
4. **回滚必备**：每个升级步骤必须有对应回滚步骤
5. **监控不可缺**：运维监控章节列出关键指标和告警阈值

---

## 标准结构模板

```markdown
# [产品名] 部署及配置手册（v1.0）

## 修订记录 / 法律声明 / 目录

## 一、环境准备
### 1.1 硬件要求
| 部署模式 | CPU | 内存 | 磁盘 | 网络 |
| 单机最小 | 4C | 8G | 100G | 千兆 |
| 单机推荐 | 8C | 16G | 500G | 千兆 |
| 集群单节点 | 16C | 32G | 1T | 万兆 |

### 1.2 软件要求
| 类型 | 支持范围 |
| OS | CentOS 7.x / RHEL 8 / Ubuntu 20.04 / 国产 OS |
| 数据库 | MySQL 5.7+ / PostgreSQL 12+ / Oracle 19c+ |
| 中间件 | Nginx 1.18+ / Tomcat 9+ |
| JDK | OpenJDK 11 / 17 |
| 浏览器 | Chrome 100+ / Firefox 100+ / Edge 100+ |

### 1.3 网络要求
| 入向端口 | 用途 |
| 80 / 443 | Web 访问 |
| 8443 | API 通信 |

### 1.4 依赖软件清单
（具体包名和版本）

## 二、安装步骤
### 2.1 单机部署
**步骤 1**：上传安装包
\`\`\`bash
scp [产品名]-v1.0.tar.gz root@server:/opt/
\`\`\`

**步骤 2**：解压
\`\`\`bash
cd /opt && tar -xzf [产品名]-v1.0.tar.gz
\`\`\`

**步骤 3**：执行安装脚本
\`\`\`bash
cd /opt/[产品名] && ./install.sh
\`\`\`

**步骤 4**：验证安装
\`\`\`bash
systemctl status [产品名]
curl -k https://localhost:8443/health
\`\`\`

### 2.2 集群部署
（部署架构图 + 节点角色 + 安装顺序 + 节点互信配置）

### 2.3 容器化部署
（docker-compose.yml / Helm Chart 示例）

### 2.4 云部署
（云市场镜像 / Terraform 模板）

## 三、初始化配置
### 3.1 关键配置文件清单
| 配置文件 | 路径 | 说明 |
| application.yml | /opt/[产品名]/conf/ | 主配置 |
| db.properties | /opt/[产品名]/conf/ | 数据库连接 |

### 3.2 关键配置项
| 配置项 | 默认值 | 说明 | 必填 |
| server.port | 8443 | Web 端口 | 是 |
| db.url | jdbc:mysql://localhost/[db] | 数据库 URL | 是 |
| log.level | info | 日志级别 | 否 |

### 3.3 首次启动配置
（初始管理员账号 / 许可证导入 / 时区时间同步）

## 四、高可用部署（可选）
### 4.1 高可用架构图
### 4.2 负载均衡配置
### 4.3 数据库主备
### 4.4 故障切换验证

## 五、升级与回滚
### 5.1 升级路径
| 当前版本 | 可直接升级到 | 升级方式 |
| v1.0 | v1.1, v1.2 | 在线 |
| v1.2 | v2.0 | 停机 |
| v1.0 | v2.0 | 需中转 v1.2 |

### 5.2 升级前检查清单
- [ ] 备份数据库
- [ ] 备份配置文件
- [ ] 通知业务方
- [ ] 检查磁盘空间

### 5.3 升级步骤
\`\`\`bash
# 1. 备份
./backup.sh

# 2. 停服务
systemctl stop [产品名]

# 3. 替换程序
tar -xzf [产品名]-v2.0.tar.gz -C /opt/

# 4. 执行升级脚本
cd /opt/[产品名] && ./upgrade.sh

# 5. 启动验证
systemctl start [产品名]
\`\`\`

### 5.4 回滚步骤
\`\`\`bash
# 1. 停服务
# 2. 还原备份
# 3. 启动旧版本
# 4. 验证业务可用性
\`\`\`

## 六、运维监控
### 6.1 关键监控指标
| 指标 | 阈值 | 告警动作 |
| CPU 使用率 | >80% 持续 5min | 邮件 + 短信 |
| 内存使用率 | >85% | 邮件 |
| 磁盘使用率 | >90% | 邮件 + 短信 |
| 请求延迟 P99 | >500ms | 邮件 |

### 6.2 日志位置
| 日志类型 | 路径 | 保留期 |
| 应用日志 | /opt/[产品名]/logs/app.log | 30 天 |
| 审计日志 | /opt/[产品名]/logs/audit.log | 180 天 |

### 6.3 备份恢复策略
（备份周期 / 备份对象 / 恢复演练 SOP）

### 6.4 常见故障处理
（启动失败 / 性能下降 / 数据库连接异常 等）
```

## 命令呈现规范

| 类型 | 呈现方式 |
|------|---------|
| Shell 命令 | 代码块（含 \`bash\` 标记） |
| 配置文件 | 代码块（含 \`yaml\` / \`properties\` 标记） |
| 路径 | 等宽字体行内代码 |
| 占位符 | 用 `[产品名]` / `[版本号]` 等带方括号 |

---

## 质量要求

| 维度 | 标准 |
|------|------|
| 命令可复制 | 必须能直接运行，禁止伪代码 |
| 多模式覆盖 | 至少含单机 + 集群两种部署模式 |
| 升级回滚 | 必须配对出现 |
| 监控指标 | 至少列 5 个关键指标 |
